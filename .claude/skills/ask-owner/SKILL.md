# 提问闸（ask-owner）

**权威规则**：`CLAUDE.md` 的 **⚖ 缺口裁决协议**（owner 2026-08-06 立·全库生效）。
本 skill = 它的可执行摘要。**Lead 不得自裁后追认，更不得先写了代码再补申请。**

## 第一步·分类（大多数问题到这里就该结束）

| | A 类·你自己答 | B 类·才配问人 |
|---|---|---|
| 长什么样 | 「这样好玩吗」「手感够不够」「UI 够不够华丽」「这条环闭没闭」 | 「策划案这句话有两种读法」「现有能力真表达不了这件事」 |
| 判据在哪 | `docs/playbooks/game-flow-questions.md` T0–T8 · `docs/playbooks/self-check.md` 好玩三问 + 玩家视角八问 | 歧义无法靠读 GDD 消除 / 实查后确认重组不成立 |
| 怎么办 | **再迭代一轮**。答不出来 = 活没干完，不是问题 | 往下走第二步 |

> **A 类拿来问 owner = 把人当搜索引擎**，也是把「我干不完」伪装成「我在请示」。

## 第二步·三步走（B 类必须逐步做完，缺一步不许问）

### ① 先查——留下原文，禁凭印象
- 对 **capability-registry 实查**（`node scripts/dump-capability-catalog.mjs`，机读真相；
  别信手册里的手抄字段表）。
- 读**对应生产线手册**（`docs/playbooks/index.md` 找本），以及 `docs/playbooks/pick-list.md` 决策树。
- **查不到先 `git pull` 再查**——旧树查新知必然空手（2026-08-13 实证）。
- 写下来：**查了什么 · 为什么重组不成**。这段原文是问题的入场券。
- **重组成立的（第 ① 步就解决了）不上报**，自己做完。

### ② 摆两条路（不许开放式提问）
必须写成 **A / B 二选一**，每条附四样：**代价 · 影响面 · 通用性 · 选错要付什么**。

- **A · 补引擎缺口**（下沉成通用 capability：确定性 · 可审计 · 可复用 · 加引擎不在游戏层写 system）
- **B · 游戏独有逻辑**（申请游戏层代码例外 · 记债）

**你给推荐，但你不下裁决。** 写「我建议 A，因为…」，然后停。

### ③ 攒批 + 立单
- **攒批**：同一轮的问题攒成**一张表一次问**，别逐条打断。
  自证对齐单里的每一行 ⚠ 降格，天然就是这张表的一行。
- **立单**（两条通道，按轻重选）：
  ```bash
  # 快速通道（词表/能力小缺口·台账 .zerocraft/cap-gaps.jsonl → Lead 裁）
  node scripts/capgap.mjs add --slug <game> --role PE \
    --title "一句话" --need "为什么现有能力表达不了（附①的实查原文）" \
    --proposal "建议的下沉形态" --acceptance "验收判据"
  ```
  - 游戏级工单 → `docs/design/<slug>/requests.md`（不占引擎池硬槽）
  - 引擎级 → `docs/workflow/requests.md`（**最多 10 硬槽·满了先清后加**）
  - 3D 线 → `docs/workflow/requests-3d.md`

## 第三步·等
- 等裁决期间**做所有不依赖这个答案的事**——别整条线停在这儿空转。
- **绝不绕开基座自己发明**。等不到答案就先做别的，不是「先按我的想法实现，回头再说」。

## 反面清单（出现即这次提问不合格）
开放式问「你觉得呢」 · 没实查就说「现有能力做不到」 · 只摆一条路 · 自己裁完了来追认 ·
**先写了代码再补申请** · 逐条打断而不攒批 · A 类问题伪装成 B 类 · 等裁决期间整条线停摆。

> **一句话**：问之前先证明你查过；问的时候给两条路和你的推荐；然后**闭嘴等判**，别自己动手。
