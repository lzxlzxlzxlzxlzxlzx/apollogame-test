# S2战斗能力验证与统一技能方案（讨论稿）

2026-09-10。用户提出将攻击与主动技能统一为技能，并由单位算法选择使用时机。本文细化建议，未更改全库流程、实现代码或阶段签核。

## S2边界

可以在S2进行能力组合的功能验证。当前game-pipeline.mjs中S2是gap-check，主要检查计划与缺口裁决，并不自动证明技能、索敌、寻路已运行通过。

建议本游戏增加S2证据要求：规则契约→最小场景→实际引擎测试→结果与缺口→计划审查。原有S3装载验证、S4完整游戏闭环验证仍保留。测试现有能力组合与开展已裁决的公共能力工作，不等于提前写整套游戏。正式让全库S2机器门强制运行这些测试需要单独调整流程，本文未实施。

## 架构方向

普攻与主动技能共享定义、实例、执行、效果结算。技能定义包含目标规则、施放距离、效果形状、前摇/持续/后摇、冷却起点、资源消耗、锁定方式、打断规则、命中次数和效果列表。伤害只是效果之一，治疗、控制、召唤无需虚构伤害值。

每个单位每项技能的冷却与执行进度独立保存，不写回共享技能模板。瞬时、持续和被动触发可共用部分效果词汇，但被动不强制伪装成主动施法。

公共决策器先筛选可用的“技能+目标”组合，再按数据化优先级/评分选择。首版建议明确条件与优先级，必要时引入评分；不能为每只怪物写一套决策函数。正在执行时保持动作，除非明确打断，不每拍重选覆盖施法。

寻路独立：索敌选对象，技能决定可施放区域，移动系统寻找可达施放位置并避让；冲锋/俯冲通过技能阶段调用移动能力。空旷战场先验证动态拥堵、接敌与停位，有障碍时再验证全局路径；不因战略游戏采用复杂导航而照搬全部系统。

## S2场景与通过条件

| 场景 | 必须证明 |
|---|---|
| 同种单位独立技能 | A触发不影响B的目标、阶段、冷却 |
| 普攻与主动技能竞争 | 优先级清楚，不重复施放、不永久饿死普攻 |
| 不同技能目标 | 治疗友军与攻击敌人独立选目标 |
| 前摇目标死亡/离开 | 按契约取消、落空或继续，不错误换目标 |
| 俯冲反击 | 窗口内可被地面近战反击，窗口外拒绝；选中与命中合法性一致 |
| 打断与死亡 | 计时、动作锁、窗口状态正确清理；已发射弹道按契约继续或取消 |
| 拥堵接敌 | 多单位能到达可攻击位置，失败可解释，不持续穿叠/抖动 |
| 不可达目标 | 有重寻、换目标或等待策略，无无休止逐拍重算 |
| 多段/范围 | 目标命中次数和间隔正确，友伤规则明确 |
| 确定性与规模 | 同输入seed重复一致；按目标单位规模记录模拟耗时，阈值待目标设备确定 |

每项记录规则编号、场景配置、预期、实际结果、代码/数据版本、命令与退出码；动态行为附可视化证据。日志需能解释技能为何未释放，例如冷却、目标非法、距离、不可达或动作锁。
