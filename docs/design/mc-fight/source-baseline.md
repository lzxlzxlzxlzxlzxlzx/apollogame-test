# MC Fight 原版规则基线（立项分析稿）

日期：2026-09-09。来源：同级 `mcfight-unity-main` Unity 项目。状态：代码与配置静态分析；未启动 Unity 实测，不代表新版本已采纳所有原行为。

## 新版修订记录（2026-09-09，用户已明确）

本节为新版设计决定，优先于下文对应的原版行为；下文保留作为来源对照。未涉及的原版条款不因本次修订自动视为新版已确认。

- R-F01/R-F02/R-F03：新版仅支持PvAI，移除PvP和玩家操作另一阵营的流程。
- R-F04：新版唯一主循环为商店→部署→战斗→结算→重新购买；进入游戏直接到商店，不设主菜单。
- 原独立图鉴由商店内点击单位查看详情信息与介绍替代；详情属于商店内界面，不新增主流程阶段。详情展示字段后续细化。
- R-D03：新版允许拖拽放置。是否同时保留点击放置、是否允许移动已部署单位或拖回库存，本次尚未决定。
- 索敌、对空、护甲以及相关攻击规则进入讨论，尚未定稿；后续建议不视为用户已批准的规则。
- 后续已确认：地面近战可以通过飞行单位的俯冲窗口反击。窗口的起止阶段、时长、打断处理与适用技能尚待定义；不自动沿用原版0.55秒。

## 1. 游戏定位

MC Fight 是双阵营预算配军、自由坐标布阵、自动战斗的对战沙盒。玩家主要决定购买哪些怪物、购买多少和放在哪里，随后观看单位自动交战，并通过结算反馈调整下一局阵容。

从已读主流程看，没有传统自走棋的多轮经济、利息、商店刷新、合成升星或逐轮淘汰系统；没有关卡进度或养成介入主对局。不能因自动战斗就为迁移版加入这些规则。

产品价值判断（分析推断）：有限预算下的数量与质量取舍、兵种与技能克制、布阵和友伤风险，以及不同怪物组合碰撞产生的观战反馈，是核心体验。

## 2. 模式与流程

- R-F01：主菜单进入 PvP 或 PvAI，另有图鉴。
- R-F02：PvP 是现有代码里的本地红蓝两队配置方式，可切换操作阵营；未据此发现在线匹配/同步，不称为已实现网络对战。
- R-F03：PvAI 由玩家配置蓝方，程序为红方购买和布阵。UI 中仍存在通用阵营切换入口，是否应在 PvAI 禁用属于待确认项。
- R-F04：主流程为商店→部署→战斗→结算→重新购买或回主菜单。
- R-F05：重开进入商店时清空购买和部署记录，双方金币恢复1000；不是保留原阵容直接复赛。

依据：`GameFlow/GameManager.cs`、`UI/ShopUI.cs`、`UI/ResultUI.cs`（本文件以下 Scripts 路径均相对 Unity `Assets/Scripts/`）。

## 3. 怪物目录与数据来源

本次按 monsterId 合并84份 Resources/Monsters资产与84条 monster_config.json记录，全部一对一匹配。目录快照见同目录 `source-monsters.json`。

- 共84种单位定义，其中6种价格为0，正常商店明确隐藏，因此正常可购买的是78种。
- 价格0的定义为悚怖尸兽、悚怖食尸鬼、悚怖劫蛛、悚怖尸奴、跨座蝌蚪、恼鬼。它们不应作为免费购买单位展示。
- 全部84种定义中，移动类型为飞行的10种，攻击类型为远程的28种，填写特殊技能组件的48种。这些分类有交集，也不等于技能效果覆盖数。
- 数据分为身份/标签/类型/技能组件（SO）与生命、攻击、护甲、韧性、移动速度、射程、攻击间隔、半径、价格及技能参数（JSON覆盖/查询）。
- 实际技能可能使用独立参数或硬编码数值，面板 attack 不等于每种技能的实际伤害。

依据：`Data/MonsterDatabase.cs`、`Data/MonsterConfigLoader.cs`、`Core/MonsterDefSO.cs`、`UI/ShopUI.cs`。

## 4. 购买规则

| 编号 | 原版行为 |
|---|---|
| R-S01 | 蓝红双方独立预算，各1000金币 |
| R-S02 | 从价格大于0的完整目录选怪，可重复购买同种单位 |
| R-S03 | 单次购买与批量购买入口；批量常量为10 |
| R-S04 | 批量按只逐个扣款，资金不足时停止，因此可能只买到请求数量的一部分 |
| R-S05 | 已读购买逻辑未设人口上限、同种数量上限或随机商店库存 |
| R-S06 | 不必花光预算；PvP双方各至少买1只才可进入部署，PvAI仅要求蓝方买过单位 |
| R-S07 | 筛选含全部、地面、飞行、近战、远程，并有价格排序等目录操作 |
| R-S08 | 已读主购买流程没有出售退款步骤；未使用金币不会变成战斗优势或下一局积累 |

购买函数本身不拒绝零价定义，但正常商店和AI都过滤零价；这是接口防护与正常玩家规则的区别，不能据此写成“玩家可免费买召唤物”。

## 5. 部署规则

- R-D01：战场逻辑尺寸1280×720，中线x=640。
- R-D02：蓝方只能在x≤610处放置，红方只能在x≥670处放置，中心留60宽的禁部署带。
- R-D03：真实交互是先选怪物卡，再左键点击战场放1只；同种还有库存则继续选中，右键取消选择。并非拖拽放置。
- R-D04：放置消耗1个待部署购买条目，新增1个战场单位。
- R-D05：位置按 max(radius,20) 与战场外边界钳制；阵营区域校验发生在此之前。
- R-D06：放置函数未检查单位间重叠。没有读到已放单位回收、撤销或移动的主流程实现。
- R-D07：正常开战按钮在PvP双方部署完后可用；PvAI蓝方部署完后可用，红方剩余单位在开战时自动放置。
- R-D08：自动部署处理所有剩余购买条目，使用随机位置；商店和部署界面存在自动部署后直接开战的路径。

自动部署位置：蓝方x约210～610，红方x约670～1070，y约100～620，未做逐单位的重叠排除。自动部署按钮使用固定seed 42；PvAI开战补部署路径使用墙钟随机种子。

注意：`StartBattle()` 本身没有复用“全部部署完成”的检查，正常约束主要由UI按钮承担。迁移时应区分正常交互规则和接口可绕过行为。

依据：`GameFlow/GameManager.cs`、`UI/DeployUI.cs`、`UI/ShopUI.cs`。

## 6. 战斗推进与玩家控制

- R-B01：战斗单位自主索敌、追击、攻击和释放技能；已读对局UI仅提供观战和1×/2×/4×速度控制，未见战斗中手动控制单位或点技能的入口。
- R-B02：固定模拟步长1/60秒；倍速改变每帧可推进的模拟时间，不应解释为攻击属性增强。
- R-B03：普通启动的战斗模拟seed固定为42，但自动购兵/部分部署使用不同随机来源，所以“一局总流程”并非仅凭42可重现。
- R-B04：初始攻击和技能冷却为0；特殊能力自己的初始化可能覆盖其内部状态。
- R-B05：每拍按区域/投射物→逐单位状态、冷却、索敌及技能→单位分离与边界→胜负的顺序处理。
- R-B06：单位列表逐个执行、伤害可即时修改目标状态，因此同拍不是天然的双方同时出手。

依据：`View/BattleBridge.cs`、`Simulation/BattleSimulator.cs`、`UI/BattleUI.cs`。

## 7. 索敌、对空、移动

- R-T01：仅选择不同阵营且未死亡、可攻击的目标，通常按距离最小选取；等距离保留先遍历到的候选。
- R-T02：当前目标仍可攻击且在交战半径+30内时优先保持；2.5秒周期强制重选。目标失效时也会清除重新寻找。
- R-T03：带 anti_arthropod 的单位对飞行且带 arthropod 标签的目标按距离×0.75评分，体现优先攻击，而非直接增加伤害。
- R-T04：飞行攻击者可打空中单位；地面远程可对空；地面近战一般只能攻击地面目标，或有脆弱窗口的飞行目标；特殊技能可声明对空。
- R-T05：通用飞行近战成功攻击后给予自身0.55秒脆弱窗口。不能推导为所有飞行技能都会如此，特殊组件需逐项核查。
- R-M01：追击按目标方向直线位移，不是网格走位或寻路地图。
- R-M02：无目标、恐惧以及部分攻击冷却时会随机游走；游走速度为当前移动速度×0.72，方向每0.35～1.2秒更新，碰边反弹。
- R-M03：圆形半径重叠时推开；敌对推开倍率2.5，同阵营1；击退免疫单位不受该分离力。精确同坐标时d≤0.01的组合不进入推开分支。

依据：`Simulation/TargetingSystem.cs`、`MovementSystem.cs`、`Abilities/GenericAbilities.cs`、`Core/Constants.cs`。

## 8. 攻击和伤害

### 通用攻击

- R-A01：优先使用配置指定的特殊技能组件；没有时依次选择爆炸标签自爆、远程、范围近战、普通近战。
- R-A02：普通近战有效距离为 max(自身射程,双方半径和)+目标半径；冷却就绪时即时对目标结算伤害。
- R-A03：普通远程有效距离为自身射程+目标半径；向目标当前方向发射直线弹，默认速度280，最大飞行距离为传入射程×1.15。
- R-A04：普通弹只检查敌方，碰到路径上的敌人也可命中，通常命中后销毁；特殊追踪弹、穿透弹单独处理。
- R-A05：通用范围近战以目标位置为中心，普通半径64，giant标签半径92；特殊技能另有范围规则。
- R-A06：自爆附近出现敌人（距离≤爆炸半径×0.8）时点燃引信，倒计时结束爆炸并死亡。范围内伤害不分敌我；中心到边缘按配置线性插值。触发后不以敌人离开范围自动取消。

### 护甲与类别

类别为近战、远程、光束、爆炸、真实伤害。普通伤害的基础护甲公式：

```text
g = min(20, max(armor/5, armor - 4×damage/(toughness+8)))
afterArmor = damage × (1 - g/25)
```

伤害≤0为0；护甲≤0不减伤。真实伤害或攻击者带armor_piercing绕过基础护甲计算，但不意味着绕过前面所有特殊防御分支。

特殊分支包括潜地免伤、特定防御姿态仅承受10%近战且拒绝其他类别、部分远程减半/免疫、特定状态减半。已读实现中这些属于单位标签/技能状态，不能泛化为所有Boss共同规则。

依据：`Simulation/DamageSystem.cs`、`ProjectileSystem.cs`、`Abilities/GenericAbilities.cs`。

## 9. 状态效果

| 状态 | 默认持续时间 | 已读实际行为 |
|---|---:|---|
| 中毒 | 5秒 | 每累计1秒直接扣2生命 |
| 燃烧 | 10秒 | 每累计1秒直接扣1生命；可向周围52范围单位传播，未区分敌我 |
| 凋零 | 4秒 | 每累计1秒直接扣3生命 |
| 减速 | 5秒 | 移速×0.7，攻击间隔÷0.7 |
| 恐惧 | 2秒 | 主循环进入游走分支，跳过后续正常攻击决策 |
| 冰冻 | 2秒 | 移速归零、攻击间隔设为极大值；不是统一硬中断所有攻击/施法 |
| 眩晕 | 30秒 | 移速归零，临时改为地面类型，结束恢复；未见主循环统一禁止攻击的门 |

- 相同状态再次附加刷新剩余时间，不额外叠一层伤害，也不重置已存在效果的伤害计时器。
- 火焰免疫标签拒绝燃烧。
- DoT直接改生命，绕过普通护甲公式，但潜地状态有免伤分支。
- 代码先处理剩余时间到期，再处理该拍DoT，因此不能简单把“持续秒数×每秒伤害”当成精确总伤害。
- 燃烧传播实际发生于携带燃烧状态者受到该DoT函数扣血时，因此同时带毒/凋零时也可能触发传播。

此处尤其应把“名称预期”与“代码行为”分开：眩晕30秒并不能直接解释成30秒无法行动；冻结也不保证清除已就绪攻击或中断忙碌中的技能。

依据：`Simulation/StatusEffectSystem.cs`、`BattleSimulator.cs`。

## 10. AI和特殊技能的立项口径

### 阵容AI

红方从当前买得起且价格大于0的怪物中随机选1只购买，重复直到没有可买单位、金币用完或达到100次尝试。不按前排/后排搭配、不做预算优化，也未见难度档或针对玩家阵容的克制策略。布阵是对应半场随机坐标。

### 单位AI与技能

单位技能由通用行为加指定组件构成。已确认存在近战、远程、范围、自爆、状态施加、自疗、持续范围施法，以及复杂Boss组件；不能把“48份单位绑定特殊组件”误写成“48种技能都已逐条验完”。

示例：

- 女巫在受伤且敌人不在指定近距离时自疗；近距离随机选择伤害/附毒/附减速的范围攻击，技能使用独立冷却。
- 捕鸟蛛蜂攻击节肢目标可附加眩晕，涉及地空关系。
- 撼地斯拉配置有激光冷却20秒、持续5秒、15段、每段20伤害、半宽24、长度500，以及践踏参数；这些是有效配置，不代表每个目标必定吃满300伤害。

立项应把“每只怪物技能有规则定义与验收”纳入后续范围。完整技能逐个定序、触发条件和参数消费分析应形成专门的技能册；本稿完成核心公共规则及代表性技能分析，不冒充全部84种逐技能运行验证。

## 11. 胜负与结算

- R-W01：仅一队还有存活单位时，该队胜利。
- R-W02：双方都无存活单位时，CheckWinner返回-1，与“尚未结束”共用值；不会在该路径立即触发平局结算。
- R-W03：模拟时间超过120秒仍未结束，比较各队“存活单位当前生命总和÷这些存活单位最大生命总和”。死者不进分母。
- R-W04：比例高者胜，相同比例蓝方胜。结合R-W02，双方全灭会继续到超时，最终走蓝方胜的分支。
- R-W05：例如蓝方只剩1只10/10，红方剩100/200，原公式比较100%与50%，蓝方胜，即使红方绝对血量更多。
- R-W06：结果界面展示胜方、时长、单位统计，按伤害排序，筛选全部/蓝/红；当前筛选集合内伤害最高者标MVP。界面虽有“同归于尽”文案，但普通模拟结束判定不直接提供该结果。

统计不是额外胜负条件，也不产生金币奖励或局外养成。DoT等路径与统计事件未必全部贯通，不能在未对账前把统计表当作精确战斗事实。

依据：`Simulation/BattleSimulator.cs`、`BattleStatsCollector.cs`、`UI/ResultUI.cs`。

## 12. 必须与新版本设计分开的疑点

| 编号 | 静态发现 | 立项处理建议（未裁决） |
|---|---|---|
| Q01 | 同归于尽延迟到超时且蓝方获胜，UI另有同归于尽文案 | 明确新版本是否即时平局 |
| Q02 | 超时分母只含活人，同比分蓝胜 | 选择保留或改为全队初始生命/其他口径，不能静默修改 |
| Q03 | 冰冻和眩晕未统一阻断施法/就绪普攻；眩晕默认30秒 | 单独定义移动、普攻、技能、对空状态四项权限 |
| Q04 | 苦力怕自爆初始化读取centerDamage，但当前该怪配置只有explodeRadius和fuseDuration | GetAbilityParam缺参会报错并返回0；按当前路径静态推断自爆无有效伤害而仍自杀，需运行复现；不能直接取面板49当成已生效爆炸伤害 |
| Q05 | 部署允许重叠，精确同点的分离分支不推开 | 确认是否允许叠放，必要时对照实测定义 |
| Q06 | 购买/部署AI与战斗种子来源不同 | 区分复刻原行为与引入整局可回放种子 |
| Q07 | UI限制与底层StartBattle检查不一致；PvAI通用切队入口仍存在 | 玩家模式与接口约束统一定义，避免把绕过行为当正常规则 |
| Q08 | 状态直接扣血与DamageEvents统计路径不同 | 用真实事件对账后再定结算统计准确性要求 |

所有疑点只登记，不在本轮修复或代替用户裁决。没有启动游戏，因此“运行中必现”的结论需补原版运行证据。

## 13. 立项结论草案

建议项目一句话：**用有限金币组建怪物军团，在战场布阵，观看不同怪物技能自动交锋，并根据结果不断调整阵容。**

优先保留的体验：预算选择、怪物差异、自由布阵、自动技能交战、友伤与控制带来的组合变化、可读的结算与快速再来一局。

当前没有证据支持自动追加的内容：联网匹配、多轮经济、升级合成、随机商店刷新、局外养成。它们若有需要，应作为新需求单独定义。

本稿可作为S1讨论与后续GDD的输入；不等于S1已签核，更不等于S2能力计划通过。
