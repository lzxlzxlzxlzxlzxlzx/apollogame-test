# `game-lockpick` 验收场景

## A. 规则与确定性

1. easy / normal / hard 分别创建 3 / 4 / 5 个槽位，值域均为 0..2。
2. 同难度、同 seed、同输入序列运行两次，目标、逐步 match tier、终局、trace 摘要完全一致。
3. 点名异 seed 样例至少产生一个不同目标。
4. 目标不得等于全 1 初始向量；开局不得自动成功。
5. 重复值目标合法，例如 `[0,0,2]`。
6. 每次合法移动立即更新 current 与 matchCount；无一拍延迟。
7. 非法槽位、非法值、非法 arg、终局后输入均拒绝并留下 opt-in `reject` trace。

## B. 无限尝试与唯一失败路径

1. 对 hard 连续执行至少 1,000 次合法但不完成的移动，会话仍为 `playing`。
2. 不存在 moves、attempts、timer、deadline 或自动失败分支。
3. 错误移动只更新反馈，不减少资源、不损坏滑钮、不失败。
4. 点击第一层“放弃”只打开确认框，不改变规则状态。
5. 取消确认回到原局，组合与反馈不变。
6. 确认放弃才进入 `failure`，并只完成 SDK 一次。
7. SDK 卸载 / dispose / requestExit 不产出 `failure`。

## C. 成功

1. 将最后一个错误槽位移到目标值，在同一规则提交中进入 `success`。
2. 成功后滑钮不可再改变，重复输入不得二次输出。
3. 成功表现完成后输出严格等于 `{ outcome: 'success' }`。
4. 成功前 UI、音效事件与 SDK 数据均不可泄露 target 或精确 matchCount 文本。

## D. SDK 合同

1. 三个合法枚举均通过；大小写变体、数字、空串、额外字段均拒绝。
2. 输入与输出 contract / version 不匹配时拒绝。
3. 输出数据只含 `outcome` 一个键。
4. 宿主 empty-data preview 不被伪装为正式会话。
5. `complete()` rejected / timeout 时不重复改变模拟终局；可记录错误但不可伪造另一结果。

## E. UI 与可访问性

1. 1440×900 与 810×506 下机关盘、全部滑钮、指示器和放弃按钮无溢出 / 重叠。
2. 3、4、5 滑钮布局均居中、等距、可操作。
3. 鼠标、触控与键盘均可完成一局；滑钮松手吸附到三档之一。
4. 反馈色阶同时有亮度 / 脉冲差异；静音仍可玩。
5. reduced-motion 下保留状态可读性，缩短或取消位移动画，不延迟规则提交。
6. 放弃按钮对比度达标，确认 Modal 焦点正确，不可误触背景。
7. 运行 `validateLayoutNode`、UI audit 与截图对齐单，❌ 为 0；⚠ 均有明确去向。

## F. 包与资产

1. `manifest.json` schema 3 通过最新 SDK 校验。
2. 调用说明文档存在且由构建自动更新。
3. dist 在断网、本地静态托管与 DokiWorld 子路径下均可启动。
4. 资产索引无孤儿条目，所有 `skinKey` 有消费槽，所有必需文件位于包内。
5. 构建产物不得包含绝对磁盘路径或依赖开发服务器。
