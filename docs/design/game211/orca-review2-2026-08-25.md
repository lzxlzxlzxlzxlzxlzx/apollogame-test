两队对穿那条压根不走这条分支（worst 0.70004 > 半径和 ⇒ 从没重叠过）。
这正是 P0-2 修复所在的那条分支：脱离速度大一倍/小一半都不会有人喊。

### N4 新写的两段组件注释**一段都没挂上**（他点名要我判的那条披露在内）

用 TS 编译器自己取 `FlowAgent` 每个成员的 JSDoc：

```
[DOC] separation   → **软分离**（owner 2026-08-24 定方向：「用分离力做…  ← 没有「只在同一张场内生效」那段
[DOC] orca         → **ORCA 硬避让**（owner 2026-08-24 拍板「可以上」…   ← 没有「两条降级」那段
```

原因是位置：
- 「⚠ **软分离只在同一张场内生效**…」那块写在 `separation?: {...};` **之后**、`orca` 的 JSDoc **之前**
  ⇒ 是 `orca` 前面的第二块 JSDoc，工具只认最后一块，**这块谁也不属于**。
- 「ORCA 的两条**降级**…」那块写在 `orca?: {...};` **之后**、接口 `}` **之前**，**后面没有成员** ⇒ 挂空。

所以他问的「这个降级说清楚了没有（组件注释 + trace）」——
**trace 那半边说清楚了**（T9/M3 各恰红，我也读到实际那行：`ORCA 降级：半径非法 1 · 完全同位 2 · 邻居不还礼 4`），
**组件注释那半边等于没写**：作者在 IDE 里悬停 `orca` 看不到任何降级说明。
修法是纯位置问题：把第一块并进 `separation` 自己的 JSDoc，把第二块并进 `orca` 的 JSDoc（或做成 `orca` 的成员注释）。

### N5 「只到我自己那半径」不是下界

他自陈的 1v1 数字我**复现到小数点后五位**：

```
[P16] 被审方用例原样（1v1·R=0.6·速度 0.15）对面=plain      → 最近 0.60333（自称 0.60333）
[P16] 同上                                  对面=separation → 最近 0.60333
[P16] 同上                                  对面=orca       → 最近 1.20000
```

但把**同一条件**里的 1v1 加密成 2v2/3v3（别的一个字不改），它就掉下去：

```
[P17] 1v1 · 对面=plain      → 0.60829     [P17] 1v1 · 对面=separation → 0.60018
[P17] 2v2 · 对面=plain      → 0.54918     [P17] 2v2 · 对面=separation → 0.50476
[P17] 3v3 · 对面=plain      → 0.54918     [P17] 3v3 · 对面=separation → 0.55887
```

再让 ORCA 单位又慢又小、纯流场单位又快又直（自己半径 0.60）：

```
[P18] ORCA 速度 0.15 · 纯流场速度 0.15 → 0.60841
[P18] ORCA 速度 0.15 · 纯流场速度 0.5  → 0.54223
[P18] ORCA 速度 0.05 · 纯流场速度 0.9  → 0.16476   ← 承诺的 0.60 的 27%
```

机理是结构性的：**对方的速度完全不受任何约束**，ORCA 只能对着它**上一拍**的速度让路一拍。
所以正确的口径不是"降到自己那半径"，是"**对不还礼的邻居没有下界，只是尽力**"。
现在这个数字写在组件注释里（虽然如 N4 所述没挂上），读起来像个保证。
