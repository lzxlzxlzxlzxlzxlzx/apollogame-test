# 《潜取》游戏设计文档 v0.1

## 1. 设计支柱

1. **贪念可见**：已经取得的物品一直展示在“战利品袋”中；每多拿一件，继续停留的代价更高。
2. **操作与概率分层**：QTE 命中取得一次合法判定机会；概率未中不等同于玩家失误。
3. **风险持续**：选物、看结果和等待下一次 QTE 时暴露都不暂停。
4. **随时收手**：除终局裁决拍外，玩家始终拥有明确的撤退动作。
5. **世界权威在宿主**：小游戏提供确定性过程与回执，DokiWorld 决定物品转移和叙事后果。

## 2. 一局的状态机

| 状态 | 进入条件 | 允许输入 | 离开条件 |
|---|---|---|---|
| `ready` | 合法输入装载完成 | 开始、退出 | 开始→`selecting`；退出→`aborted` |
| `selecting` | 开局或一次偷取成功 | 继续、撤退 | 继续→按调用方数组顺序锁定下一件并进入 `waiting_qte`；撤退→`withdrew`；无剩余物品→`cleared` |
| `waiting_qte` | 已锁定当前物品 | 撤退 | QTE 出现→`qte_active`；暴露满→`exposed` |
| `qte_active` | 确定性 QTE 窗口开始 | QTE 输入、撤退 | 命中→`loot_roll`；失误/超时→`waiting_qte`；暴露满→`exposed` |
| `loot_roll` | QTE 命中 | 无 | 成功→`loot_reveal`；未中→`waiting_qte` |
| `loot_reveal` | 取得一份物品 | 继续、撤退 | 继续→`selecting`；撤退→`withdrew`；无剩余→`cleared` |
| `withdrew` | 安全撤退 | 无 | 终局 |
| `exposed` | 暴露达到上限 | 无 | 终局 |
| `cleared` | 候选物品全部取完 | 无 | 终局 |
| `aborted` | 输入无效、宿主取消或初始化退出 | 无 | 终局；不得产生奖励 |

### 2.1 同拍裁决顺序

每个固定 tick 严格按以下顺序处理：

1. 推进被动暴露及累加余数；
2. 若达到上限，立即进入 `exposed`；
3. 否则消费该 tick 的玩家输入；
4. 结算 QTE 命中/失误；
5. 必要时推进种子 PRNG 并结算偷取；
6. 生成状态转移和表现信号。

因此玩家不能在暴露已经于本 tick 满值后通过撤退抢跑。

## 3. 物品规则

- 一局可配置 1–12 个候选条目；每条绑定稳定 `itemId`、最终 `dc`，唯一物品额外绑定 `instanceId`。
- `items[]` 数组顺序即权威偷窃顺序；游戏不得排序，玩家不得跳选。一次只锁定第一件尚未耗尽的条目。
- 堆叠品成功一次取得 `takeQuantity`，不超过剩余 `quantity`；唯一实例成功后立即耗尽。
- 同一条目成功后，该条目的概率成长清零；其他条目的成长互不共享。
- 不允许客户端凭空增加条目、数量或实例；宿主按开始时快照复算并在提交时再次检查库存。
- 库存已变化导致无法提交时，宿主返回冲突，不用其他物品静默替代。

## 4. QTE 与偷取概率

v1 使用“移动指针进入命中窗后按下”的单键时机 QTE。QTE 的目标位置、方向和间隔均由 seed 与闭集参数派生；鼠标、触屏和键盘映射到同一个具名动作。

DC 查表、基准常数和连偷概率矩阵以 [`balance-model.md`](./balance-model.md) 为唯一数值基准；不得把 D20 整件目标概率直接当作每次 QTE 命中后的单抽概率。

每件物品先由 `dc` 查表得到 `initialChanceBp`。第 `n` 次命中当前物品时：

```text
chanceBp = min(
  maxSuccessBp,
  initialChanceBp[dc] * (10000 + failedLootRolls[item] * growthFactorBp) / 10000
)
```

- 首次命中使用 DC 校准表的初始概率，不预加成长。校准目标不是“单次命中概率等于 d20”，而是标准参数、80% QTE 命中率下，该物品在暴露前的累计得手概率近似原 d20 成功率。
- QTE 命中但概率未中：`failedLootRolls[item] += 1`，不追加暴露惩罚。
- QTE 失误/超时：不掷偷取概率，追加游戏版本固定的 `qteMissPenaltyBp`。
- 偷取成功：取得物品，当前条目累计清零；暴露仍按调用方传入的单一速率继续增长，不另加调用方可调惩罚。
- 所有概率均使用整数基点（0–10000），所有时间均使用整数 tick。

## 5. 暴露

```text
passiveRateBpPerSecond = exposureRateBpPerSecond

每 tick：
remainder += passiveRateBpPerSecond
exposure += floor(remainder / tickRate)
remainder %= tickRate
```

附加项只有游戏内固定的 QTE 失误惩罚；调用方不能分别改写失误、得手或切换惩罚。DokiWorlds 把妙手空空、烟雾、环境和 NPC 状态统一折算成 `dc` 与 `exposureRateBpPerSecond`。

界面颜色按 `exposure / maximum` 连续由冷暗色过渡到红色；颜色变化只读状态，不参与规则。

## 6. 终局语义

| 状态 | 已取得物品 | 犯罪建议 | 关系/记忆建议 |
|---|---|---|---|
| `withdrew` | 保留 | 有战利品则记录隐藏 theft；无战利品且发生过 QTE 可记录隐藏 attempted_theft | 默认无公开关系损失 |
| `cleared` | 保留 | 记录隐藏 theft | 默认无公开关系损失 |
| `exposed` | **保留** | 有战利品为 reported theft，否则为 reported attempted_theft | 对已识别受害者/目击者应用关系下降与记忆 |
| `aborted` | 不提交 | 无 | 无 |

“成功但暴露”是正式结果，不回滚已取得物品。

## 7. 宿主参数来源

小游戏只接收最终数值，不解释 DokiWorld 领域。宿主可用以下因素计算输入：

| 世界因素 | 建议投影 |
|---|---|
| 玩家 DEX / 偷窃熟练度 / 职业优势 | 由宿主降低逐物品最终 `dc` |
| 工具、装备、妙手空空 | 由宿主降低逐物品最终 `dc`；不以能力名进入 App |
| NPC 警觉/感知 | 由宿主提高 `dc` 或 `exposureRateBpPerSecond` |
| 黑暗、烟雾、人群 | 由宿主降低 `dc` 或 `exposureRateBpPerSecond` |
| 物品大小、位置、固定方式 | 由宿主形成该物品最终 `dc` |
| 房间目击者 | 只用于宿主生成 `crime`/`memory` 效果，不由小游戏决定名单 |

## 8. UI 信息架构

建议使用 `apolloOnyx` 起手并在 S5 换成专属“冷暗→警戒红”皮肤；全屏保持透明，让 DokiWorld 场景可见。

- 顶部：目标名称与 `偷窃/扒窃` 语义标签。
- 主区域：当前物品、移动指针与命中窗；QTE 出现时不被文字层遮挡。
- 左侧/下方：候选物品列表，显示剩余数量、难度图标和已取得状态。
- 右侧：战利品袋，持续显示已取得清单。
- 外圈/背景：整面暴露渐变与环形 `ProgressBar`；达到高风险区时加强脉冲但不闪烁致盲。
- 固定 CTA：`立即撤退` 始终可见、可点，不能藏在菜单中。
- 反馈：命中、未偷到、取得、失误分别使用不同文字和声音；“命中但未偷到”不得显示成红色失败。

UI 全部使用 LayoutNode 闭集；候选物品用 `buildItemSlot`/Card 组合，暴露用 `ProgressBar.shape:'ring'`，反馈使用 `Float`/`Particles`/闭集 FX。交互只发具名 action 信号。

## 9. 调试面板

开发模式提供 `theftDebug=1` 面板，支持即时编辑：

- 候选物品数量、顺序与逐物品 `dc`；
- 调试 seed（正式合同禁止调用方指定）；
- 单一 `exposureRateBpPerSecond`；
- 游戏内部的概率成长、上限、QTE 失误惩罚（只供研发调平，不属于业务合同）；
- QTE 周期、命中窗、响应时限；
- 皮肤和无障碍模式。

修改同步到可复制 URL；生产包不显示调试面板，且业务调用仍以 SDK 输入为准。

## 10. 音画节奏

- 每轮 QTE 前有短促预告，不使用纯视觉唯一信号。
- 暴露越高，环境音层和边缘脉冲越密，但判定节拍保持参数化且可读。
- 偷取成功有物品飞入战利品袋的可见落点；失误产生向暴露环汇聚的红色反馈。
- `prefers-reduced-motion` 下关闭强烈晃动与大幅闪烁，保留颜色、文字和声音反馈。

## 11. 风险与防护

- **伪权威风险**：客户端日志确定性重演只能验证规则一致与幂等，不能阻止修改客户端伪造完美输入；高价值经济需要宿主事件流/服务器时钟或接受该信任级别。
- **库存竞态**：开始快照与最终提交之间物品可能变化；提交必须按 `instanceId/itemId` 再验证并原子转移。
- **参数不可玩**：过高被动增长可能在首个 QTE 前必曝；输入校验必须做可达性下限检查并提供设计期模拟。
- **信息拥挤**：多物品列表不能遮挡 QTE；S5 必做窄屏、长名称和 12 条目压力验收。
- **假随机**：表现抖动不得推进规则 PRNG；规则和表现随机流必须分离。
