# 《潜取》验收设计

> 本目录当前是 GD 验收规格，不是已可运行的 conformance 剧本。`games/game-theft` 骨架和 acceptance adapter 在 S3/S4 到位后，再把以下场景逐条落为 `.scenario.jsonc`；不得用实现反写预期。

## 核心场景

### AC-01：DC 标定、命中后成长并取得单件

- 固定输入：1 个带最终 DC 的物品，seed 使第一次合法命中未中、第二次合法命中成功。
- 操作：开始后自动锁定该物品 → 两次命中 QTE → 撤退。
- 断言：第一次后无物品、无失误惩罚、成长增加；第二次取得一份；撤退终局保留该物品。

### AC-02：多物品连续偷取

- 固定输入：2 个唯一物品，seed 使两者均在可知次数内成功。
- 操作：按调用方顺序取得 A → 继续 → 自动锁定 B → 取得 B。
- 断言：A 成功后会话未终止、暴露未清零；B 有独立累计；全部耗尽后 `cleared`。

### AC-03：QTE 失误导致暴露

- 固定输入：失误惩罚使一次超时后暴露达到上限。
- 操作：首件自动锁定后不输入直到超时。
- 断言：不进行偷取概率 roll，不取得物品，终局为 `exposed`，qteMisses=1。

### AC-04：成功后继续冒险并暴露

- 固定输入：首次命中得手，随后被动增长令会话暴露。
- 操作：取得物品后不撤退。
- 断言：终局 `exposed`，acquired 仍包含已得物；宿主映射为 reported theft，而非回滚。

### AC-05：安全撤退

- 操作：物品锁定后在暴露未满时点击撤退。
- 断言：终局 `withdrew`，之后的输入全部拒收；结果只结算一次。

### AC-06：同拍暴露优先于撤退

- 固定输入：某 tick 开始时被动增长恰好填满暴露。
- 操作：同 tick 提交 withdraw。
- 断言：结果为 `exposed`，证明固定裁决顺序没有抢跑窗口。

### AC-07：确定性重演

- 对同一输入、seed、日志运行两次，并从中途快照恢复运行一次。
- 断言：三份回执逐字段一致；下一随机序列位置一致；digest 一致。

### AC-08：非法/对抗输入与顺序保护

- 覆盖：重复 seq、tick 倒退、伪造 select/skip/reorder、QTE 窗口外伪造命中、终局后继续输入、重复 complete。
- 断言：全部 fail-closed；不产生奖励和部分世界写入。

### AC-09：库存提交冲突

- 开始后由外部状态移除目标实例，再提交合法客户端日志。
- 断言：宿主拒绝/冲突回执；不得静默换物或超额转移；attempt 幂等状态明确。

### AC-10：DC、暴露和顺序边界

- 覆盖：DC 低于 1、高于 30、暴露速度非正数、空物品数组、超过 12 件、重复 instanceId。
- 断言：非法输入在开局前拒绝；合法输入逐项保持原始顺序，DC21–30 的初始概率为 0。

## UI 与可玩性验收

- 真浏览器用鼠标、触屏等价事件和键盘各完成至少一轮 QTE。
- 12 条物品、最长合法中英名称、窄屏和 200% 字体下，QTE/撤退/暴露值均不被遮挡。
- 暴露颜色变化、文字和环形数值三重表达；色觉缺陷模式不只靠红/绿。
- `prefers-reduced-motion` 下规则时机完全不变。
- 取得物品有可见落点进入战利品袋；不能只让机读数字增加。
- 每个终局出口都真实点击；重复开局无上局状态残留。

## 数值验收

- 对每套预设跑固定 seed 扫描，并用精确状态推进交叉核验，记录平均单局时长、取得件数、撤退率和暴露率。
- 基准标定目标见 `../balance-model.md`：80% QTE、4%/秒暴露时，单件最终概率接近 D20；同为 DC10 时，两件全得约 14.79%、三件约 2.37%、四件约 0.25%。
- 任意合法参数必须满足：不会在首个最慢合法 QTE 前被动必曝、成功率永不越界、暴露单调不降。
