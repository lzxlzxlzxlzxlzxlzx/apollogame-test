## 0. 一句话与定位

> 为游戏构建「**活世界**」（Building a "Living World" for the Game）

素材开篇的问题意识：

> 想到游戏 NPC，脑子里冒出来的大概是：「任务提示、重复台词、点完就走」。
> 但娜洛不太一样——**她有回应、有边界、有态度**。

已落地事实（素材自述）：在《星布谷地》落地了多个 AI NPC——咖啡店主**娜洛**、街市引导员**谷多曼**、篝火区游戏主持人**瑞芙**、舞台主持人**阿莱**等。

AI NPC 共覆盖**五大核心场景**，不同场景全部跑通：

| 场景 |
|---|
| 多人社交共创 |
| 破冰互动 |
| 新手指引 |
| 游戏主持 |
| PVP 玩法 |

## 1. 三层架构（素材的组织骨架）

素材反复强调这是一套「从体验场景 → 能力模块 → 研发侧工具」的**三层架构**，称为「AI Native 游戏技术全景」。三层之间是一个闭环：体验**调用**能力，能力**驱动**体验，工具**工程化沉淀**能力，能力又**反哺**工具。

| 层 | 名称 | 内容 |
|---|---|---|
| **#1 体验**（Experience） | 玩家体验的感受 | AI 叙事体验 · AI 玩法体验 |
| **#2 能力**（Capability） | 背后依靠的技术 | 通用 Agent 框架 · 通用 AI 角色模型 · AI 生态后训练框架 |
| **#3 工具**（Tools） | 研发侧使用的工具 | 通用 NPC UGC/PGC 配置工具 · 世界观与编年史工具 · 叙事编辑器 · 自演化沙盒 |

### 1.1 体验图景（素材的场景分类）

> 玩家能感知到的一切，都发生在这里。

- **AI 叙事体验**（AI Narrative Experience）：剧情叙事 · 涌现叙事 · 情感叙事
- **AI 玩法体验**（AI Gameplay Experience）：休闲娱乐 · 关系养成 · 社交互动

## 2. AI 叙事体验

> **定位**：让世界有故事感，让玩家相信这个世界是「活的」。

### 2.1 #1 剧情叙事 —— UGC 小剧场 + AI 导演

标签：`剧情分支动态调整` · `动态记忆检索/筛选` · `叙事流可视化编辑`

**核心表现（原文）**：

> AI 导演是一个以**玩家体验为中心**的 Agent，**实时感知玩家动态**，在框架内调整叙事节奏和分支走向，让多位玩家共创始终保持沉浸感。

配图案例：「茉尔与玩家 / AI NPC 一起庆生」——3D 场景内一群角色围在舞台前，聊天流里玩家发言（「我要送给 tttt 一首生日歌！」「快唱鸟」「你唱」），NPC 与玩家混流互动，左侧是带时间戳的聊天记录（11:43:xx），右上角有金币计数（10000）。

### 2.2 #2 涌现叙事 —— 无固定剧本，NPC 自然交互的游戏世界

标签：`动态运行的游戏世界` · `NPC 行为实时演化` · `长记忆链式影响`

**核心表现（原文）**：

> NPC 因各自在世界中的经历产生不同的**动机**，动机之间相互影响，玩家只需在**闲聊中自然说话**，就能改变 NPC 后续的**行动意图**，为整个世界埋下**链式影响**。

**配图：NPC 的生活看板（后台/调试面板）**——这张图信息量最大，是理解其运行模型的关键，逐项记录：

- **左侧「小都会地图」**：六个分区，每区一段场景描述 + 一格格的物件图标网格（可交互对象清单）。分区为：
  - 图书公家大楼
  - 后山遗迹
  - 秘密研究团（该区高亮选中，下方列出「在场角色」头像：茉尔、大宝王）
  - 智慧书馆
  - 圣心教堂
  - 小都会音乐所
- 右上角状态条：`回合 +5` · `总时长 00:00`
- **右侧「NPC 管理」面板**：
  - 标签页：`列表` / `编辑`
  - **当前 NPC（7）**，每行一个角色 + 编辑/删除按钮，可见：茉尔黛、王小蒲、方远森、鲜果、大宝王 等（每行带一个数字 id）
  - 顶部「新增」按钮
  - **回合控制** → `运行中` 按钮
  - **运行阶段**：状态 `processing`、旁边一个时间字段（`--:--`）
  - 「显示详细阶段」折叠项
  - **会话与调试** 区：`导入日志` / `导出日志` / `导出世界快照` / `导出 LLM 日志` / `重置世界`（红色）
- **底部左「事件日志」**：长段自然语言叙述，形如「……和其他人讨论了明天的活动安排，把大王了一遍……」「……的对话让我意识到……」，即 NPC 视角的经历流水
- **底部右「调试日志」**：机读事件流，可辨识两条：
  ```
  [HH:MM:SS]  TURN_START
  [HH:MM:SS]  NEEDS_DECAY_START
  ```

> **归档者注（仅标注事实，不作裁决）**：`TURN_START` / `NEEDS_DECAY_START` 说明其世界推进是**回合制 + 需求衰减**驱动的，不是纯实时；「导出世界快照」「导出 LLM 日志」说明快照与 LLM 调用是**分开**落盘的两份产物。这两点对本仓后续架构对账非常关键。

## 3. AI 玩法体验

> **定位**：让 AI 真正成为**游戏机制的核心**。

### 3.1 #1 关系养成 · 称号系统

**核心表现（原文）**：

> 随着互动深入，NPC 会为玩家解锁**专属称号**，好感度越高，称号越专属、越稀有。
> 玩家顶着这个称号与他人交流，自然形成独一份的「**社交面具**」，带动自发传播的话题效应。

配图案例：「玩家佩戴专属称号」——咖啡馆 3D 内景（WildCoffee 招牌、吧台、书店），玩家角色站在吧台前，头顶显示「吧台座位 1」，对话气泡带称号前缀，形如 `(称号) tttt，你今天这身搭配也太高级了吧`；左侧聊天记录同样以 `(称号)` 前缀出现；右上有场景切换下拉（咖啡馆 → 咖啡 · 吧台）。

**素材附带的玩家反馈截图（原文引用）**：

> - 「我直接珍藏这个称号 😍」
> - 「称号系统，伟大的设计 🤔」
> - 「史诗级更新 x2」
> - 「被看见的感动 —— 感觉在今天的世界里，努力不一定就有回报，但是我们希望能被看见。配合 bgm，甚至热泪盈眶了 🥹」

### 3.2 #2 社交互动 · 小星书

**核心表现（原文）**：

> NPC 用与玩家真实互动形成的**记忆**发帖、回复，**跨场景跨载体**保持连续性。
> 玩家可展示游戏成就、NPC 交互历史，把小星书当作**活的社交名片**——这些互动也会**反过来影响 NPC 的记忆**，在游戏世界留下真实痕迹。

「小星书」= 游戏内的图文社区（小红书式）。素材给了三张帖子切片：

| 帖子标题 | 摘要 | 互动 |
|---|---|---|
| 【深夜树洞】如果明天不用上班，你最想去哪？🌏 | 一条带 A/B/C/D 选项的投票式贴，选项含「睡到自然醒」「哪些下班也要去公园发呆」「来整咖啡抓老板聊天（欢迎！随时奉陪～）」「《起床动力美式》一杯！」 | 10 条评论 |
| 等一盏没有亮起来的蓝色光 | 「晨报说喷泉夜晚会发蓝色的光。于是傍晚坐在广场长椅上等，从天还亮等到路灯亮起来。喷泉一直没有亮……」——一段散文式观察 | 2 条评论 |
| 买不起汽水的傍晚 | 「傍晚散步到自动售货机前，橘子汽水 3 块钱。翻了翻口袋——0 元。……风是免费的，路灯是免费的，坐着发呆也是免费的。」 | 0 条评论 |

## 5. #2 能力层

### 5.1 通用 Agent 框架

> **定位**：让 NPC 具备**主动行为**能力，支撑更自然、更智能的角色表现。

#### 5.1.1 自研类脑 NPC 决策架构

**核心能力（原文）**：

> NPC 不只是被动响应。Agent 架构让它能**感知环境、自主决策、发起行为**。
> 我们没有沿用工程化的 **Sense-Plan-Act 范式**，而是**从脑认知与行为科学中寻找蓝本**：外界信号经事件感知层输入，由 **PFC 决策中枢判断**，驱动**行为模式层切换**，最终由**行动执行层落地**。
> 越贴近人脑的组织方式，角色越能摆脱「脚本感」，向真正的「活人感」逼近。

配图为「NPC 决策架构 × 人脑认知模型」对照图，左列人脑认知模型、右列 NPC 智能架构，逐层对位（右列可辨识层名）：

| 人脑认知模型（左） | NPC 智能架构（右） |
|---|---|
| 感知系统 | **事件感知层** |
| 情绪与动机 | **PFC 决策中枢** |
| 记忆系统 | **行为模式层（BCN）** |
| 执行与行为输出 | **行动执行层** |

图底部一行小字（部分可辨）：「感知 → 决策 → 行为 → 反馈闭环 → 产生新经验」。

#### 5.1.2 自研超类人记忆系统

**核心能力（原文）**：

> NPC 的主动行为离不开忆。常见记忆系统只做到「**检索历史**」：浅、散、易漂移。
> 我们要做的是一套**超类人记忆系统**，基于人类记忆组织方式，让记忆更立体、长效。

**五重能力（原文逐条）**：

| 能力 | 原文说明 |
|---|---|
| **脑认知记忆** | 有编码、遗忘、联想与重构，而不只是存储 |
| **跨角色记忆** | 经历在 NPC 之间流转共享，成为剧情涌现的养料 |
| **超长期记忆** | 突破上下文窗口的限制，跨越漫长时间线，角色依然完整 |
| **超多人记忆** | 同时维系与众多玩家、众多角色的关系脉络，互不干扰 |
| **跨平台记忆** | 角色的人格与经历不被单一场景锁定，随场景切换场景而延续 |

> 五重能力指向同一目标：让 NPC 从「能对话的程序」，成为真正能在游戏世界中**自主生存**的角色。

配图为「记忆系统能力对比」表：**常规记忆系统**（检索历史 / 单场景绑定 / 上下文窗口受限 …）**VS 超类人记忆系统**（多轮记忆、可重构 / 多场景、多角色 / 长线人格连续 …），五枚图标分别对应上表五重能力；图底一行结论（部分可辨）：「**最终形态 —— 人类可信赖的伙伴**」。

### 5.2 通用 AI 角色模型

> **定位**：让角色从「能对话」进化到真正有「活人感」。

#### 5.2.1 自研角色扮演模型

**核心能力（原文）**：

> 角色扮演的上限，不在于「回答是否正确」，而在于**对话节奏是否足够自然流畅**。
> 我们更关注交互中的**动态质感**：对话的张弛留白、言外之意的临场反应、性格在长程交互中的自然生长，沉浸感不是靠单句对话堆出来的，而是靠**交互节奏的可信度撑起来**的。
> 自研角色扮演模型同时驱动多个 AI NPC，保证**低延迟、高拟真**。在《星布谷地》对外测试时，也收到了许多「有原则」「活人感」「温暖」的好评。

#### 5.2.2 自研奖励模型

**核心能力（原文）**：

> 奖励模型在训练中充当**质量的度量与锚点**，决定「能被优化到多好」。
> 在角色扮演场景，奖励模型已经能较好把握「**高情商**」这类细腻场景，通用能力也在同步提升。
> 评估器的质量决定自我改进循环的上限。自演化叙事的近期路径是**先把三层地基打牢：说得像人、想得连贯、评得准确**。

### 5.3 AI 生态后训练框架

> **定位**：让 NPC 具备主动行为能力，支撑更自然、更智能的角色表现。

**核心能力（原文）**：

> 后训练是角色智能从「能说」走向「始终好」的关键一跃。我们完整走通了 **SFT → RLHF → DPO → OPD** 全链路，其核心命题始终如一：**如何把模糊的人类偏好，稳定地转译成模型可优化的定量信号**。
> 在 Reward 层，我们搭建了基于 **rule 规则、scalar 信号和 rubric 生成式反馈**的 **Hybrid Reward** 体系，结合 **OPD** 等技术，在保障客观逻辑智商以上，也能兼顾情感与角色性格。
> 核心判断是：RM 与 RL 的真正难点都不在算法，而在**建模出「什么是好的 AI 角色表现」**。

配图两张：

1. **「LLM 模型训练的四个阶段」**：`Pre-training`（预训练）→ `SFT`（监督微调）→ `RLHF`（人类反馈强化学习）→ `DPO/OPD`（偏好优化），下方一条上扬曲线标注「模型能力随阶段提升」。
2. **「Reward Model (RM) 应用场景与技术」**，分两阶段：
   - **阶段一：在线打分（Best-of-N）** —— Agent 输出 N 个候选 → RM 打分 → 选出最优回复。
   - **阶段二：对齐微调训练 / 反馈训练** —— 分 `Scalar-based RM`（标量打分）与 `Rubric-based RM`（生成式评分细则）两路，汇入强化学习训练；左侧标注 `Candidates`（候选集）。

按缺口裁决协议第 ① 步「先查，留下查了什么」，本次对 registry 与源码做了实查，结论仅陈述事实：

| `DebugTrace` | `src/skills/debug-trace.ts` | 对应素材的「调试日志 / LLM 日志」 |

**`AishePort` 的既有纪律（原文摘录，下一步的核心依据）**：

> 「AishePort —— 爱诗(AIGP)视频生成端口（**基础设施，确定性 sim 之外**；表现层旁路，REQ-C-004）。……**绝不碰 world / snapshot / hash**（异步旁路，与资产、音频同纪律）→ 不影响确定性/lockstep/录放。」

**未查到的**（实查结论，非印象）：registry 与 `src/` 内**没有**任何 LLM 对话端口、Agent 决策回路、记忆检索/遗忘、需求衰减（needs decay）、回合制世界推进（turn scheduler）这几类能力。`grep -ilE "llm|openai|anthropic|prompt"` 的命中全部是无关词（`prompt` 命中的是 UI 文案与 AIGP 提示词）。

**因此下一步必须摆到 owner 面前的结构性矛盾**（这里只点名，不自裁）：

素材的运行模型是 **LLM 即运行时**（NPC 每回合真的去调模型决策）；本仓的最高纲领是**数据驱动 + 确定性解释器**，尺子是「最弱 LLM 能否产出同样的数据」——那把尺子丈量的是**产出数据的作者**，而素材要的是**产出行为的运行时**。这不是一个能靠重组现有 capability 抹平的差量，也不是一句「加个端口」能了结的。`AishePort` 的先例证明「调外部 AI」本身不违规，**但它的合规性恰恰建立在「绝不碰 world/snapshot/hash」之上**，而 NPC 决策**必须**写世界。

这道题的 A/B 两条路、各自的代价与影响面，落在 `capability-plan.md` 里交 owner 判。本文到此为止。
