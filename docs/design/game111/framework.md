## 0. 一句话

> **game111 = 一个回合推进的小镇活世界：NPC 由 LLM 驱动自主生活，玩家只靠闲聊就能改变他们的动机，改变沿着关系网链式扩散。**

参照物：素材的《星布谷地 / 小都会》；机制骨架近似 *Dwarf Fortress 的传闻传播* × *Stardew Valley 的关系养成*，但决策层换成 LLM。

## 1. 核心矛盾与解法（本文最重要的一章）

### 1.1 矛盾

| | 素材要的 | 本仓的第一准则 |
|---|---|---|
| 运行模型 | **LLM 即运行时**——NPC 每回合真去调模型决策 | **数据 + 确定性解释器**；`hashSnapshot` 逐字节对拍，lockstep 一旦分叉立即报 desync |
| 尺子 | 角色「活人感」= 模型输出的不可预测性 | 「最弱 LLM 能否产出同样的数据？」 |

素材的 `NPC 决策` **必须写世界**（移动、发帖、改关系）。而本仓唯一的外部 AI 先例 `AishePort`（`src/services/aigp/aishe-port.ts`）合规性恰恰建立在相反的前提上，原文：

> 「**绝不碰 world / snapshot / hash**（异步旁路，与资产、音频同纪律）→ 不影响确定性/lockstep/录放。」

所以 **AishePort 不能照抄**。这不是加个端口能了结的事。

### 1.2 解法：LLM 不是解释器，LLM 是**输入源**

实查 `src/net/commands.ts` 文件头，原文写着：

> 「Command 是一个玩家在**某一个 tick** 的意图。……把『实时键盘』和『网络对端』都抽象成**同一个 InputSource**：现在喂本地键盘，以后换成网络源，**引擎一行都不用动**。」

这句话就是答案。**人类玩家本身就是一个非确定性源**——引擎从不试图让键盘变确定，它只要求：*给定同一份命令流，世界的演化必须逐字节一致*。

> **一个 LLM 驱动的 NPC，在架构上与一个远端人类玩家完全同构。**

于是三层分离：

```
┌─ 表现层 ──────────────────────────────────────────┐
│  3D 场景 · LayoutNode UI · 聊天流 · 小星书界面      │  不进 hash
└───────────────────────────────────────────────────┘
            ↑ 读快照                    ↓ 玩家点击
┌─ 世界层（确定性 sim）─────────────────────────────┐
│  全部现有 capability · 纯数据 · 进 hash · 可 lockstep │
│  可录放：重放命令流即可，**不需要再调模型**           │
└───────────────────────────────────────────────────┘
            ↑ tick 边界注入 Command        ↓ 导出快照切片
┌─ 意图层（Intent Bridge · sim 之外）───────────────┐
│  记忆检索 → 组装 prompt → 调 LLM → 解析成闭集意图   │  异步·不进 hash
└───────────────────────────────────────────────────┘
```

**由此得到的四条硬性质**（这是整套框架的验收判据）：

| # | 性质 | 怎么成立的 |
|---|---|---|
| ① | **录放 bit 一致** | 录的是**意图流**（Command log），不是模型。重放时不调模型，喂同一份 log → 同一 hash |
| ② | **lockstep 不误报** | 意图与玩家命令走同一条 `applyCommands` 路径，按 `playerId` 排序应用，与到达次序无关（`commands.ts` 铁律原文） |
| ③ | **模型换了不影响存档** | 世界里存的是意图产生的**结果**，不是模型的话 |
| ④ | **断网可玩** | 意图层不可用时 NPC 降级到 L1–L2 确定性规则（见 §3），世界照转 |

### 1.3 「最弱 LLM」那把尺子还成立吗？

成立，但要**分面**用——这是本文对宪法的精确化，请 owner 一并裁：

| 面 | 尺子 | 理由 |
|---|---|---|
| **世界表**（地图、分区、物件、NPC 人设卡、需求曲线、称号表、意图闭集词表） | ✅ **尺子全效**——必须最弱 LLM 可一致产出的纯数据 | 这是「作者产出的数据」，正是宪法丈量的对象 |
| **行为流**（某个 NPC 这一回合决定去后山拍照） | ❌ 尺子不适用 | 这是**运行时**产物，同一把尺子丈量它等于要求「玩家的操作必须可预测」——荒谬 |

> **判据**：宪法丈量的是**产出数据的作者**，不是**产出行为的运行时**。玩家的键盘从来不受那把尺子约束，LLM NPC 同理。

## 2. 意图闭集（Intent Closed Set）—— 框架的地基

### 2.1 为什么是闭集

素材自己暴露了答案。`concept-source.md` §3.2 那段 Agent 日志里，NPC 茉尔的全部行动只用了 5 个工具：

```
event_done · world_move · world_photo · starbook_mypage · starbook_post
```

行类型也是闭集：`思考` / `调用` / `结果` / `观察`。

**这与本仓的 UI 铁律完全同构**——「控件 = 闭集 · 写世界 = action 信号入队 · handler 不塞自由逻辑」。我们把同一条纪律推广到 NPC：

> **LLM 只能吐闭集里的动词 + 参数。闭集外的一切，引擎拒收。**

### 2.2 契约

意图层的输出必须是、且只能是这个形状：

```
Intent := { npcId, verb: <闭集枚举>, args: <该 verb 的定长标量参数>, tick }
```

三条红线：

1. **拒收即记录**——解析失败 / 动词不在闭集 / 参数越界 / 目标不存在 → 丢弃，并 `appendTrace` 记一条 `reject`。
   > 依据：日志基准守则原文「凡『什么都没发生』的分支**必须**记——本仓所有难查 bug 的共同形状」。LLM 输出是本仓有史以来最大的一个「什么都没发生」的来源。
2. **无自由文本入世界状态**——NPC 说的话是 `Text` / 事件日志内容，进 hash 无妨（它是确定的字符串）；但**绝不允许模型输出的 JSON 直接反序列化成组件**。
3. **闭集是数据表**——动词表是 manifest 里的一份纯数据（最弱 LLM 可产），不是散落在代码里的 switch。

### 2.3 意图动词表（v0 草案 · 待 owner 增删）

对位素材，分五类：

| 类 | 动词 | 写入世界的什么 | 由哪个现有 capability 落地 |
|---|---|---|---|
| **移动** | `move_to(zoneId)` | 位置 / 在场分区 | `a1-transform` · `t2-zone-occupancy` |
| **交互** | `use_object(objectId)` · `take_photo()` | 物件状态 · 产出物实体 | `k1-spawn` · `f2-flag` · `j1-state` |
| **社交** | `talk_to(npcId, topicId)` · `give(npcId, itemId)` | 关系值 · 记忆条目 | `g2-relation` · `f1-resource` |
| **社区** | `feed_post(draftId)` · `feed_reply(postId, draftId)` | 帖子实体 · 互动计数 | `k1-spawn` · `x3-string-variable` |
| **自理** | `rest()` · `event_done(eventId)` | 需求资源回补 · 事件闭环 | `f1-resource` · `t1-event-log` |

> 注：`take_photo` 产出的**图片**走 `AishePort` 式旁路（不进 hash），世界里只存一个句柄 id——这条正是 AishePort 先例可以照抄的部分。

## 3. NPC 智能分级（L1–L5）——素材的分级，本仓的落法

素材的 L1–L5（脚本化 / 感知响应 / 动机决策 / 认知规划 / 自主智能体）不是营销话术，它是**成本与确定性的分档**。本仓照搬这个轴，但给每级钉死「谁来决策」：

| 级 | 素材定义 | **本仓落法（决策者）** | 是否调 LLM | 断网可用 |
|---|---|---|---|---|
| **L1** | 脚本化 | `tier3/timeline`（定点 cue）+ `tier3/dialogue`（固定对话图） | ❌ | ✅ |
| **L2** | 感知响应 | `tier2/self-rule` + `tier2/condition`（读自身状态→施自身动作） | ❌ | ✅ |
| **L3** | 动机决策 | `tier2/behavior-tree` 选行为模式 + **LLM 只产出台词** | 🔶 仅表达 | ✅ 降级 |
| **L4** | 认知规划 | **LLM 产出意图**（§2 闭集）+ 记忆检索参与 prompt | ✅ | 🔶 降级到 L2 |
| **L5** | 自主智能体 | L4 + 跨角色记忆流转 + 自主发起社交 | ✅ | 🔶 降级到 L2 |

**框架红线**：

- **每个 NPC 的等级是人设卡上的一个数据字段**，不是代码分支。L1–L2 一行 LLM 不调。
- **L4/L5 必须有 L2 降级路径**。「模型挂了世界就停」= 设计缺陷。断网时 L5 退成 L2，NPC 依然会饿、会睡、会走路，只是不再有新意图。
- **一个小镇不该全是 L5**。成本与噪音都不允许。v0 配比建议：L5 × 2（主角级）、L4 × 5、L2 × 10、L1 × 若干背景。

> 素材侧证据：其「NPC 管理」面板当前 NPC 恰为 **7 个**（`concept-source.md` §2.2），与上面的「L5+L4 = 7」同量级——这不是巧合，是算力约束的自然结果。

## 4. 世界运行模型

### 4.1 回合制，不是实时

素材调试日志实锤：`TURN_START` → `NEEDS_DECAY_START`（`concept-source.md` §2.2）。

**这对我们是极大的好消息**，理由有三：

1. **给了异步 LLM 一个天然的等待边界**。实时帧里等模型回包无解；回合制下「收齐本回合全部意图再推进」与 lockstep「收齐本 tick 全部命令再步进」**是同一个 barrier**（`src/net/lockstep.ts` 已实现该形状）。
2. **成本可控**。7 个 L4+ NPC × 每回合一次调用，而不是每帧。
3. **可读**。玩家看到的是「小镇的一天天」，不是一锅乱炖。

### 4.2 回合相位

用 `tier3/flow`（`src/skills/tier3/flow.ts`，声明式 `GameFlow` 状态机，**闭语法·不收自由代码**）摆成一份数据：

| 相位 | 做什么 | 承载 capability |
|---|---|---|
| `TURN_START` | 回合号 +1，广播信号 | `flow` |
| `NEEDS_DECAY` | 精力/心情/社交欲 逐项衰减 | `tier2/over-time` + `f1-resource` |
| `PERCEIVE` | 为每个醒着的 NPC 生成「可感知事件集」（同分区在场者、新帖、未完成事件） | `w2-spatial-query` + `t2-zone-occupancy` |
| `INTENT`（异步 barrier） | 导出快照切片 → 意图层 → 收齐意图 | **§6 缺口 ②③** |
| `COMMIT` | 按 npcId 排序应用全部意图 | `net/commands.ts` `applyCommands` |
| `SETTLE` | 关系值结算、称号解锁判定、事件日志落账 | `g2-relation` · `tier2/condition` · `t1-event-log` |
| `TURN_END` | 快照 hash、trace 落盘 | `net/world-hash.ts` · `DebugTrace` |

> ⚠ **定序警告**（CLAUDE.md「施工与复查」第 1 条实证）：`REQ-108-ENG-02` 的教训是「一放 Update 就闭合成环」，而 `topological-sort` **成环时只告警不抛**、落序不合语义仍照跑 → 接缝静默失效。本框架的 `INTENT → COMMIT → SETTLE` 是新增相位链，**属 🔴 只归主程**的定序/相位面。落地时必须读 stderr 告警，绿灯不等于没话说。

### 4.3 需求（Needs）

素材的 `NEEDS_DECAY` 直接对应 `tier2/over-time`（实查文件头原文）：

> 「一实体的 OverTime 持一个 TimedEffect 列表 → 燃烧+冰冻+毒可同时存在，各自计时/到期……resource 且 amountPerTick 且到 period 整数倍 → queueResourceMod 到自身」
> 「确定性：纯整数 tick 计数 + 加性累加（序无关）；effects 是 POD 数组 → 进 snapshot 可重放。」

**结论：需求衰减是纯重组，零新代码。** 需求表（精力/心情/社交欲/好奇心，各自 period 与 amountPerTick）= 一份纯数据。

素材日志里 NPC 的自述「精力还行但也不算特别充沛」「你感觉有点无聊」——就是这几个 resource 的阈值文案，由 `tier2/condition` 查表得出，喂进 prompt。

## 5. 五大玩法子系统 → 现有能力对账

### 5.1 关系养成 · 称号系统

素材原文：好感度越高，称号越专属越稀有；称号成为玩家的「社交面具」。

| 要素 | 落法 | 实查依据 |
|---|---|---|
| 好感度 | `f1-resource`（每对 NPC-玩家一条） | `src/skills/atoms/resource` |
| 关系脉络 | `g2-relation`（`kind` + `targetId`） | `src/skills/atoms/relation/index.ts` |
| 好感度受修正（礼物/事件加成） | `tier2/modifier-stack`（字段表 + 混合合并策略 + 条件门控） | `src/skills/tier2/modifier-stack.ts` |
| 称号解锁条件 | `tier2/condition`（ConditionExpr 受控表达式树）+ `f2-flag` | `src/skills/tier2/condition.ts` |
| 称号文本 | `x3-string-variable` | `src/skills/atoms/string-variable` |
| 称号表 | **纯数据 manifest**（条件 → 称号 id → 文案 → 稀有度） | — |

> **结论：重组成立，不上报缺口。** 但 owner 请注意一个设计判断：**称号是「NPC 给的」，不是「系统发的」**——这是素材那些玩家反馈（「被看见的感动」）的全部情感来源。落法上体现为：称号解锁条件必须挂在**某个具体 NPC** 的关系实体上，且解锁时由该 NPC 亲口说出。这条写进数据表，不写进代码。

### 5.2 社交互动 · 小星书

| 要素 | 落法 |
|---|---|
| 帖子 | 一个实体：`x3-string-variable`(标题/正文) + `g2-relation`(作者) + `f1-resource`(点赞/评论数) |
| 发帖 | 意图动词 `feed_post`（§2.3） |
| 图片 | `AishePort` 式旁路句柄，不进 hash |
| Feed 排序 | 纯数据排序规则（按 tick 降序），确定性 |
| 「反过来影响 NPC 记忆」 | 帖子互动 → 写入记忆条目（**§6 缺口 ①**） |
| 界面 | `ui/components` LayoutNode（**禁手写 React/DOM**） |

> **结论：除记忆一项外，重组成立。**

### 5.3 涌现叙事 · 链式影响

素材原文：「NPC 因各自经历产生不同动机，动机之间相互影响……为整个世界埋下链式影响」。

**链式影响的本质 = 记忆在 NPC 之间流转**（素材的「跨角色记忆」）。这是 §6 缺口 ①，**整套框架的成败点**。

没有它，game111 就只是「一群各自独立的聊天机器人」——这正是素材明确点名要超越的形态（原文：常见记忆系统只做到「检索历史」：浅、散、易漂移）。

### 5.4 AI 导演

素材原文：「AI 导演是一个以玩家体验为中心的 Agent，实时感知玩家动态，在框架内调整叙事节奏和分支走向」。

**落法：导演 = 一个世界级的 InputSource，与 NPC 同构，只是它的意图闭集不同**——它不移动、不发帖，它只发「节奏干预」意图：

| 导演动词 | 效果 | 现有 capability |
|---|---|---|
| `nudge(npcId, topicId)` | 给某 NPC 注入一个动机倾向 | 写 `f2-flag` / `j1-state` |
| `schedule_event(eventId, atTurn)` | 在第 N 回合触发事件 | `tier3/timeline`（cue 四种闭集动作） |
| `adjust_pacing(level)` | 调节需求衰减速率 | `tier2/over-time` 参数 |

> **结论：重组成立**——`spawn-director.ts`（`src/skills/tier2/spawn-director.ts`）已经是「按波表调度出本 tick 该发几个」的**确定性纯函数核**先例，导演是它的同构推广。**不要为导演新建引擎能力**；它就是一个意图源 + timeline。

### 5.5 玩家 ↔ NPC 对话

| 要素 | 落法 |
|---|---|
| 对话呈现 / 分支游标 | `tier3/dialogue`（读数据图、推进游标） |
| 玩家自由输入 | `net/queued-input.ts` `enqueueAction`（UI 侧 enqueue，tick 边界确定性释放） |
| NPC 回话 | 意图层产出 → 写 `l6-text` |
| 「闲聊改变动机」 | 玩家发言进入该 NPC 的记忆 → 下回合 prompt 变化（**缺口 ①**） |

### 缺口 ① 记忆系统（Memory）

**实查结论**：registry 与 `src/` 内**不存在**任何记忆能力——无编码/遗忘/联想/检索，无跨实体记忆流转。`t1-event-log`（`src/skills/tier1/event-log.ts`）只是**平铺事件流水**，没有衰减、没有检索、没有归属。

**为什么重组不成**：素材要的五重能力里，**跨角色记忆**（经历在 NPC 之间流转）和**遗忘/重构**是新语义。用 `f1-resource` + `x3-string-variable` 硬凑，等于在游戏层写一个检索解释器——正是宪法明令禁止的「数据表 + 游戏层自写解释器」的虚胖数据（game-g 天罡/地煞的教训）。

| | **A · 下沉为引擎 capability `memory`** | **B · 游戏层独有（game111 专属）** |
|---|---|---|
| 做什么 | 新 capability：记忆条目 = 实体（主体/客体/时刻/强度/标签）；每回合强度衰减（可复用 `over-time` 形状）；确定性检索（按 标签+强度+时近 打分排序，取 top-K）；`share` 动作把一条记忆复制给另一 NPC 并打折强度 | 同样的东西写在 `games/game111/` 里 |
| 代价 | 高。属 🔴 主程面（进 hash、影响快照大小与存档） | 中。但**game111 的核心卖点从此不可复用** |
| 影响面 | 全库。所有有 NPC 的游戏（101 海港绯闻、108、未来的 A/B/C）立刻可用 | 仅 game111 |
| 通用性 | **极高**。「谁在何时对谁做了什么，且这件事会淡忘、会被传开」是 RPG/模拟/社交游戏的通用原语，不是 111 独有 | 无 |
| 选错要付什么 | 选 A 而实际只有 111 用 → 引擎多一块无人消费的面（YAGNI） | 选 B 之后 101/108 也要记忆 → 三份实现各写一套，正是 `modifier-stack` 当年下沉前的原样（库里出现三次却各写一套） |

**Lead 推荐：A**，理由是通用性证据已经在库里——`docs/design/game101/`（海港绯闻）是一个以「绯闻传播」为名的游戏，它与「记忆流转」是同一个原语。但**这是推荐，不是裁决**。

### 缺口 ② LLM 决策端口（NpcAgentPort）

**实查结论**：`src/services/aigp/` 的 `AishePort` 是唯一外部 AI 先例，但其契约明写「**绝不碰 world / snapshot / hash**」，而 NPC 决策**必须**写世界。**不能照抄。**

| | **A · 下沉为引擎端口 `NpcAgentPort`** | **B · game111 自己接 LLM** |
|---|---|---|
| 做什么 | 照 `EnginePort` 风格定契约：`decide(context: AgentContext): Promise<Intent[]>`；提供 `NullNpcAgentPort`（确定性桩，测试与断网用）+ `HttpNpcAgentPort`（真后端）。**端口不写世界**，只产 `Intent[]`，由 §1.2 的注入路径落地 | 同样的东西写在 `games/game111/` |
| 代价 | 中。契约面窄（一个方法），先例齐全（AishePort / 渲染 / 音频 同哲学） | 低 |
| 影响面 | 引擎多一个 service 端口。**不进 hash，不碰 sim** → 确定性风险接近零 | 仅 111；且 111 从此有一块「游戏层直连外部服务」的面 |
| 通用性 | 高。任何要 AI NPC 的游戏都需要；`NullNpcAgentPort` 还是**全库测试基建**（无网 CI 跑 AI 游戏） | 无 |
| 选错要付什么 | 几乎无——端口是最轻的下沉形态 | game111 的测试将无法在无网 CI 里跑，或各游戏各写一套桩 |

**Lead 推荐：A**。这项代价极低且先例明确（AishePort 已经证明「外部 AI 服务端口」在本仓是合法形态），分歧点只在「要不要现在做」。

### 缺口 ③ 异步意图的 tick 对齐（Intent Barrier）

**实查结论**：`tier3/flow` 管相位跳转，但**不会等异步回包**；`net/lockstep.ts` 有「收齐再步进」的 barrier 形状，但它等的是**同步到达的对端命令**，不是 Promise。二者之间缺一格。

**为什么这格危险**：这是整套框架里**唯一会污染确定性的地方**。回包次序是网络抖动决定的，若直接按到达序应用 → 每次跑出的世界都不同 → 存档/录放/lockstep 全废。`commands.ts` 的铁律（「应用前一律按 playerId 排序——顺序只由内容决定，与网络到达次序无关」）就是为这件事写的，但它没有覆盖「**回包迟到/失败**」。

| | **A · 下沉为引擎能力 `intent-barrier`** | **B · game111 在 flow 里自己等** |
|---|---|---|
| 做什么 | 通用「异步意图收齐门」：本回合登记 N 个待决 NPC；超时/失败按**确定性降级策略**补默认意图（如 `rest()`）；收齐后**按 npcId 排序**一次性注入。超时判据用**回合数**不用墙钟（墙钟 = 录放对不上，`debug-trace` 红线②同源） | 写在 game111 |
| 代价 | 高。🔴 **主程面**：碰定序/相位、确定性、存档 | 高，且**风险更高**——这类坑「不在 spec 也不在 review 清单里，是动手才撞出来的」（CLAUDE.md 实证原文） |
| 影响面 | 全库；且它是缺口 ② 的必要配套（有端口没 barrier = 不确定性直接漏进 sim） | 仅 111，但踩坑代价全 111 自己吃 |
| 通用性 | 中高。任何「异步外部决策 → 确定性 sim」都需要（联机、云存档校验、外部 AI） | 无 |
| 选错要付什么 | 选 A 而只有 111 用 → 引擎多一块面 | **选 B 的下行风险最大**：一个静默的非确定性源潜伏在游戏层，症状是「偶发 desync / 存档读出来不一样」，属本仓最难查的 bug 形状 |

**Lead 推荐：A**，且**与 ② 捆绑**——只批 ② 不批 ③ 是最坏组合（有了调模型的能力，却没有把结果确定性落地的能力）。

---

### 缺口 ④ 动机/意图是否成为世界状态（PFC 层）

**实查结论**：`tier2/behavior-tree` 提供确定性行为选择，`j1-state` 提供状态机，但**没有「动机」这层语义**——即「NPC 当前想做什么、这个想法持续多久、被什么影响」。

**这一项与 ①②③ 不同：它可能根本不该做。** 我把它摆出来是因为素材把它画成了架构核心（PFC 决策中枢 + 行为模式层 BCN），但素材是**模型侧**的架构，不必然是**游戏侧**的数据结构。

| | **A · 显式动机层** | **B · 不做，动机只活在 prompt 里** |
|---|---|---|
| 做什么 | 世界里存 `Motive` 组件（倾向标签 + 强度 + 来源 + 时效），进 hash，可被导演 `nudge`、可被其他 NPC 观察、可在 UI 上显示 | 动机由意图层每回合从「需求 + 记忆」现推，不落世界 |
| 代价 | 中。多一组件、多一份衰减、多一份快照体积 | 零 |
| 影响面 | 全库（若下沉）或仅 111 | 无 |
| 通用性 | 待定——**目前只有 111 一个消费者，YAGNI 风险明显** | — |
| 选错要付什么 | 过度设计：造了一层只为「看起来像素材架构图」的状态 | 「链式影响」变得**不可观测**：玩家改变了 NPC 的想法，但世界里没有任何地方记下这件事发生过 → 素材的核心卖点无法在 UI 上呈现，也无法测试 |

**Lead 推荐：B（先不做）**，但附一个条件——**§5.1 的称号与 §5.3 的链式影响必须有可观测的落点**。如果最终发现「链式影响没法测」，再回来走 A。这正是宪法「警惕 YAGNI / 过度设计 / 无脑加宽引擎」的应用。

## 8. UI 与美术（华丽起手铁律）

CLAUDE.md：「朴素默认 UI = 缺陷」「华丽度 = 第一要素」。本框架的起手三步：

2. **起手包**：主菜单 / 每日结算屏直接 `import` `@ui/starters`（`buildStarterHome` / `buildStarterResult`）。

## 9. 日志基准（DebugTrace 接线点）

按日志基准守则，**写带逻辑的代码就同提交接 trace**。111 的四类记录点：

| 类 | 记在哪 |
|---|---|
| `decision` | 意图层选了哪条记忆进 prompt（只记 top-K 的 id，不 dump 内容）；导演选了哪个 nudge |
| `transition` | 回合相位跳转（`INTENT→COMMIT`）；NPC 等级降级（`L5→L2`，断网时） |
| **`reject`** | **本项目最重要**——LLM 输出解析失败 / 动词不在闭集 / 参数越界 / 目标不存在 / 回包超时补默认意图。**凡「什么都没发生」的分支必须记** |
| `commit` | 本回合每个 NPC 实际落地的意图摘要（npcId + verb + 主要参数） |

密度：每 system 每 tick ≤ 3 条，无事 0 条。验收：**开 trace 跑一回合，只读 trace 能重建出「为什么茉尔去了后山」**。

三条红线照旧：进 `NON_DETERMINISTIC` · 禁墙钟 · 关时真 no-op。
