# game111 · 战斗卡牌化：怎么融合（策划）

> owner 2026-09-17：想把战斗卡牌化，如何融合。

---

## 0. 先说会翻车的那条路

**最直觉的做法**：白天收的菜变成卡，夜里当手牌打出去。

**这条路是 Farmagia 的死法。** 它的评测原文是「farming 是 afterthought」——
一旦收成只是「备牌」，**种田就退化成战斗前的准备环节**，种什么、种在哪、什么时候收，
全都只剩「凑够牌」这一个目的。市场报告 §二.1 已经点过：
**这个品类里战斗本来就容易压过种田，卡牌化会加剧这件事，不会缓解。**

判据仍然是那条：**把夜战拿掉，白天的决策是否还一样做。**

---

## 1. ⭐ 真正的答案：**田本身就是牌桌**

把两边的动作摆在一起看：

| 卡牌游戏 | 种田游戏 |
|---|---|
| 你把**一张牌**打到**牌桌的一个位置** | 你把**一颗种子**种到**田里的一格** |

**这是同一个动作。**

于是不需要「收成→转换成卡→再打出」这一层。**种下去，就是出牌。**

> **你白天种的每一格，就是你今晚的一张牌——而且它已经在牌桌上了，盖着。**

### 1.1 由此得到的三段结构

```
白天  ──▶  出牌（你把牌打到桌上，盖着）
黄昏  ──▶  亮牌（预告：看到部分牌面，还来得及收一张回来）
夜里  ──▶  结算（牌按规则互相作用）
```

**这三段和 `core-loop.md` §2 的心流曲线是同一条**，只是换了卡牌的说法。
不是新加一套系统，**是给已有的循环换了一副更好的语言**。

### 1.2 为什么这个融合是对的

| 它解决了什么 | 怎么解决的 |
|---|---|
| **种田实感不丢** | 种田不是「获取卡牌的手段」，**种田就是出牌本身** |
| **「种在哪」第一次真的重要** | 牌桌有位置，田格有位置，两者合一 |
| **不用抽卡** | 你提前一整天就把牌打出去了。夜里只是翻开 |
| **反悔机制天然存在** | 黄昏抢收 = **把一张已经打出的牌收回来**（代价：打断「最后一捆」的布置） |
| **战斗深度有地方长** | 这是市场报告 §二.1 那个全品类缺口的正面解法 |

## 2. 三个牌库来源 = 白天的三件事

这是整套设计里最干净的一处对应。**你白天能做三件事，它们各自产出一种牌**：

| 牌种 | 来源（白天的活动） | 在牌桌上是什么 |
|---|---|---|
| **场面牌** | **种地** | 你种下的作物。已在桌上，盖着，夜里翻开 |
| **技能牌** | **去镇上打听** | ⭐ **名字与传闻**（见 §3）。你手里的主动手段 |
| **随从 / 遗物** | **打赢并收服妖怪** | 长线积累的常驻战力（补上回程车流） |

> **三个来源对应白天的三种活动，而白天的时间是有限的。**
> 于是「今天是去种地、去镇上、还是去打」变成了一个**构筑决策**——
> 你在决定今晚这副牌长什么样。

## 3. ⭐ 名字就是卡（呼名 × 卡牌的接点）

`monster-prototypes.md` §3 那条呼名线，卡牌化之后**变得比原来更好**：

- **不知道它的名字** → 你手里**没有**对付它的牌。只能硬打。
- **打听到名字** → 你**获得一张「呼名」卡**。
- **打出这张卡** → 喊出它的名字 → 它僵住 / 现形 / 不战而退。

**这一下把三块焊死了**：

```
白天在镇上聊天  ──▶  拿到名字  ──▶  变成一张卡  ──▶  夜里打出去
    （AI NPC 层）      （情报）      （构筑）        （战斗）
```

**111 已经做好的记忆系统、NPC 对话、好感度，产出物直接就是卡。**
不用重做任何东西，只是它们的产物从「称号」扩成了「牌」。

> 而且呼名卡有一个别的卡没有的性质：**它是知识，不是资源。**
> 用掉不会消失（你还是知道那个名字），但**只对特定的那一只有效**。
> 这让「收集名字」变成一条独立的、长期的成长线。

## 4. 四种卡牌化方案的取舍（我的裁决）

| 方案 | 说的是 | 判决 |
|---|---|---|
| **A · 田即牌桌** | 种下去 = 出牌，田格 = 牌位 | ✅ **推荐主线**。见 §1 |
| **B · 种子即牌库** | 你带哪些种子进这一季 = 构筑 | 🔶 **可作为 A 的补充**：季初选种 = 赛前构筑，但**不要让它取代 A** |
| **C · 收成即手牌** | 收的菜在夜里当手牌打 | ❌ **驳回**。Farmagia 的死法，种田退化成备牌（§0） |
| **D · 妖怪即卡** | 打服的妖怪变成你的卡 | ✅ **推荐作为长线成长**。补回程车流，收集欲强 |

**推荐组合：A 为主（每夜的玩法）+ D 为长线（跨夜的成长）+ B 为季度构筑（中循环）。**

三者各管一个时间尺度，互不打架：

| 尺度 | 谁管 |
|---|---|
| **一夜** | A —— 今天种了什么，今晚就是什么牌面 |
| **一季** | B —— 这一季我带哪些种子（构筑） |
| **长线** | D —— 我收服了谁，他们常驻在我的牌组里 |

| 已定的设计 | 卡牌化之后 | 结论 |
|---|---|---|
| 八派六味克制（`sect-taxonomy.md`） | **直接就是卡牌的类型与属性** | ✅ 强化 |
| 黄昏预告（`core-loop.md` §2.1） | **亮牌阶段** | ✅ 强化 |
| 最后一捆 → 头目 | **最后打出的那张牌成为关键牌** | ✅ 强化 |
| 善恶由种法决定 | 同一张牌，两种打法两种结果 | ✅ 兼容 |
| 放着不收 → 升阶 | **牌留在桌上会自己变强** | ✅ 强化（更有画面） |
| 偷菜（`core-loop.md` §6.6） | **妖怪的目标是拿走桌上的牌** | ✅ 兼容且更清晰 |

**是给已经长成这个形状的设计，找到了它本来该用的语言。**

## 6. 还没解决的三个问题

1. **构筑深度从哪来？**
   A 方案不抽牌，所以传统卡牌那种「抽牌运」带来的变化没有了。
   深度必须来自**空间**（种在哪）+ **时机**（什么时候收）+ **组合**（三姐妹式配植）。
   ⚠ **这一条需要纸面原型验证**，是本方案最大的未知。

2. **牌面上写什么？**
   `sect-taxonomy.md` §0 定了「用图标认植物，不用名字」。
   那牌面就是**一张图标 + 派系色 + 味的符号**，**不写字**。
   这其实很好——但**数值怎么表达**要设计（图标大小？角标？）。

3. **手牌区还要不要？**
   §3 的呼名卡、辛派的防御牌，这些是真正的「手牌」。
   那么屏幕上就有两个区：**田（已出的牌）+ 手（技能牌）**。
   ⚠ 会不会太复杂？还是说这正是深度所在？
