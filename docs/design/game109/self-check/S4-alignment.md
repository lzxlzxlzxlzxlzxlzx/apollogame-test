## 2. 玩家视角复核八问（`self-check.md:44-73`·逐条答·不许答「还行」）

**1. 核心信息是不是屏上最抢眼的？** ❌ **不是。**
这游戏的玩法赖以成立的信息 = **每格的地块状态与生长阶**，而它在屏上**根本不存在**（§0 实测 0 像素）。
屏上最抢眼的是 36 块静态色块——它编码的是「这一列种什么」（装配期定死），**不是**「现在怎么样了」。
最抢眼的位置给了最不随时间变的信息。**归 S4（信息层级）。**

**2. 我刚做的操作，屏上有确认吗？** ❌ **几乎没有。**
选工具有确认（`▶` + 读数），睡觉有（日期跳），卖货有（金币跳）。**但 108 次干活里没有一次有**：
点地块后地块像素不动，唯一变化是 HUD 的体力数字 −1 ⇒ 玩家要靠**盯数字反推**点没点上。
**归 S4（状态可见性）。**

**3. 结果发生那一刻，能一眼看出「发生了什么·赢没赢·代价多少」吗？** 分裂。
**赢** ✅ 一眼看出：「通关！」大字 + `用时 7 天 · 最终金币 1026 / 1000`。
**日常的「结果」** ❌ 看不出：收获那一下屏上**没有任何东西增加**（背包不存在），只有体力 −1 和几天后金币涨。
**归 S4（出胜负明示已达标；日常结果明示缺失）。**

**4. 数值差异有没有视觉差异？** ❌ **没有。最大与最小长得一模一样。**
一块刚翻的荒地，与一块熟透待收的南瓜地，**像素完全相同**。这正是不合格定义本身。
**归 S4（定层级）；强弱留给 S5。**

**5. 我知道现在在哪个阶段、还剩多久、第几回合吗？** ✅ **知道。**
`第 N 天` 在屏上；`体力 N/20` 就是「今天还剩多少下」。这是本屏做得最好的一条。
**S4 达标。**

**6. 第一次打开的人，知道这些键干嘛吗？** 部分。
6 枚键的文字**就是动作名**（锄地/播种/浇水/收获/睡觉/卖货），不用教 ✅。
❌ 但**36 格的颜色没有任何人解释过**：左两列橙、中两列黄、右两列暗橙、同列内深浅相间。
玩家无从知道「颜色 = 作物、深浅 = 棋盘格」，**更会误读成「深浅 = 状态」**——
而它恰恰**不是**状态。**记为教学设计缺失**（该列清单报裁决）。

**7. 有没有「世界侧通了但玩家点不到」的功能？** DOM 侧 ✅ 6/6 够得着
（`ui-inventory.mjs` 实测绿；该工具对回合制游戏的量程盲区已单独实测交代）。
❌ **但世界侧通了、玩家「看不到」的是一大批**：地块状态 / 生长阶 / 成熟 / 今日已浇 / 背包——
世界里全有值（`State.current`、`Resource.current`、`Flag.active`、`inv-*`），屏上 **0 处**呈现。
第 7 问的变体：**不是点不到，是看不到**。**归 S4（功能缺失）。**

**8. 屏上每样东西，玩家知道它是谁的、是哪一刻的吗？** ❌ **答不出。**
① **归属**：底下那排 6 个实体和地块**同一尺寸、同一排布**，没有任何视觉区分（颜色已被地块占用为作物编码）——
指着问「这是按钮还是地块」无从回答，而它确实**是**可点的按钮（PE 实测：终局屏点它天数会跳）。
② **时效**：指着某格问「这是这一天的还是上一天的」无从判断——浇水标记不可见，而它按天清除。
**归 S4（状态可见性）。**

## 3. 好玩三问 + 节奏检查（`self-check.md:75-81`）

**这局玩完，我想再来一把吗？为什么？**
**不想。** 不是因为不好玩，是因为**看不见自己经营了什么**：7 天 108 下点完，
农场与第一帧**一模一样**；通关那一刻，屏幕下方的农场**仍然是空的样子**。
「再来一把」的前提是「我看到了我的经营在长」，而这个前提当前不成立。

**关键操作的反馈（打中/得分/失败）一眼看得见吗？**
**看不见。** 收获/播种/浇水/翻土四种**全部**：地块 0 像素变化，只有体力 −1。
**失败（被拒）完全无反馈**——实测图 3b→4：画布 0 像素，HUD 只有「选工具」那 6242 像素，
被拒那一下**屏上什么都没发生**。这条最严重：玩家会以为自己没点到，于是**重复点**。

**有没有让我困惑或等待的瞬间？在哪一步？**
