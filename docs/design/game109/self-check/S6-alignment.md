## 9. 闭卷后的那次修复：生长条「错位 + 随阶漂移」（owner 报的 bug）

**触发**：owner 2026-09-19 逐行复核之后报「方块下面的黑色横条错位，比方块靠左」。
**定性**：**不是美术画错**（`plant-bar.svg` 的 `track x="1" width="94"` 在帧内是居中的、填充也是左锚画的），
是**贴图的锚点语义与 gauge 的原点语义不一致**。

### 9-① 机制（代码 + 实测两半都钉住）

`src/skills/tier2/gauge.ts:114-115` 是引擎**故意**这么写的（`src/engine/protocol/components/render.ts:642-646` 复述了理由：
「渲染 box 以中心为 pivot、缩放只能对称收缩，锚不了左」）：

```ts
Shape.width      = clamp01((current - min) / (max - min)) * Gauge.width;
Hierarchy.localX = (g.leftX ?? -g.width / 2) + shape.width / 2;   // 左端钉死、从右端缩
```

⇒ **原点随比例移动**：stage 0 时 `localX = −48`（`PLANT.w = 96` 的一半），满阶回到 0。素坯期 `Shape` 宽 0 ⇒ 位移看不见；
S6 上图后 96 宽的贴图按 `anchorX: 0.5` **居中画在那个移动的原点上** ⇒ 整条左偏半宽，并随生长阶右移最多半宽。
引擎侧无处可修：渲染器 box 以中心为 pivot、`Shape` 没有位置偏移字段 ⇒「左端钉死」只能靠移动原点换来，
与「固定尺寸贴图」**数学上互斥**。

实测（真浏览器截图，逐行扫暗横条，设备 px；同一条量法量三态）：

| 屏 | 修前（`s6-prefix/`）条中心−格中心 | 修后（现 `shots/`） |
|---|---|---|
| `1-start`（全格 stage 0） | `−51, −51, −51, −51, −50` | **`0, 0, 0, 0, 0, 0`** |
| `5-first-harvest`（成熟期） | 错配（`−97` / `+67` / `+219`）并出现一条 **190px 宽的并条** | **6 条各自独立、逐格 0**（其中一条 −1，取整） |

（每行第一项是场地围栏的暗边、不是条。）另：`s5/`（换装前）那一态在**同一扫法下一条暗横条都扫不到** ——
素坯期 `Shape` 宽 0 ⇒ 不可见 ⇒ **这个错位从 S3 起就在，只是上图才把它显形**。
