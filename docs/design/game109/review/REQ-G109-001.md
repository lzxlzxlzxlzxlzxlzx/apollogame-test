## 三、三处**我想请你重点看**的判断（最可能出错的地方）

1. **「id 不符则不施、且不回落全局」——这个取舍你认不认？**
   理由：回落 = 又写错实体（正是本缺口本身的形状）。代价：**数据写错 id 时不报错、只是不生效**——
   正是 `events-logic.md` ③′ 反复警示的「不报错、就是不生效」。我**刻意**沿用孪生件 `set-flag-tagged` 的静默纪律以保持一致，并把「逻辑链寻址失配要不要告警」列为工单 §7 的债务、不在本件收口。
   **请判**：本件该不该打破孪生件的静默、加一道硬抛/告警？

2. **多源信号**：`targetsOf('@signal-source')` 返回的是 `sources.get(onSignal)`，即**本拍发出该信号名的全部实体**，不是「一个」。
   物理 kind 早就如此；逻辑 kind 我继承了这个语义。若同拍有两格各发 `act`，则两格都会被改，且 `appendScoreEvent` 会按元素各记一次。
   **请判**：这是既有语义的自然继承（我倾向：是），还是逻辑 kind 该另立「只取一个」的语义？

3. **`set-state` 用 `ds.fsmId === ef.targetId` 匹配**——我假定全局路径 `lookup.state(ef.targetId)` 也是按 `fsmId` 定位。
   **请核**：这个等价性成立吗？若 `lookup.state` 的匹配键不是 `fsmId`（或不止按 `fsmId`），那第 3 支的「实体路径」与「全局路径」语义不等价。
