# game109 《暂名》· S1 立项卡

> owner 2026-09-17 定：**编号 game109**（接 101–108 主线顺延）· **回合制日**（非实时）· **名字先挂暂名**。
> 目标 = **在引擎里快速实现一个可玩的星露谷式种田 demo**（非商业量产项目）。

## 一句话玩法

**每天有一定的体力，点地块干农活；干完睡觉，作物长一天；卖货攒够目标金币就算通关。**

参照物：星露谷物语的「种—长—收—卖—睡」核心循环，**剥离**实时时钟、战斗、社交、下矿、建造。

## 「回合制日」的确切定义（本项目的根设计·owner 已定方向，此处落成可实现的规格）

- **一天 = 一串离散动作**，不是一段实时时钟。引擎里「时间」不流逝，**体力的消耗就是时间的度量**。
- **一次动作** = 选定当前工具（翻土 / 播种 / 浇水 / 收获）+ 点一个地块 = 扣 1 点体力。
- **结束一天** = 玩家主动点「睡觉」→ 结算：作物按天生长一阶 → 体力回满 → 日期 +1。
- 体力耗尽**不强制**结束（可继续以 0 体力空转查看农场），只有睡觉才推进日。
- 推论：**不需要分钟/时刻/换季/天气**。这些全部出局，不是在 demo 里简化，而是本项目定义上就不存在。

## Demo 竖切范围（In / Out of Scope）

| In Scope（本 demo 要跑通的） | Out of Scope（后续批次 / 不做） |
|---|---|
| 一小块地（6×6 = 36 格），逐格状态 | 多区域地图 / 农场扩建 |
| 4 个动作：翻土 / 播种 / 浇水 / 收获 | 工具升级 / 耐久 / 锄头种类 |
| 3 种作物（生长天数与卖价各异） | 几十种作物 / 品质分级 / 巨型作物 |
| 体力 = 每日动作预算 | 食物回体力 / 温泉 / 体力药 |
| 睡觉 = 推进一天，作物按天生长 | 季节 / 天气 / 节日 |
| 收获物进背包，卖货换金币 | 商店 UI / 浮动价格 / 订单委托 |
| **通关判据：攒够目标金币**（T2 闭环门的推进出口） | NPC 好感 / 送礼 / 剧情 / 结婚 |
| — | 钓鱼 / 下矿 / 战斗 / 建造 / 多人 |

> 「攒够目标金币」这一条是刻意的：它给一个本没有胜负的游戏一个**明确的终局**，
> 好让 T2 闭环竖切（开始→操作→推进→可重开）**能被机器证明**。这是流程要求反过来定的玩法。

## 核心循环（一条链，不做分支）

```
点地块 → 当前工具作用在该格 → 扣体力
  翻土：荒地 → 已翻土
  播种：已翻土 + 有种子 → 已播种（第 0 阶）
  浇水：已播种 → 今日已浇（不浇则当天不生长）
  收获：成熟作物 → 产物进背包（Resource +N），地块回「已翻土」
睡觉 → 每种已浇的作物长一阶；未浇的不长；浇水标记清除；体力回满；日期 +1
卖货 → 背包里的作物换成金币
金币 ≥ 目标 → 通关结算屏
```

## 技术路线（S2 待证）

**目标：全程 L0/L1（纯数据 + 现有能力重组），零引擎改动、零 A/B 裁决。**

依据：回合制日消解了「日历」缺口，「一格一实体」是 game102 的既定正路（Lead 认可），
背包用「一个物品一个 Resource」的现成惯用法（game101 先例），玩家不用走格子所以没有方格移动 / 四向朝向问题。

**但这是推理不是实证**——下列三条接线组合必须在 S2 用最小 manifest 真跑一遍（缺口裁决协议第①步的实查）：

| # | 待证组合 | 风险点 |
|---|---|---|
| P1 | **点某格 → 只改那一格的状态** | 最高危。`events-logic.md` ③′ 记明引擎的 `Effect.targetId` / `ConditionExpr` 是**全局 id 路由、无 `entity` 字段**，为这条出过五次事故。农场是「每格都有同名状态」的教科书级踩坑场景。 |
| P2 | **睡觉信号 → 所有作物各长一阶** | `effect-apply` 的 `set-flag-tagged` 能按 Tag 掩码批量置 Flag，重组**可能**成立，要证。 |
| P3 | **体力不够 → 动作被拒** | 负路径。`craft-recipe` 自带「可负担才扣」，有可能白送，要证。 |

- **三条全绿** → 直接进 S3 骨架，全程 L0/L1。
- **任一条红** → 该条成为**真缺口**，走 A/B 两路（A 补引擎 / B 游戏独有逻辑）交 owner 裁决，落 `capability-gaps.json`。
