## 动作词表（`signal`）——就是屏上的 `data-action`【R-108-70·词表对齐律】

| `signal` | 屏上是什么 | 含义 |
|---|---|---|
| `pick-till` / `pick-sow` / `pick-water` / `pick-reap` | HUD 工具键（`TOOLS[].pickSignal`） | 换当前工具（翻土 / 播种 / 浇水 / 收获），**不扣体力** |
| `work` | **Canvas 上的地块**（无按钮） | 干当前的活：`args.tile` 指出点的是哪一格，扣 1 体力 |
| `sleep` | HUD 动作键 | 睡觉：作物长一阶 · 体力回满 · 日期 +1 |
| `sell` | HUD 动作键 | 卖货：背包里的作物换成金币 |
| `restart` | 结算屏上的**重开**键（`HUD_ACTION.restart`） | 拆掉本局、照原路径重挂一局（`game109.ts` 的宿主 handler） |

词表与 `games/game109/hud.ts` 的 `TOOLS[].pickSignal` / `ACTIONS[].signal` / `HUD_ACTION.restart`
**同一串字符**——机器才点得动（game-a 曾因两套词表各写各的，可驱动率 0/19）。

⚠ **`restart` 在两个域里同名不同源**（`hud.ts:54-62` 明记）：`pick-*`/`work`/`sleep`/`sell` 是**世界信号**
（找不到本地 handler ⇒ `enqueueAction` 入队 ⇒ Effect 按名消费）；`restart` 是**宿主动作**
（`mountUI` 查得到本地 handler ⇒ 就地拆局重挂，**不入队**）。「往世界里发一个名叫 restart 的信号 =
屏上那颗键点了没反应且不报错」——所以剧本 07 的重开段要能跑，`acceptance-adapter.ts` 必须为
`restart` 单独约定一条落到世界层的路（见下「接线约定（**已裁定**）」）。

## 时序纪律（三条，都是被真事故逼出来的）

1. **`waitUntil` 优先**（先查后拍·`cap` 必填）：表达「等到体力回到 20」「等到那格变成 sown」，
   不赌拍数。裸 `{ "tick": N }` 只在**两种地方**用：
   - **拒绝路径**——「什么都没发生」`waitUntil` 表达不了（条件恒真 ⇒ 0 拍返回 ⇒ 信号还没被消费，
     等于没测）；
   - **每次睡觉之后的观察窗（3 拍）**——生长与清标记是**下一拍**才施放的（`brief.md:16` 的落定时序），
     不摆窗就判生长，「本夜不长 / 只长一阶」会在生长**之前**被判过 = **假绿**。
     这一窗还顺带把「相位旗卡真会二次生长」暴露出来。
2. **换工具两步走**：`{signal:'pick-x'}` 然后 `{waitUntil:[{res:'tool',eq:N}]}` 再干活——
   不依赖「同一拍里换工具与干活谁先施放」的隐式序（那是把语义交给 eid 字典序）。
3. **格子断言一律 `comp` + 显式实体 id**（理由见上「机读态」）。
