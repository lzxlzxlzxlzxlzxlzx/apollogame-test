# game-105 AI 美术外部试验计划

> 状态：计划稿，尚未执行  
> 目标：在不修改现有 S1–S8 生产流程、不替换正式素材、不改变玩法与 UI 结构的前提下，验证“AI 发现视觉问题 → 生成候选 → 放回真实画面验证 → 人工选择”的闭环是否有效。  
> 首选生成工具：Codex 内置图像生成功能。  
> 当前正式版本：`games/game-105/` + `public/games/game-105/art/`，试验期间保持不变。

## 1. 为什么先做外部试验

当前美术系统已经具备稳定素材 ID、资源索引、素材台账、程序化回退、多状态截图和 S7 视觉评分卡。主要缺口不是“不能换图”，而是缺少对素材进入真实游戏后的自动复查与定向再生成。

本轮不直接改生产流程，原因如下：

1. 需要先证明 AI 视觉复查能够稳定发现真实问题，而不是产生大量主观建议。
2. 需要先测量图像生成对透明边缘、九宫格、角色一致性和材质平铺等技术约束的服从程度。
3. 需要确认生成候选放入游戏后确实提升画面，而不是孤立素材看起来漂亮、整屏效果反而变差。
4. 需要得到真实的耗时、生成轮数、人工选择成本和失败率，再决定流程自动化程度。

## 2. 试验边界

### 允许

- 读取当前游戏源码、正式素材、台账、截图和视觉证据。
- 使用内置图像生成制作候选素材。
- 在独立试验目录保存提示词、候选图、分析结果和合成截图。
- 复制一份页面截图或素材用于离线合成。
- 使用临时覆盖表或独立预览页验证候选，但不得写入正式资源索引。
- 对候选执行尺寸、透明通道、边缘、对比度和文件体积检查。

### 禁止

- 不修改 `games/game-105/` 的玩法、布局、AI或物理代码。
- 不修改现有 S1–S8 阶段定义、门禁逻辑或生产流程面板。
- 不覆盖 `public/games/game-105/art/` 中已批准素材。
- 不修改正式 `art-ledger.json`、`index.json` 或 `pipeline.json`。
- 不把试验候选标记为 approved/filled。
- 不以孤立素材图代替真实游戏画面验收。

## 3. 独立试验目录

所有试验产物统一放在：

```text
experiments/game-105-ai-art/
├─ baseline/              当前正式画面与素材副本
├─ specs/                 风格包、槽位规格、检查规则
├─ prompts/               每轮生成提示词与负向约束
├─ candidates/            AI 生成候选，按素材槽和轮次分组
├─ normalized/            去背景、裁切、缩放、格式归一化后的候选
├─ composites/            候选放回真实截图后的合成效果
├─ runtime-preview/       临时实机覆盖结果
├─ reports/               机器检查、AI复查和人工结论
└─ rejected/              淘汰候选及原因
```

该目录属于试验工作区，不参与当前游戏发布。若未来决定保留，应再裁定哪些内容进入项目版本管理。

## 4. 本轮验证问题

试验不是泛泛地“让AI把游戏画漂亮”，而是回答以下问题：

1. AI能否从多状态截图中稳定发现棋盘格、透明残边、文字对比不足、按钮变形和遮挡？
2. AI能否生成真正适合九宫格缩放的UI框体，而不把文字烘焙进图片？
3. AI能否生成四张角色一致、姿态和表情不同的透明背景立绘？
4. AI能否生成可平铺、没有明显接缝的木材颜色/法线/粗糙度素材？
5. AI能否保持“月灯奶油夜”的风格，同时不让背景抢过3D积木塔？
6. 自动技术检查能否淘汰明显错误候选，减少人工逐图检查成本？
7. AI给出的视觉评分，是否与人在真实游戏里的感受大体一致？
8. 一项素材通常需要几轮生成、多少候选和多少人工时间才能达到可用水平？

## 5. 试验对象与优先级

### P0：互动卡框

当前问题：玩家互动卡边缘出现明显棋盘格/透明残留，属于成品阻断级问题。

生成目标：

- 透明 PNG。
- 奶油纸卡、玫瑰金边、温柔夜间约会风格。
- 中央为干净低纹理文字安全区。
- 不含任何文字、数字、图标或棋盘格。
- 四角装饰固定，边缘可九宫格拉伸。
- 同时适配玩家卡、AI卡和收尾卡的尺寸。

验证重点：透明通道、边缘污染、九宫格拉伸、正文可读性、桌面与窄屏状态。

### P0：主次按钮

当前问题：不同尺寸按钮存在拉伸感，长文本可能换行，主次按钮视觉权重不稳定。

生成目标：

- 主按钮与次按钮为同一设计语言。
- 无文字透明按钮底图。
- 明确九宫格安全区。
- 可覆盖普通、悬停、按下、禁用状态；首轮可以先测试普通状态。

验证重点：短标签、长标签、单行保持、不同宽度、窄屏点击区域。

### P1：AI角色立绘组

当前问题：已有四张立绘，但角色在实际画面中的存在感弱，一致性和状态表达需要重新评估。

生成目标：

- 同一角色、同一服装、同一光向和统一裁切。
- 透明背景半身像。
- 至少覆盖思考、期待、开心、害羞四态。
- 表情差异清楚，但不夸张、不幼态。
- 在小尺寸显示时仍能辨认状态。

验证重点：角色一致性、小尺寸辨识度、UI内裁切、与背景色分离、AI各阶段状态匹配。

### P1：积木与桌面材质

当前问题：积木偏塑料感，桌面纹理重复明显，2D背景和3D舞台融合不足。

生成目标：

- 一套可平铺的轻木颜色纹理。
- 配套法线和粗糙度；若内置生成暂不适合直接生产技术贴图，先验证颜色纹理与高度参考，再离线派生法线/粗糙度。
- 四个频道继续由游戏参数染色，不为54块分别生成贴图。
- 桌面纹理尺度更自然，减少周期性波纹。

验证重点：无缝平铺、重复感、色彩染色效果、近景质感、性能和文件体积。

### P2：背景分层与氛围件

当前问题：背景细节较丰富，有时与塔竞争；2D房间和3D桌面之间仍有拼接感。

生成目标：

- 保留现有房间构图，优先生成“弱细节远景”候选，不立即重做整个场景。
- 尝试拆分远景、柔光、暗角、前景光点等层次。
- 中央塔区留出低对比视觉空间。

验证重点：主体显著度、透视一致性、不同相机角度、互动卡出现时的画面负荷。

## 6. 第一轮执行方式

第一轮只选择两个对象：互动卡框和AI角色立绘。一个是技术型问题，一个是一致性/情绪型问题，可以验证两类不同能力。

### 6.1 建立基线

固定以下真实游戏状态：

- 1280×720：开局、玩家互动卡、AI观察、AI抽取、倒塌。
- 800×450：开局、玩家互动卡、AI抽取。
- 390×844：开局、玩家互动卡、倒塌。

同时记录：

- 当前素材文件。
- 当前画面截图。
- 当前S7评分和已知问题。
- 页面上的实际消费尺寸与裁切方式。

### 6.2 编写槽位规格

每个试验素材建立一份 `ArtSlotSpec`，至少包括：

```json
{
  "skinKey": "game-105/ui/card-frame",
  "purpose": "互动卡框",
  "format": "png",
  "transparent": true,
  "embeddedText": false,
  "nineSlice": 22,
  "safeTextArea": { "left": 44, "top": 40, "right": 44, "bottom": 40 },
  "styleTags": ["cream-paper", "rose-gold", "romantic-night"],
  "forbidden": ["checkerboard", "letters", "numbers", "heavy-center-texture"]
}
```

角色槽位还要增加角色身份锚、服装锚、镜头、光向、姿态和表情字段。

### 6.3 使用内置图像生成

每个槽位首轮生成4个候选，不直接追求一次命中。

提示词由以下内容拼接：

```text
游戏风格锚
+ 槽位用途
+ 构图和技术规格
+ 与现有画面的关系
+ 禁止项
+ 输出要求
```

所有候选保留：

- 完整提示词。
- 使用的参考图。
- 生成批次。
- 候选编号。
- 人工或机器淘汰原因。

### 6.4 素材级技术检查

候选进入合成前必须通过：

- 文件可解析。
- 尺寸与宽高比符合规格。
- 需要透明时确有透明通道。
- 边缘无棋盘格、白边、黑边和大块脏像素。
- 中央文字安全区满足要求。
- 图片中没有误生成文字。
- 文件体积在预算内。
- 平铺素材通过四宫格拼接检查。

失败候选直接进入 `rejected/`，不浪费整屏验证时间。

### 6.5 离线合成检查

先把候选放入现有截图对应位置，生成不影响运行时的合成预览。

检查：

- 是否遮挡文字。
- 是否与其他面板属于同一风格。
- 是否抢夺积木塔的视觉焦点。
- 是否在桌面与窄屏都成立。
- 角色状态是否一眼可辨。

离线合成通过后才进入临时实机覆盖。

### 6.6 临时实机覆盖

实机验证必须使用独立覆盖表，不修改正式索引。候选至少跑过：

- 开局。
- 玩家抽取与松手。
- 玩家互动卡。
- AI观察和抽取。
- 心动值增加。
- 倒塌与重开。

记录控制台错误、加载失败、布局变化、帧率变化和截图。

### 6.7 AI视觉复查

将基线与候选截图成组交给视觉模型，要求输出结构化结果：

```json
{
  "verdict": "pass | revise | reject",
  "issues": [
    {
      "severity": "P0 | P1 | P2",
      "state": "player-interaction",
      "asset": "game-105/ui/card-frame",
      "problem": "透明边缘出现黑色残留",
      "evidence": "候选B左侧边框",
      "promptPatch": "clean transparent alpha edge, no dark fringe"
    }
  ]
}
```

AI必须指出画面区域和证据，不接受“整体更高级”“可以再精致”等空泛意见。

### 6.8 人工选择

人工只需要回答：

1. 这个候选是否符合产品情绪？
2. 是否明显优于当前正式版本？
3. 是否存在AI和机器没有发现的问题？
4. 是否值得进入正式替换提案？

本轮即使产生优秀候选，也只形成“建议替换包”，不自动写入游戏。

## 7. 验证维度

### A. 技术正确性

- 格式、尺寸、透明、色彩空间正确。
- 九宫格缩放不破坏四角。
- 不产生加载错误。
- 不改变布局、点击区域和玩法。
- 性能退化不超过既定预算。

### B. 视觉质量

- 艺术方向一致。
- 积木塔仍是主视觉。
- AI角色状态可辨。
- UI正文清晰。
- 背景、3D和UI不会互相争夺注意力。
- 桌面与窄屏都达到可用底线。

### C. AI生成能力

- 首轮技术合格率。
- 两轮内可用率。
- 同角色一致性。
- 对透明和无文字约束的服从率。
- AI复查问题与人工判断的一致率。
- AI生成的修复提示词是否真的让下一轮改善。

### D. 生产效率

- 单项素材生成耗时。
- 平均候选数量。
- 人工筛选时间。
- 每项素材的重试次数。
- 最终保留率。
- 与人工从零制作相比节省的时间。

## 8. 通过标准

首轮试验满足以下条件才建议进入第二轮：

1. 互动卡框在三种分辨率下无棋盘格、无透明残边、无正文遮挡。
2. 新卡框比当前版本获得明确的人工偏好，且AI评分没有明显误判。
3. 四张AI立绘被人判断为同一角色，小尺寸下至少三种状态可清楚区分。
4. 生成候选不会修改正式游戏文件，也能完成真实页面验证。
5. 至少一种失败可以通过AI生成的 `promptPatch` 在下一轮得到修复。
6. 单项素材最多两轮生成即可得出“采用或放弃”的明确结论。

任一以下情况出现，则暂不自动化：

- AI持续生成带文字或假透明背景的UI。
- 角色一致性无法稳定维持。
- AI视觉复查与人工判断频繁相反。
- 候选进入真实页面后普遍不如孤立预览。
- 每项需要大量人工修图才能使用。

## 9. 分阶段安排

### Pilot 0：准备

- 固定基线截图。
- 建立实验目录和两份槽位规格。
- 确定人工评价表。
- 不生成图片。

### Pilot 1：互动卡框

- 生成4个候选。
- 完成技术检查、离线合成和AI复查。
- 选择最多2个进入临时实机覆盖。
- 得出采用、重试或放弃结论。

### Pilot 2：AI角色立绘

- 先生成角色母版。
- 锁定母版后生成四种状态，而不是四张独立自由生成。
- 验证一致性和小尺寸识别。
- 选择最多1组进入临时实机覆盖。

### Pilot 3：材质

- 测试积木木纹和桌面无缝纹理。
- 验证平铺、染色、PBR派生和性能。

### Pilot 4：总结

- 汇总基线、候选、评分、耗时和失败类型。
- 判断哪些步骤适合机器规则、哪些适合视觉模型、哪些必须由人决定。
- 输出生产流程改造提案，但此时仍不直接修改现有S1–S8。

## 10. 预期最终产物

试验结束应交付：

1. 一套可复用的游戏视觉风格包草案。
2. 两到四份 `ArtSlotSpec` 样板。
3. AI图像生成提示词模板。
4. 候选素材及淘汰记录。
5. 基线/候选多状态对比图。
6. AI视觉复查结构化报告。
7. 人工最终选择记录。
8. 成本、耗时、成功率统计。
9. 是否值得修改正式生产流程的结论。
10. 若值得，下一阶段的最小流程改造清单。

## 11. 建议立即开始的最小实验

首个实验只做 `game-105/ui/card-frame`：

1. 以当前玩家互动卡截图作为上下文参考。
2. 以现有 `card-frame.png` 作为问题参考，而不是风格唯一参考。
3. 使用内置图像生成一次产出4个透明卡框候选。
4. 检查透明通道和九宫格。
5. 合成到桌面与窄屏两张截图。
6. 做AI对比复查。
7. 由owner选择是否值得进入第二轮。

这个实验范围最小、现有问题最明确，也最容易判断AI闭环是否真正有效。
