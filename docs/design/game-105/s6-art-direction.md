> GD-105 · 2026-08-30 · 前置：S1--S5 已签核。本文只定义正式美术资产、替换槽和验收；不改变 S4 冻结的结构、玩法、AI 行为或物理参数。

## 1. S6 目标

将已可玩的程序化竖切替换为可追溯、可审核、可替换的正式美术包，同时保持以下事实不变：

- 54 块真物理塔、尺寸、碰撞盒、抽离阈值与倒塌规则不变。
- S4 冻结的 HUD、操作区、互动卡区、余波提示区、收尾卡区的位置、层级、交互与状态可见性不变。
- Local AI 仍只使用本地模板和共享执行器；美术不得暗示风险预测、成功率或 AI 读取物理私有信息。
- 倒塌为中性收尾，不使用“惩罚”“胜利/失败”“稳定度”叙事。

## 2. 风格锚

**主题名：月灯奶油夜。**

- 情绪：私密、轻松、温柔，不幼态化或过度甜腻。
- 主色：奶油纸 `#FFF4E2`、雾粉 `#E8A7B4`、梅紫 `#72526D`、夜蓝 `#263554`、柔金 `#D7A54A`。
- 材质：轻木纹、哑光纸卡、细金属边、暖灯漫反射；避免镜面塑料和高饱和霓虹。
- 角色：默认 AI 为旧 demo 的粉发女性角色，仅代表 M1 默认陪玩形象，不代表玩家，也不绑定外部角色档案。
- 文案仍以高对比文字承载；图片只提供框体、氛围和状态，不把任务内容、分数或操作提示烘焙进图。

## 4. 接入规则

1. S6 前先建立 `public/games/game-105/art/index.json` 与逐项台账；每一行必须有真实 `skinKey` 消费槽、来源、许可证/owner 授权、缩略图、状态和替换路径。
2. 旧 demo 图片先复制或转码到 game-105 的正式美术根，再从 `skinMap`/索引解析；禁止游戏代码读取旧 demo 的绝对路径。
3. 每个视觉槽都必须保留程序化回退：资源缺失、未审核或加载失败时，游戏仍能完整游玩。
4. 图片接入只能改变材质、贴图、皮肤或装饰；不得改蓝图实体数量、LayoutNode 结构、命中区域、碰撞体、镜头或规则数据。
5. 旧 demo 的所有“惩罚”命名只在 provenance 保存原文件名；玩家界面一律使用“互动卡”“余波卡”“收尾卡”。

## 5. 施工顺序

1. 程序建立所有 A/B 项的 `skinKey` 与加载回退，先运行台账审计，确保零孤儿行。
2. 美术/程序将 A01--A14 逐项登记、缩放和接入；每项在平台中标记来源与审核状态。
3. 补做 B01--B03，并以同一风格锚登记；程序化 SVG 也必须进入索引。
4. 在开局、玩家卡、AI 观察、余波、AI 收尾和重开六个状态进行桌面/窄屏截图走查。
5. 美术平台逐行复核所有已接入项；未审核资源不能覆盖当前程序化回退。

## 6. S6 验收

1. A01--A14 与 B01--B03 全部有真实消费槽、来源记录、可见缩略图和审核状态；`ledger:audit --strict game-105` 零孤儿。
2. 背景、桌面、四频道积木、AI 状态、心动账、卡框、按钮和收尾横幅均在真实游戏画面中可见，并可从索引替换。
3. 积木材质替换后，54 块物理布局、碰撞盒、抽离与倒塌测试完全不变。
4. UI 正文、按钮与输入框在桌面和窄屏下仍达到 S5 可读性要求；无稳定度、风险率、成功率或 AI 思考进度。
5. `banner-win/lose/warn`、稳定度条、思考条、货币与长期记忆图标未被接入当前游戏。
6. 完成美术平台逐行复核后，S6 人门自动闭合；再运行 S7 评分卡，不在 S6 阶段改玩法。

## 7. 后续扩展，不纳入 S6

- 多角色 AI 皮肤包、玩家自定义角色、外部陪伴系统角色注入。
- 运行时 LLM 头像/立绘生成。
- 长期记忆、信件、唱片或货币等玩法资产。
- 对 UI 结构、卡牌规则、AI 策略或物理模型的修改。
