# game-105 S4：Standalone Release M1 玩法闭环施工单

> GD-105 · 2026-09-02 · 以 `standalone-release-freeze.md` 为最高优先级。前置：本版 S2 独立复查与 owner 签核、S3 本地游戏骨架通过。`gdd.md`、本文件、`s4-experience-extension.md`、`acceptance/` 是本版 S4 的唯一策划验收输入。

## 1. 完成定义

玩家能直接启动 game-105，与默认本地 AI 完成一局真物理叠叠塔。玩家与 AI 均可抽取和结算；AI 主卡、余波卡和 AI 倒塔惩罚卡均显示卡面并只生成一次本地模板回复。游戏结束显示游戏内结算。

本地模板是本版唯一文本来源；无 Host、无网络、无模型凭据时物理与结算仍完整可玩。未来 Host 接缝可保留，但不得被调用或成为本版启动、回合或结算条件。

## 2. 必做范围

1. 保持既有真物理、实时倒塌、连带抽取、余波、退役积木、战利品、玩家输入与重开清理规则。
2. AI 每张主卡/余波卡：可见卡面 -> pending 状态 -> 一次回复 -> 显示回复 -> 下一张/玩家回合。
3. AI 倒塔：确定性选择一张安全收尾卡 -> pending -> 一次回复或模板 -> 仅一次确认收尾。
4. 若保留 Host adapter，它必须默认禁用，且游戏不含模型密钥、模型选择或 `apps.launch`。
5. 游戏内结算只显示本局白名单信息并排除玩家自由输入；外部结果投影与去重属于 M2。

## 3. 禁止项

- 禁止模型选择积木、改变物理/倒塌、卡牌、心动值、胜负或记忆候选规则。
- 禁止把确定性模板记为真实模型成功证据。
- 禁止在本版发起模型请求，或让任何保留接缝的晚到回调在重开/卸载后写入任何局。
- 禁止为新卡牌状态移动 S5 已冻结的结构布局；只能使用既有互动卡区域、等待态和确认层。
- 禁止游戏写长期记忆、关系档案或聊天历史。

## 4. 程序交付与证据

1. 为 AI 主卡、余波、惩罚卡的本地模板、顺序、单次显示、重开与重复信号补回归。
2. 验证模板文本不能改变物理、抽取顺序、卡牌、心动值、胜负或种子确定性。
3. 验证无 Host、无网络、无模型凭据时可启动、完整游玩、重开与结算。
4. 真 SDK Host witness 和真实模型 witness 作为 M2 历史/未来证据保留，不是本版 S4 条件。
5. 完整运行 GD 签名剧本、S4 gate、类型检查、浏览器渲染/点击探针和递归故障注入。递归 JSON 必须 `ok:true` 且包含全部声明的注入数；不完整结果不得在自证中写“通过”。
6. 程序重写 `s3-program-evidence.md`、`s4-program-evidence.md` 以如实覆盖本版范围；历史自证不得覆盖。
