S1 简报 §配方数据模型要求同一材料可重复，托盘按稳定 ID 显示剩余份数；S1-P-06 原型用 `counts[id]` 显示份数、归零后禁用该材料。此项属于 S4 交互结构，不以 S5 美术延期代替。

## 现有能力与实证

- 2026-10-13 运行 `npx vite-node scripts/dump-capability-catalog.mjs --only t2-ordered-action-session,t2-effect-apply,t2-event-when,t2-self-rule,t2-keybind,t2-drag-place`，结合 `docs/playbooks/events-logic.md`、`docs/playbooks/pick-list.md` 实查。共享工作树有大量并行未提交改动，未执行会改写现场的 `git pull`。
- G1 `OrderedActionSession` 按步骤接受并**移除**匹配的 `Signal`，只在终局发 success/failure；没有每步确认后的具名信号或可供 Effect 过滤的接受事件。`Effect` 在 G1 后执行，因信号已移除，不会扣 `Resource`。曾把两份材料初始为 2、尝试 `Effect{onSignal:'brew.add.moon-herb',kind:'modify-resource',value:-1}`，定向测试实测第一次正确投料后仍为 2（expected 1），故撤掉未生效组合。
- `EventWhen(Resource≤0)` + `Effect(destroy)` 表面可组成归零移除，但 `EventWhen` 在 Update 统一清理旧 `Signal`；G2 `AngularGesture` 在 Input 已发出的整圈信号被清掉。真实 Edge 回放：完成第一步后，鼠标沿椭圆一圈，`confirmedCount` 仍为 0、无浏览器错误。改用 `SelfRule(Resource≤0 → destroy)` 避开清扫后，整圈回放恢复通过，但前述 G1 消费信号仍使库存不扣。
- `KeyBinding.when` 可按 Resource 阻止耗尽的键盘动作；`Draggable.onlyFlag` 对锅口投放按 G3 设计绕过，不能把库存直接套在拖拽门上。游戏 UI 派生 `stepIndex` 可显示数字，但无法可靠阻止世界内已耗尽实体继续投料；这会造成外观和权威判定分叉。
- 已撤回上述失败组合，保持 5/5 验收剧本、14/14 定向单测、12 张真浏览器序列的可玩基线；材料份数仍是显式未实现项，不宣称 S4 收敛。
