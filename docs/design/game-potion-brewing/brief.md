# `game-potion-brewing`《坩埚炼药》立项简报

> S1-P-06 HTML 原型已获 Owner 于 2026-10-12 在本会话确认定稿并通过独立关键路径复查；项目控制台 S1 Owner 人门已通过。当前处于 S2 能力计划与合同草案评审，正式游戏尚未开工。

## 一句话玩法

DokiWorld 为本局指定唯一要炼制的物品及公开配方；玩家直接进入炼药台，严格按照配方顺序把材料投入坩埚，并在指定步骤按正确方向完成搅拌，全部步骤正确即成功，任何明确错误动作立即失败。

## 产品定位

- 类型：独立、短局、无随机、无时限的手工炼药小游戏。
- 宿主：DokiWorld。
- 体验目标：用少量操作表现“亲手按配方炼成药剂”的仪式感，而不是做复杂模拟器。
- 首版逻辑画布：1440×900。
- 首版操作：拖拽 / 触控为主，必须提供键盘等价操作。
- 参考方向：借鉴手工炼药台的仪式感与《Potion Craft》的触感反馈，但不复制任何游戏的素材、界面、配方或专有名词。

## 已冻结的玩法范围

首版只有两种权威步骤：

1. `add`：投入指定材料；
2. `stir`：按指定方向搅拌指定有效圈数。

明确不加入研钵研磨、火候控制、计时沙漏、蒸馏、装瓶或品质评分。

## 一局流程

1. 宿主传入本局唯一指定的配方、目标成品图、材料和完整步骤；游戏不提供配方选择。
2. 输入有效后直接进入炼制台，初始坩埚装清水，搅拌棒已没入水中。
3. 配方卷轴始终公开显示，当前步骤高亮，已完成步骤盖章或划除。
4. `add`：玩家把正确材料拖入坩埚；成功后材料溶解、药液变化并推进步骤。
5. `stir`：玩家握住搅拌棒，沿指定方向完成要求圈数；每个有效圈即时反馈并推进圈数。
6. 全部步骤完成后，坩埚产生稳定的成功演出并返回成功结果。
7. 玩家提交错误材料或形成明确的反向有效搅拌圈，立即进入失败演出并返回失败结果。

## 错误判定边界

- 拖拽未进入坩埚有效区域：材料弹回，不失败。
- 点错材料但尚未投入：不失败。
- 投入的材料 ID 与当前 `add` 步骤不符：立即失败。
- 搅拌轨迹过短、抖动或未形成完整圈：忽略，不失败；棒尖始终受角度轨道约束，不会离开锅中。
- 形成与当前 `stir.direction` 相反的一个完整有效圈：立即失败。
- 当前不是 `stir` 步骤却在坩埚中形成完整搅拌圈：立即失败。
- 当前不是 `add` 步骤却提交材料：立即失败。
- 达到要求圈数时步骤立即锁定并自动前进，避免多划半圈被误判。
- 失败后所有玩法输入禁用，只允许确认结果或按宿主退出流程离开。

## 配方数据模型草案

每个配方只包含闭集数据：

- 稳定 `recipeId`；
- 配方名称与成品 render-only 图片；
- 本配方可用材料表：稳定 `ingredientId`、名称、render-only 图片；
- 有序步骤数组：
  - `{ kind: "add", ingredientId }`
  - `{ kind: "stir", direction: "clockwise" | "counterclockwise", turns: 1 | 2 | 3 }`

同一种材料可以在配方中重复出现；材料托盘必须用稳定 ID 与剩余份数表示，不能按图片或数组位置判定。

字段长度、数组上限、图片 URL 策略、合同名和版本将在 S2 对最新版 SDK 与 parser 约束实查后冻结。

## 初步 DokiWorld 权威边界

### 宿主预计传入

- 本次调用的稳定 `brewingId`；
- 本局唯一指定的完整公开配方；
- 该配方所需材料的展示信息与步骤；
- 可选的场景标题或叙事说明，仅作展示。

### App 预计返回

- `brewingId`；
- 宿主指定的 `recipeId`（仅作结果对账，不是玩家选择）；
- `outcome: "success" | "failure"`。

首版不向宿主返回品质、分数、用时、错误材料、内部手势轨迹或动画阶段。

### 明确不归 App

- 不扣除 DokiWorld 背包材料；宿主在调用前或成功后自行进行幂等结算。
- 不发放药剂、不写任务、剧情、成就、存档或数据库。
- 不自行扩展配方、替换材料或随机决定成品。
- 输入图片只影响显示，加载失败不得改变材料和步骤判定。

## 终局语义

- `completed + success`：全部步骤按顺序完成。
- `completed + failure`：玩家明确提交错误材料或明确完成错误方向的有效搅拌圈。
- `cancelled`：关闭、返回、主动退出、非法输入、资源或 SDK 技术错误；不是业务失败。
- 每局最多一次成功的 `complete()`，被拒绝时保留终局并允许诊断或重试同一结果。

## S1-P HTML 原型范围

原型必须是单文件 `docs/design/game-potion-brewing/prototype.dc.html`，固定 1440×900，并至少提供两份原创占位配方作为**互斥宿主样例**；玩家常态画面只接收其中一份，不能选方：

### 配方 A：月露安神剂

1. 加入月露草；
2. 顺时针搅拌 2 圈；
3. 加入银叶；
4. 逆时针搅拌 1 圈。

### 配方 B：赤焰醒神剂

1. 加入赤莓；
2. 加入火椒籽；
3. 逆时针搅拌 2 圈；
4. 加入晨光花瓣；
5. 顺时针搅拌 1 圈。

原型至少覆盖：直接进入炼药台的默认态、材料悬停 / 拿起 / 回弹 / 正确投入 / 错误投入、搅拌待机 / 有效圈 / 无效轨迹 / 反向失败、步骤推进、成功、失败、退出确认与 reduced-motion。第二份占位配方仅在隐藏审阅控制中切换，用来验证同一布局的数据适配。

## 初步画面方向

- 视角：略微俯视的坩埚，中央大型坩埚是绝对视觉主体；游戏画布背景透明，不带桌面或背景图片。
- 左侧：展开的配方卷轴，完整步骤全部可读，当前步骤有强高亮。
- 右侧：材料架或托盘，使用有形的植物、种子、晶体和瓶装粉末，而不是纯文字按钮。
- 中央：药液颜色、旋涡、气泡、光点和蒸汽随正确步骤逐渐丰富。
- 搅拌：搅拌棒初始在锅中，棒尖只由一个角度决定并沿椭圆轨道运动；水面与前侧锅沿遮挡入水段，有方向轨迹与圈数反馈。
- 成功：药液稳定发光、符文环收束、成品徽记升起；不额外要求装瓶操作。
- 失败：药液迅速变为浑浊紫色，锅身、锅沿与锅脚保持静止；演出保持短促，不拖延结果。

## 首版包含

- 一份宿主指定的公开配方，直接进入炼制；
- 有序 `add / stir` 步骤；
- 正确步骤、明确错误与唯一终局；
- 鼠标、触控、键盘可达；
- 成功 / 失败 / 取消语义；
- DokiWorld 严格合同、调用说明、资产闭包与 dist 交付。

## 首版不包含

- 研磨、切割、称量、火候、计时、蒸馏、装瓶；
- 隐藏配方、材料属性推理、自由实验或随机副作用；
- 品质、星级、用时奖励、连击、排行榜或难度等级；
- 宿主背包写入、材料扣除、奖励发放和数据库操作；
- 多锅并行、生产流水线或经营系统；
- 复制现有作品的美术、音频、配方与 UI。
