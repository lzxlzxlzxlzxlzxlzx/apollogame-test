### GAP-POTION-04 / G4 · 通用拖动预览施工规格

- 施工主体：待共享输入/2D 渲染线领工与主程 review；暂定能力名 `t2-drag-preview`，并非已注册 API。默认关闭，只有配置了预览槽的 Draggable 才生成表现影像。原材料实体位置与 G1 判定始终是唯一权威；预览不建第二份可点击/可投放实体。
- 输入与输出：复用 `PointerInputSource` 已有的 down/move/up 世界坐标采集，但**现有代码没有** `pointercancel` 监听或 `pointerId` 活跃指针守卫（见 `queued-input.ts:65-107`）；A 能力需在默认关闭的预览 opt-in 路径补 `pointercancel`/`lostpointercapture`/失焦清理，记录单个活跃 `pointerId` 并拒收第二指针，不能把它们写成已具备功能。渲染端用稳定 `Sprite.textureKey`/`Frame`/`Color` 槽画跟手影像。结束时调用 G3 新抽出的**同一共享纯命中判定**，读只读 zone 结果：合法投放消隐，锅外按固定 280ms ease-out 回起点；权威结果仍以 `drop-zone` 的 Signal 为准，预览不得自行提交或改写世界。此输入只影响视觉，不向 G1 发送额外玩法动作。
- 边界：不从 URL/图片 alpha 反推材料 ID，不用游戏级自由 DOM/CSS/Canvas，不以墙钟或裸随机影响规则；预览态不得进入 World 快照/hash 或宿主输出。指针取消、窗口失焦、资源加载失败和组件卸载必须清影像。reduced-motion 时保留落点/结果反馈但取消大位移。
- 点名验收：桌面鼠标、真实触控、不同 DPR/画布缩放、两个材料的并发拒收、按下不动/短距离松手、锅外回弹与锅口消隐、pointercancel/离窗/unmount、资源失败 fallback；原材料 Transform 与快照/hash 从头到尾不因预览变化；默认不开能力的旧拖拽游戏逐字节回归。锚点撤修验红、无新增系统环告警、非施工者独立复查后才可从 `accepted` 改 `delivered`。

- 输入：严格闭集 `steps`，每步有完整具名 `expectedAction` 与有界 `requiredCount`；本游戏投料用 `brew.add.<ingredientId>`，搅拌用 `brew.stir.clockwise|counterclockwise`。配方全量材料 ID 在启动适配器校验后映射为动作名，不含 URL/显示色/任意回调。现有 DropZone 的 `Signal` **没有** `arg`，仅透传 `Clickable.action` 和被拖实体 `source`；G1 匹配动作全名，不假设能读到材料参数。稳定 ID 只来自合同数据，不依赖 UI 文案或图片。
- 行为：只消费本会话声明的 `brew.add.*`/`brew.stir.*` 玩法动作；其它 UI 信号不等于错误。按单 tick 有序处理；未形成动作的短弧/锅外释放不进入会话。匹配时增步或圈数，最后一步立即锁定并只发一次 `success`；已提交但不匹配时立即锁定并发一次 `failure`；终局后输入 `reject`。重复材料与同拍多动作要有明确全序及去重规则。不得因不同材质图片、动画时长或宿主 URL 改判。
- 可观测：只记步骤 index、已确认圈数、终局与必要有限状态；DebugTrace 按 decision/transition/reject/commit 每 system 每 tick ≤3 条；关闭真 no-op。给外部只读投影，不让 UI handler 写世界。

## S1-P-01：公开配方手工炼药台 Demo

### 1. 唯一目标

交付一份可离线直接打开的 1440×900 单文件 HTML Demo，验证“选择公开配方 → 按顺序投料 → 按方向搅拌 → 成功 / 明确错误立即失败”的完整交互与视觉节奏。它是 authoring-time 视觉真相，不是生产代码。

### 2. 文件范围

只允许创建或修改：

- `docs/design/game-potion-brewing/prototype.dc.html`
- `docs/design/game-potion-brewing/prototype-notes.md`
- `docs/design/game-potion-brewing/ui-refs/**`（仅原创占位和验收截图）

禁止修改 `games/**`、`src/**`、`public/games/**`、`dokiworld/**`、SDK、manifest、构建和发布脚本。

### 3. 必须实现的两份占位配方

严格使用 `brief.md` 中的“月露安神剂”和“赤焰醒神剂”。两份配方必须有明显不同的材料、药液主色与成功效果，但共用同一套炼药台和交互规则。

### 4. 必须覆盖的屏幕与状态

1. `recipe-select`：两张公开配方卡，能预览完整步骤并选择。
2. `bench-idle`：进入炼药台，配方卷轴全程展开，当前步骤醒目。
3. `ingredient-hover/focus`：材料名称、图形和剩余份数清晰。
4. `ingredient-drag`：材料跟手并有拾取高度 / 阴影反馈。
5. `ingredient-snapback`：未投入坩埚时自然回弹，不失败。
6. `ingredient-correct`：正确材料落入、溶解、药液变化、步骤推进。
7. `ingredient-wrong`：错误材料投入后立即锁定失败并播放短失败演出。
8. `stir-ready`：当前步骤显示方向和所需圈数，搅拌棒可操作。
9. `stir-valid`：完整有效圈逐圈确认；方向轨迹、圈数和药液旋涡同步。
10. `stir-invalid`：短轨迹 / 抖动被忽略并回到待机，不失败。
11. `stir-wrong-direction`：明确完成反向有效圈后立即失败。
12. `success`：最后步骤完成、成功演出和结果确认。
13. `failure`：失败原因用玩家可懂的简短语言显示，但不输出调试轨迹。
14. `exit-confirm`：主动退出确认，仅表达取消，不伪造失败。
15. `disabled`：提交、演出和终局期间其它输入可见禁用。

### 5. 输入细节

- 鼠标 / 触控：拖拽材料进入坩埚；拖动搅拌棒围绕中心画圈。
- 键盘：`Tab` 遍历配方、材料和按钮；`Enter/Space` 选择材料；选择后激活坩埚等价投入。搅拌步骤提供可聚焦的顺 / 逆时针操作入口，每次确认代表一个完整有效圈，用于无鼠标与辅助技术等价完成。
- `Escape`：关闭当前说明 / 结果弹层；炼制中打开退出确认。
- 点击材料本身不提交，只有投入坩埚或键盘确认坩埚才提交。
- 命中边界必须宽容；材料落在坩埚外沿但未进入有效内圈时应回弹，不能误杀。

### 6. 圆周手势原型口径

原型可用专用 JS 验证手感，但必须记录算法目标，且禁止复制进生产游戏：

- 以坩埚中心为基准累计角度变化；
- 进入有效半径后才开始累计；
- 单帧异常跳变、折返抖动和半径越界不计入有效角度；
- 累计同向角度达到约 300–360° 才确认一圈；
- 只有确认了完整反向圈才失败；
- 达到目标圈数立刻锁定并推进步骤。

具体阈值由原型真机手感调定并写入说明；S2 需重新判断由哪项通用能力承载。

### 7. 动画节奏

- 材料拾取：`100–160ms`；回弹：`220–320ms`。
- 正确投入：落入与药液反馈并行，总计 `450–750ms`；下一步骤高亮不能等所有装饰粒子结束。
- 每个有效搅拌圈：确认反馈 `120–200ms`，不打断连续搅拌。
- 成功：最后步骤提交后立即锁定结果；演出 `1.0–1.6s` 后显示结果确认。
- 失败：错误提交后立即锁定；演出 `0.7–1.1s` 后显示失败结果。
- reduced-motion：取消大位移、旋转光环和闪烁，保留步骤变化、结果与必要颜色 / 文本反馈。

### 8. 布局基线

- 固定 `1440×900`，窗口只等比缩放。
- 坩埚中心约位于 `(760,500)`，视觉高度约 `430–500px`。
- 配方卷轴位于左侧安全区，宽约 `330–390px`，五步配方也不能滚动才能看全。
- 材料架位于右侧，至少可清晰容纳 5 种材料；重复材料用份数表达。
- 当前步骤、方向与圈数不能只靠小字或颜色；需要图标、方向箭头和文本共同表达。
- 原型控制不得遮挡目标 UI。
