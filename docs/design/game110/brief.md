## 1. 一句话玩法

**把小说的关键时刻变成一局卡牌冲突**——用一套通用的行动卡语法（哭喊/逃跑/辩解/出示证物…）组合出招，
改写场景状态条，最终改写这一幕的结局。参照物：DokiWorld 概念图《红楼梦·宝玉挨打》示例局。

**不是选 A/B/C/D**，而是抽到一手有代入感的行动卡、组合打出、由规则引擎结算数值、再由 AI 演出剧情文本。

## 2. 概念图六格 → 本作要素（逐格转写·概念图=唯一需求原文）

| 格 | 概念图说什么 | 本作落成什么 |
|---|---|---|
| ① 关键时刻→卡牌冲突 | AI 识别小说中有戏剧性的场景，转成一个可玩 Encounter | 一局 = 一个 Encounter：场景状态条（贾政怒气 82 / 宝玉状况 36 / 家族声望 65 / 你的信任 47 / 暴露风险 12）+ 一组隐藏目标 |
| ② 三层卡牌体系 | 通用行为卡（白/蓝·约 30–50 张核心）· 情境衍生卡（紫·随剧情动态生成）· 剧情机会卡（金/稀有·条件满足才出现） | 三层 = 三个牌库分层；卡 = 纯数据目录（id·层·标签·文案·效果） |
| ③ 每回合抽一手牌 | 按场景/经历/状态动态抽 5 张 | 每回合抽 5 张；**首版为「进入 Encounter 时按场景预洗牌池」**（局中牌池可变性见 capability-plan 缺口 GAP-110-01） |
| ④ 打出卡牌·组合行动 | 可单张、可多张组合；**顺序可能影响结果** | 一次出 1–N 张；结算按出牌顺序逐张过（顺序敏感由 `index` 谓词表达） |
| ⑤ 规则引擎结算 + AI 剧情演出 | 规则引擎算数值与逻辑保证公平一致；AI 生成符合原著风格的剧情演出 | **规则=确定性 sim**（进 world/hash）；**AI 演出=表现层旁路**（走 DokiWorld 宿主 SDK `./dialogue`·绝不碰 world/snapshot/hash） |
| ⑥ 改变故事 | 人物关系/解读新卡/触发新事件/影响世界状态 | 终局产出 = 状态条终值 + 达成的目标 + 结局分支；上报宿主 `GameResult` |

## 3. 参考与风格意向

- **题材参考**：概念图示例局《红楼梦·宝玉挨打》——中式古典、宅门冲突、克制的戏剧张力。
- **视觉意向**：国风宫廷 + 卡牌质感。起手 house 主题 **`apolloBrocade`「锦霞」**（暖白锦缎 + 金/胭脂波点 + 玫瑰点睛·
  UI 手册原话适配「宫廷/女性向/**卡牌**」），配 `PlayingCard.faceArt` 整牌面插画 + 扇形手牌。
  三层卡的白蓝/紫/金色阶直接对应概念图的卡框配色。
- **反例**：朴素默认 UI（缺省 SHELL + 无成熟件）= 缺陷，PUI 复查可打回。

## 4. 目标玩家与一局时长

- 读过（或没读过）原著都能上手：卡面自带文案，不考记忆，考**取舍**。
- 一局 = 一个 Encounter，约 5–8 回合，3–5 分钟（DokiWorld Chat Game Host 的单局体量）。

## 5. 本作明确不做（首版边界）

- 不做跨 Encounter 的长线养成/牌组构筑（概念图⑥的「专属剧情线」属平台侧叙事，不在单局内）。
- 不做多人对战（单人 vs 场景，`launchRequirements.minPlayers` 待出包时按规范 §3 定）。
- 不在游戏层跑 LLM：AI 演出全部由宿主能力提供，拿不到就降级到纯数据模板文案（三形态降级铁律）。
