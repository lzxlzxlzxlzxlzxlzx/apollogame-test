# 《言弹交锋》GDD v0.1

本稿只固化已讨论的首局结构；卡牌数值、完整卡表和遭遇内容待后续需求制定。

## 局内状态

| 状态 | 含义 | 终局条件 |
| --- | --- | --- |
| `progress` | 玩家当前说服进度 | 达到 `victory.target`：胜利 |
| `pressure` | 玩家承受的交锋压力 | 达到 `pressureLimit`：失败 |
| `focus` | 本回合可用的出牌预算 | 回合开始按规则重置/补充 |
| `turn` | 当前回合序号 | 超过 `turnLimit` 且未胜利：失败 |

数值范围和初始值全部属于遭遇配置或游戏固定规则；不得散落在界面代码中。

## 言弹目录

言弹由游戏的内部、版本化目录定义。每张牌至少拥有：

```text
cardId / displayName / focusCost / artSlot / closedEffects[]
```

`closedEffects` 只能操作批准的局内资源或批准的条件，不承载宿主提供的自由文本逻辑或代码。宿主牌组是对这个目录的一个计数引用，例如：

```json
[{ "cardId": "observe", "copies": 2 }, { "cardId": "direct-question", "copies": 1 }]
```

未知 `cardId`、超过目录副本上限或与目录版本不兼容的牌组，均应在开局前拒绝。

## 对手意图

v1 对手没有自主决策：宿主传入与回合上限等长的有序意图列表，游戏逐回合展示并结算下一条。每条意图可使用与言弹一致的闭集效果词表，但只影响本局状态。若未来需要根据玩家状态选招、权重抽选或阶段换招，须另立 AI 设计与能力核查。

## 回合顺序

```text
开始回合 → 展示固定意图 → 玩家出言弹 → 结算言弹效果
→ 立即检查胜利 → 结算意图 → 检查失败/回合上限 → 抽牌 → 下一回合
```

胜利检查先于本回合意图结算：达到目标时游戏立即结束，符合“胜利后交由 DokiWorlds 接管”的边界。

## 画面与嵌入

游戏展示宿主授权的背景图与对手立绘，但它们不影响规则。卡牌视觉由游戏目录拥有。所有 HUD、手牌、提示和终局界面必须走现有 LayoutNode UI；对手立绘、背景和局内受击/提示等非 UI 画面走渲染组件与资产消费槽。

## 验收口径（首个可玩版）

给定同一经过验证的 input 和随机种子：

1. 每一次抽牌和每一步状态变化完全一致。
2. 玩家能看见当前意图、进度、压力、专注、手牌与可用操作。
3. 达成目标立即返回 `win`；失败线或回合上限触发立即返回 `loss`。
4. 小游戏不会写入奖励、长期牌组或宿主进度。
