# 《言弹交锋》demo 对齐圣经 v1

## 0. 本文用途

本文是 UI、美术、特效和验收共用的**第一交付基准**。当前内部迁移只证明玩法可运行，不得把迁移后的简化界面当成最终设计。迁移结束后的第一个可交付版本必须先复现 `fanren_qiyuan` demo 的画面结构、卡牌样式、信息层级和演出节拍，再讨论原创换皮或额外增强。

“与 demo 一样”在本项目中的可执行含义是：

1. 相同状态下，信息出现的位置、层级、尺寸关系和显隐关系一致；
2. 相同操作后，阶段顺序、停顿点、位移方向和数值反馈一致；
3. 卡牌的框体、费用徽记、插图区、名称、来源、效果文案和快捷键位置一致；
4. 背景、立绘和卡图若已确认可授权复用，则按资产流程导入；未确认时用自有素材复刻同构图与同明暗关系；
5. 不复制 demo 的 React/CSS 代码。ApolloGame 侧仍以 LayoutNode、render component、timeline、tween、VisualEffect 和资产 key 数据化表达。

首轮对齐不要求复制 DokiWorld 大世界外壳、对话页或视频播放器控件，只复现进入交锋后的全屏牌局和从对话切入牌局的镜头过渡。

## 3. 桌面画面结构

画面为全屏 16:9 优先、深色古铜墨风格。布局不使用传统“上栏 + 中栏 + 下栏”盒式面板，而是五个浮层压在同一背景和敌人立绘上。

| 区域 | demo 几何基准 | 内容与层级 |
| --- | --- | --- |
| 全屏背景 | `inset: 0`；冲突时向右平移 7%、放大 1.16 | 演武场铺满；亮度/饱和降低，暗角覆盖；不能露出默认纯色空白 |
| 左上交锋记录 | `top: 7%`、`left: 4%`、`width: 38%`、`height: 50%` | 标题、回合、金色分隔线、最近三条反馈、当前意图 |
| 中右敌人 | frame `left: 41%`、`width: 33%`、`top: 7%`、`bottom: 0` | 立绘宽约 48vw、高 93vh，保留肩部和全身轮廓；不能与右侧指标列重叠 |
| 右上敌人信息 | `top: 6%`、`right: 3%`、`width: 21%` | 名称、身份、遭遇目标、进度数字与横条 |
| 底部牌桌 | 高度 `cardHeight + 62px`，左右 padding 3% | 左为压力/专注，中为手牌，右为牌库与命令 |

冲突层本身从左到右有 `rgba(3,5,8,.65) → rgba(3,5,8,.08)` 的透明暗幕；底部另有从透明到 `#06080aef` 的压暗渐变。场景暗角沿用：中心 27% 基本透明，边缘逐渐压到深黑，顶部与底部再叠一层纵向遮罩。

### 3.1 信息显隐规则

- 交锋开启后，原 conversation、角色 roster、overture bubble 和其他大世界控件全部隐藏。
- 背景和暗角必须保留，并扩展到全宽；不能在牌局上继续显示平台侧栏。
- `camera` 阶段牌局子节点全部隐藏，只让原对话画面横向退出。
- `reveal` 才出现敌人、HUD 和交锋信息；`draw` 才出现起始手牌。
- 终局后底部牌桌替换为左下结果区，背景与敌人仍保留，不能立刻切黑或跳回宿主。

## 5. 卡牌样式逐项规格

桌面卡牌尺寸为：宽 `clamp(108px, 9.75vw, 142.5px)`，高 `clamp(165px, 22.5vh, 250px)`；源 E2E 在 1280×720 下要求宽不超过 128px、高不超过 172px。矮屏降为 112×150；窄屏为 108.75×216 并横向滚动。

从上到下的卡面结构固定如下：

1. 左上费用圆章：23×23，深褐底、浅金字、1px 金边；
2. 插图区：卡高约 33%，底部一条细分隔线，透明单色线描 SVG 居中 contain；
3. 卡名：13px、居中、深墨色；
4. 来源：10px，显示“基础/能力/技能/道具/证据/关系/情境”；
5. 效果正文：11px、行高 1.4；
6. 条件/奖励说明：9px；
7. 右下快捷键：9px、半透明。

卡框：5px 小圆角，米黄纸面径向渐变 `#eee1c2 → #c8b48e`，外部下投影与内部褐色旧纸晕染并存。hover 只上移 3px，不放大。动画期间卡牌不降透明度；已飞出的原位置隐藏并由飞行投影替代。

## 6. 动画状态机与精确节拍

所有动画表现的是已经提交的结果；动画不能发牌、改资源、决定胜负或改变随机序列。`ready` 是唯一允许玩家继续输入的阶段。

### 6.1 入场，总时长 1740ms

| 时间 | phase | 画面 |
| ---: | --- | --- |
| 0–700ms | `camera` | 原对话整体向右退出；背景向右 7% 并放大至 1.16；牌局 UI 隐藏 |
| 700–1040ms | `reveal` | 立绘先以 200ms 淡入；其他 HUD/文本以 340ms 从下方 8px 淡入 |
| 1040–1740ms | `draw` | 起始手牌从右侧小牌库位置飞入；单张 450ms，相邻牌延迟 60ms |
| 1740ms | `ready` | 第一张可用卡获得焦点，玩家可操作 |

抽牌路径起点：牌库中心；起始状态 `scale(.35) rotate(16deg)`、opacity 0，落位时回到 `scale(1) rotate(0)`、opacity 1；缓动 `cubic-bezier(.2,.75,.25,1)`。

### 6.2 出牌，总时长 1060ms

| 时间 | phase | 画面 |
| ---: | --- | --- |
| 0–320ms | `play` | 被选卡以投影从原位飞至舞台约 `(38%,31%)`，放大 1.12，旋转 -5°；原手牌位置隐藏 |
| 320–700ms | `impact` | 已提交资源值才显示；进度/压力飘字向上，敌人向右 9px 并轻旋 .6°、亮度提升 |
| 700–1060ms | `response` | 敌人向上 3px 做短回应，左上新增反馈淡入 |
| 1060ms | `ready` | 手牌收拢完成，恢复输入 |

### 6.3 结束回合，总时长 2260ms

| 时间 | phase | 画面和快照要求 |
| ---: | --- | --- |
| 0–380ms | `round-end` | 显示“回合结束”，仍保持旧压力、旧专注和旧手牌 |
| 380–880ms | `enemy` | 当前意图转危险色并发光；敌人向左 16px、scale 1.025、亮度提升 |
| 880–1220ms | `impact` | 压力变化出现；仍保持旧专注、旧手牌 |
| 1220–1560ms | `round-start` | 显示“第 N 回合·专注恢复”；专注圆点从 .6 放大到 1.3 后回正并发光 |
| 1560–2260ms | `draw` | 只给新增卡播放 450ms/张、间隔 60ms 的发牌动画 |
| 2260ms | `ready` | 新回合完整快照可操作 |

### 6.4 关键反馈

- 敌人行动：500ms，40% 处达到向左 16px、1.025 倍和 1.12 亮度；结束回正。
- 敌人受击：380ms，30% 处向右 9px、旋转 .6°、亮度 1.18；结束回正。
- 敌人回应：360ms，50% 处上移 3px；结束回正。
- 数值飘字：380ms，从下方 12px、scale .9、opacity 0 到上方 12px、scale 1、opacity .85。
- 指标闪烁：380ms，中点亮度 1.6。
- 手牌 hover：180ms 上移 3px。
- reduced-motion：取消所有动画和 transition，立即显示权威终态；功能和文本反馈不减配。

## 7. UI、特效、美术和音频的责任切分

| 内容 | 生产线 | ApolloGame 表达方式 |
| --- | --- | --- |
| 标题、回合、意图、日志、进度/压力/专注、手牌、按钮、结果面板 | UI | LayoutNode 闭集；写世界仅发具名 action |
| 背景、敌人立绘、卡牌飞行投影、数值飘字、受击/压迫反馈 | FX/play-field | render component + t1-tween + VisualEffect |
| 进入、出牌、回合、终局的时序 | Events | 只读 transition 驱动的 timeline/cue |
| 背景、立绘、卡图文件与 key | Art/Assets | skinKey → skinMap → asset index；由 asset-manager 导入 |
| demo 对齐版音频 | Audio | 无；保持静音 |
| 后续增强音效 | Audio | 经批准后用 SfxSpec + SynthAudioPort，不能直接写 AudioContext |

卡牌本体属于 UI 交互节点；飞离手牌后的只读投影属于 play-field。两者必须共享同一份卡面数据和皮肤 key，不能画出两套外观。

## 8. 终局和异常状态

### 8.1 终局

- 最后一张牌的 `play → impact → response` 必须先播完，再出现结果。
- 结果区在左下/左中，宽约 38%，有顶部金线、标题、结算说明和唯一确认按钮。
- 内部游戏版按钮文案改为“结束对局”或当前内部出口语义；不可继续沿用 demo 的“继续交谈”造成宿主职责混淆。
- 确认只关闭/上报已经结算的结果，不得再次结算。

### 8.2 必须可见的异常/降级

- 图片加载失败：背景降级为古铜墨渐层，敌人降级为剪影/徽记，牌局仍可完成。
- 卡牌不可用：保留完整卡面，明确显示费用不足等原因；不得只让点击无反应。
- 窄屏：横向压力条保留；卡牌直立并横向滚动；两个命令按钮占底部一行。
- 恢复存档/重新挂载：直接进入 `ready` 或终局，不重播已经提交的动画。
- 重复点击：一次命令只提交一次；动画忙碌期焦点停在舞台，结束后回到首个可用操作。

## 9. 真渲染证据矩阵

程序不得仅以单元测试或“看起来差不多”宣布对齐。至少在桌面基准视口和窄屏各保存一套真渲染证据。

### 9.1 桌面关键帧

1. `D01-camera`：对话正在向右退出，交锋 UI 尚未显示；
2. `D02-reveal`：背景、立绘、左右信息列出现，手牌仍为空；
3. `D03-opening-ready`：五区布局完整，起始手牌发完；
4. `D04-card-hover`：卡牌只上移 3px，信息不被裁切；
5. `D05-card-flight`：卡牌飞向中央，原位隐藏；
6. `D06-progress-impact`：金色进度飘字、敌人受击、右上进度条同步；
7. `D07-pressure-impact`：危险色压力飘字与指标闪烁；
8. `D08-enemy-intent`：意图先高亮，敌人向玩家侧压迫；
9. `D09-focus-refresh`：新回合专注点恢复、旧手牌仍稳定；
10. `D10-deal-new`：仅新抽到的牌从牌库飞入；
11. `D11-victory`：最终冲击结束后的胜利结果；
12. `D12-loss`：压力或回合失败结果；
13. `D13-fallback`：背景或立绘加载失败仍构图完整；
14. `D14-reduced-motion`：同一状态无位移动画但信息完全一致。

### 9.2 窄屏关键帧

- `M01-ready`：390×844，横向压力条、直立卡牌、横滚手牌和底部双按钮均在视口内；
- `M02-result`：结果文本与唯一出口不被裁切；
- `M03-keyboard-focus`：焦点环可见且不改变布局。

### 9.3 验收方式

- 在相同玩法快照上同时截 demo 与 ApolloGame；使用叠图/差分图检查，而不是凭记忆比较。
- 几何对齐先于美术精度：先消除布局、比例、遮挡和显隐差异，再评颜色、材质和细节。
- 动画用阶段序列截图或短录屏验收；静态终帧正确但阶段缺失，仍判失败。
- 每项差异登记为 `✅ 对齐`、`❌ 未对齐` 或 `⚠ 经 owner 裁决的有意差异`；`❌` 归零前不得宣布第一交付完成。

## 11. 首轮明确不做

- 不为“更华丽”改变 demo 的结构、配色和节拍；先完成一比一对齐。
- 不先画三名原创敌人的全套正式资产；先用一个遭遇把对齐管线跑通，再换皮复用。

- 不用音效掩盖画面反馈不足。
- 不把 demo 的 React、CSS、计时器或 URL 路径直接搬进游戏层。
- 不因当前简化迁移版“能玩”而降低第一视觉交付标准。
