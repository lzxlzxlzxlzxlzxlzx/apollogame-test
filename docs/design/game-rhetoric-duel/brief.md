# 《言弹交锋》立项简报

- 游戏槽位：`game-rhetoric-duel`
- 阶段：S1｜概念与边界冻结（草案）
- 参考：`fanren_qiyuan` 的 conflict demo 只用于理解“意图可见、出言弹推进说服进度”的交互结构；本项目不复制其人物、美术、文本、YAML schema 或实现代码。

## 一句话

玩家在一场可预告对手意图的言语交锋中，从手牌打出预设“言弹”推进说服进度，同时把压力控制在失败线以下；达到胜利条件即结束并把胜负交回 DokiWorlds。

## 核心体验

每回合先看到对方下一步施压意图，再在有限手牌、专注与压力之间作判断：是抢进度、稳住局面，还是为下一回合铺垫。它借用爬塔卡牌战斗的“可预判风险 + 小手牌决策”张力，但战斗语义是辩论、说服与反击。

## 已冻结的产品边界

1. **宿主与小游戏分工**：DokiWorlds 负责发起遭遇、保存玩家卡组、奖励、地图/后续剧情与胜利后的跳转；小游戏只运行一场遭遇。
2. **结束语义**：满足胜利条件立即结束；压力达到失败条件或回合限制耗尽立即结束。小游戏不展示或处理局外奖励。
3. **卡牌所有权**：本游戏拥有唯一的言弹卡牌目录、名称、效果、费用、视觉与平衡。宿主只传玩家拥有的 `cardId + copies`，不得传卡牌功能或自由脚本。
4. **遭遇所有权**：宿主传胜利条件、规则数值、对手意图序列、对手立绘及背景图的受授权引用；小游戏只将它们解释为本局配置。
5. **返回结果**：v1 只向宿主返回标准化的 `win`、`loss`（生命周期主动退出为 `exited`），不回传奖励、道具、存档或牌组变更。
6. **确定性**：宿主提供本局种子；抽牌和任何后续随机分支必须可复现，不能使用 `Math.random()`。

## 首局循环（v1）

1. 宿主传入已验证的遭遇配置与玩家牌组引用。
2. 游戏按种子洗牌、抽取起始手牌，展示本回合对手意图。
3. 玩家在专注限制内打出言弹；言弹的固定、闭集效果改写进度、压力或专注等资源。
4. 结算该回合意图，检查胜负；未结束则抽牌进入下一回合。
5. 终局立刻通过 DokiWorlds SDK 返回标准结果，小游戏会话结束。

## v1 明确不做

- 宿主传入任意卡牌说明、效果表达式、JS、HTML 或图片以外的可执行内容。
- 小游戏内的奖励、卡牌获得/移除、长期存档、剧情地图与关外养成。
- 自适应敌人 AI。v1 的意图是宿主给出的完整顺序脚本，长度至少覆盖回合上限；它不是由游戏临场选择的策略。
- 未经授权的外部素材下载；传入图片仅作展示，加载失败必须使用游戏内后备视觉。

## Demo 参照边界

demo 是**体验参照**，不是实现规范。首个可玩版应验证以下可观察交互：对手下一意图可见、玩家能从手牌选择言弹、进度/压力/专注可读、终局立即结束。除此之外，界面构图、美术风格、角色、卡名、数值、数据结构和程序架构均以本项目 GDD 与引擎能力为准；不得复制 demo 源码或以其游戏专属结算器作为实现模板。

## 已裁决的能力路径

owner 已选择路径 A：补一个可复用的通用声明式卡牌效果能力。“言弹卡牌 ID 如何以纯数据映射到闭集资源效果”的实查、范围与验收见 [capability-plan.md](capability-plan.md#capgap-rhetoric-001)。该能力完成并独立复查前，本游戏不进入局内规则程序实现。
