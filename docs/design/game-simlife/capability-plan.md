# game-simlife capability plan

## Purpose

`game-simlife` is a playable Little Valley acceptance entry for the Life simulation engine. It is an integration demo, not a second game rules implementation. The world now has a 36×26 continuous outdoor valley plus a separately authored 36×26 mine interior; each scene owns independent RLE terrain/collision, zones, placements, spawns and warps rather than behaving as a chain of test rooms.

## Data and interpretation

Rules are one raw JSON `LifeGamePackage`: terrain RLE, zones, items, crops, placements, dialogue graph, warps, calendar slots, complete optional NPC placement schedules, optional continuous-movement speed, package-default/per-placement Manhattan interaction ranges, a closed dialogue-session policy, a strict grid-unit camera declaration, and optional opaque visual keys are author data. Little Valley authors `movement.speed: 0.3` grid units per simulation tick; this is game tuning consumed unchanged by the shared normalized, collision-safe continuous-motion interpreter, not a capability default. `games/game-simlife/little-valley.life.json` is the sole package source; the TypeScript edge only gives that imported JSON the protocol type before the existing strict validator/compiler consumes it. `Transform` is the continuous player position authority; scheduled NPC `LifePlacement` is the same-tick interaction/render projection and is committed to NPC `Transform` plus `LifePosition` before the tick completes. `interaction.dialogueSessionPolicy` is closed to `persistent|proximity`: omission preserves legacy persistent sessions, while Little Valley explicitly selects `proximity`. In proximity mode, `t2-life-talk` reads the same-tick `LifeActivityContext.nearbyPlacementIds` already derived from the package-default/per-placement `interactionRange` and deterministically destroys an open session as soon as its target leaves that set; re-entry plus a fresh queued talk action opens a new session. `t2-life-talk` still accepts queued `life.dialogue.close` only when the current authored node is a terminal line (`next:null`). Life camera viewport, margin and target offsets remain in cell units until the existing renderer converts them once to pixels; its optional dead-zone edges are dimensionless screen ratios. `t2-camera-follow` retains the prior camera center while the AABB-midpoint-plus-offset focus is inside the zone, corrects exceeded axes independently after the existing fit-zoom calculation, and applies scene Bounds last. Omission preserves centered following exactly. Generic `Camera` keeps its existing world-unit semantics. Existing Life capabilities are the only interpreters. There is no game-layer gameplay system, callback, mutation rule, economy, AI, custom save format, custom renderer, or map-building helper. Save slot/version and IO policy belong to the host adapter and are never authored into the AI JSON package.

`SIMLIFE-ENG-13A` is the owner-approved extension of that interpreter set: the shared engine gains one closed `t2-life-quest` interpreter rather than extending the demo with another flag-specific selector. Author data declares chapters, stable quest/node ids, initial and terminal nodes, priorities, optional exclusive groups, Life-domain conditions, closed triggers and closed effects. The interpreter owns `locked|active|completed|failed`, one-shot receipts, stable `priority → questId → nodeId` resolution, preflight-before-commit semantics, same-tick write-conflict rejection, trace and projection. It accepts no expression strings, callbacks, UI state or game-private predicates. Little Valley only supplies a three-node graph and renders `LifeQuestProjection`; it never derives objective state from story flags.

`SIMLIFE-ENG-15A` adds the owner-approved shared `t2-life-relationship` interpreter. `relationships[]` is strict JSON keyed by NPC placement id and declares integer bounds/initial value, strictly increasing named levels, per-day talk/gift/action budgets, stable prioritized rules, closed triggers and the sole `relationship-delta` effect. `LifeRelationshipState` is authoritative; `LifeRelationshipProjection` is the UI/read model. The single `applyRelationshipBatch` writer performs `priority DESC → npcId → ruleId → sourceId` ordering, same-NPC conflict rejection, daily-cap and min/max clipping, gift inventory preflight, receipt creation and projection refresh. Quest and dialogue relationship conditions/effects reuse this state and writer; no game code derives levels or mutates the ledger. Calendar reset precedes relationship commit, which follows Life outcomes/dialogue and precedes quest reads.

`SIMLIFE-ENG-16A` adds no runtime capability. Its `LifeGenerationBundle v1` checker lives strictly in the authoring/tooling plane and composes the registered capabilities above as a trust-boundary probe: closed envelope → existing Life validator/compiler → registered capability/system graph checks → isolated two-tick Engine snapshot/hash/restore → draft AssetSlot closure. Prompt packets, provenance, repair paths and dry-run materialization plans are authoring artifacts and are forbidden from World/snapshot/save. Real file creation, launcher registration and AssetIndex approval remain separate human/asset-manager handoffs.

The accepted phase contract is: existing Life systems produce authoritative outcome components in Update/Resolve; `life-milestone` and `resource-apply` commit their existing writes first; `life-quest` runs in Commit afterwards, reads the resulting world/outcomes, resolves candidates in a stable total order, preflights the complete batch, and either commits every effect or none. Multiple candidates writing the same logical target fail closed unless they share an explicit `exclusiveGroup`, in which case only the highest-priority total-order winner is eligible. Quest effects reuse the engine logic writer for Flag/Resource and inventory helpers for item changes. No random source or wall clock participates.

The mine vertical slice is entirely this same data vocabulary: `mine-gate.requires` consumes the mayor-report story flag; `mine-interior` owns a distinct RLE corridor, mining zone, ore resource placement and exit warp. `t2-life-navigation` moves scene/position through authored spawns, `t2-life-activity` projects the live mine/depleted affordance, and `t2-life-resource-gather` performs the real inventory increment and quantity depletion. No test or host code sets the story Flag or adds ore during the acceptance path.

## Presentation boundary

The demo consumes opaque `art:little-valley:*` visual consumer keys for tiles, player, crops and placements. They are connected to the Life projection and Canvas `AssetManager` lookup with preview fallback. The host explicitly opts into the generic responsive scene/play-field path: the top HUD retains its authored 52px band, the remaining CSS viewport becomes the Canvas logical size, and its backing store tracks device pixel ratio. `CanvasRenderer` derives an aspect-preserving `cover` multiplier from that local viewport and the authored 28×19-cell Camera, then clamps a renderer-private effective camera from the actual visible cell count and applies that same view to the Life preview, ordinary renderables and `WorldUi2DLayer`; it does not mutate Camera, follow/clamp state, World snapshot or hash. The Life player sprite consumes continuous `Transform` through the sole cell-center projection with no second half-cell offset, while a renderer-only translucent cell highlight consumes authoritative `LifePosition` beneath placements/player. Omitted viewport options retain the fixed legacy canvas. Its interface is a `LayoutNode` tree mounted with `STARTER_THEME`; controls and browser keyboard glue only enqueue semantic actions through `QueuedInputSource`. Physical direction changes are projected as one complete `life.move.state` bitmask (up=1/down=2/left=4/right=8); `t2-life-continuous-motion` consumes the final same-tick snapshot atomically, so multi-key/alias/repeat/keyup ordering cannot leave a half-applied held flag. Legacy programmatic `life.move.start/stop` signals remain supported. E/Tab/Enter/Escape are non-blocking interaction keys: their first keydown performs only the menu/dialogue operation, repeat is ignored, and neither path changes held directions. T/N retain their release-before-time-action behavior by sending the zero movement snapshot first. Direction-key browser repeat and duplicate held-code keydown are no-ops; aliases mapped to the same direction remain active until the final physical alias is released; blur/visibility and non-dialogue pointer/HUD actions send the same zero snapshot. An authoritative dialogue panel no longer owns movement: new direction starts remain legal, dialogue keyboard/pointer progression does not release motion, and a direction keydown does not close the active dialogue projection. Under Little Valley's proximity policy the simulation session, options and panel disappear together when the actor leaves range, while physical held state and resulting Velocity continue until their actual keyup/blur/visibility events. The mayor and merchant have data-authored morning/afternoon positions and dialogue; this is a deterministic schedule projection, not autonomous decisions, path animation, or AI. Milestone effects are interpreted by generic capabilities: the first-turnip milestone sets `flag.story.first_harvest`, and the mayor's choice condition consumes that real world flag unchanged. No game-layer system or callback participates. After `SIMLIFE-DEMO-13`, the world-interaction projector obtains all current tile/placement/warp action availability and plant candidates only from compiled `LifeActivityContext.affordances`; it does not re-evaluate inventory, package placements, resource/crop state, permissions or warp gates. Local tables affect labels and presentation order only. `WorldUi2DLayer` consumes the resulting render-local descriptor every frame, constrains its scroll container and direct LayoutNode root to the logical viewport, and keeps the measured prompt/menu inside all four safe-area edges. Prompt and recursive menu declare responsive maximum widths rather than fixed widths. Its generic interactive opt-in routes LayoutNode clicks through mountUI; Little Valley handlers change only render-local selection and enqueue the exact existing leaf actions. Menu state, Transform anchor, effective camera, highlight and LayoutNode remain outside snapshot/hash.

## Save boundary

The host creates its backend only through `createStoragePort()` and delegates snapshot/order/hash IO to `LifeHostSaveAdapter` over the existing `SaveSystem`. Slot identity is derived only from the validated `life-host.v1` namespace. The stored body is a strict allowlist of authoritative progress; package-owned inventory configuration, schedule entries, resource definitions and placement art/prefab metadata stay in the freshly compiled baseline, while only their mutable items/cursor/remaining/position fields are overlaid. Descriptor, package catalogs, HUD/menu/input, Camera, motion/Velocity, prompt/provenance/assets and one-tick requests never enter the payload.

Restore verifies slot metadata, save schema, descriptor/package fingerprints, snapshot order and hash before loading into an isolated World. It then merges progress into the captured fresh compiled baseline, validates the merged persistent hash, clears held direction, velocity and navigation requests, and replaces the active World once; any failure leaves the active authority unchanged. An open dialogue persists only `LifeDialogueSession + State` as its progress cursor: `DialogueScript` and rendered `Text` never enter the save projection. Before the immediate first host paint, the normal deterministic tick first rebuilds current `LifeActivityContext`, then lets `t2-life-talk` apply the fresh package's static session policy and rebuild valid runtime. A missing catalog entry, missing/mismatched State, unknown current node, or proximity-bound target outside the restored actor's current range destroys the reserved session and residual runtime fail-safe. This recovery performs no storage write and is traceable only when `DebugTrace` is enabled. The external interaction controller is created closed after bootstrap. Autosave hashes commit-bearing progress plus scene identity, so continuous coordinates, camera follow, input, UI and ticks cannot write; simultaneous commits deterministically coalesce. Optional host decisions use `DebugTrace`, which remains outside the deterministic hash. `SaveSystem` alone owns the host timestamp, so sim/package code reads no wall clock or storage API.

## Shared host materialization boundary

`mountLifeGame(container, { descriptor, lifePackage, assetSlots, storage?, host?, loadArt? })` is the single browser composition path. It strictly parses the descriptor, compiles and validates the Life package, parses the AssetSlot manifest, and checks `assetSlots.game === descriptor.slug` before touching the DOM. Only then does it compose the existing host skeleton, run loop, responsive `CanvasRenderer`, standard presenter/interaction/input/HUD, optional save/autosave policy and render-only art loader. Descriptor paths remain authoring identity; the runtime never evaluates them as imports or URLs.

The no-storage case is explicit (`not-configured`) and performs no persistence attempt. A configured but empty or incompatible port produces the shared `missing` / `incompatible` result and keeps the fresh compiled world. Keyboard, pointer and LayoutNode actions only enqueue through `QueuedInputSource`; host code has no direct World write. Disposal is idempotent and releases held input, keyboard/document listeners, interaction state, autosave observation, run loop, renderer, LayoutNode mount and host shell. Little Valley's browser entry now supplies only its descriptor/package/slot data and the existing storage choice; a second arbitrary fixture uses exactly the same shared path.
