# MC Fight R3：全量行为验证与数值裁定计划 v1.0

日期：2026-09-15。前置：R2内容装配已独立复查PASS。目标：把84份“可校验内容”逐步变成真实可运行、可验证的单位，而不是把待定配置直接放进商店。

## 1. R3的工作方式

R3按机制族验证，再用每单位身份场景确认装配，不为84个单位复制84套战斗系统。每个机制族通过后，同族单位只新增参数化场景和身份断言；发现现有能力不能表达时登记公共缺口，不写单位专属战斗代码。

```text
R3-A 全局数值与规则裁定
→ R3-B 已验证机制族批量运行
→ R3-C 六类复杂机制验证/缺口裁定
→ R3-D 84单位身份场景和全量商店试玩
→ R4 全量数值平衡、阵容与性能
```

## 2. R3-A：需要owner确认的三项全局裁定

### A. 旧版数值兼容模式（推荐）

以旧版 `effectiveAttributes` 和已读取的旧技能参数为默认基线：

- 生命、攻击、护甲、韧性、CD、状态持续时间和技能伤害保留旧值。
- 空间换算：`1 新版世界单位 = 24 旧像素`；旧速度、距离、半径全部除以24。
- 时间单位保留秒，不按20Hz再次缩放。
- 旧版价格直接保留；全量商店基础金币改为1000，S4的30金币六单位演示作为独立原型范围保留，不混入全量模式。
- 0价格且旧版隐藏的六个单位继续只从召唤/转换产生，不进入全量商店。
- `attributeOverrides` 中仍展示SO/JSON差异，但运行基线采用已盘点的 `effectiveAttributes`。

该方案最大限度保留旧版单位相对强弱，同时将像素坐标转换为新版战场。R4可以调整数值，但每个变化必须留下“旧值→新值→原因”。

### B. 护甲和穿甲（推荐）

复原旧工程的Minecraft护甲/韧性公式：

```text
g = min(20, max(armor / 5, armor - 4 × damage / (toughness + 8)))
finalDamage = damage × (1 - g / 25)
```

- 真伤跳过护甲。
- 穿甲攻击以目标护甲和韧性为0结算。
- 护甲、韧性、伤害和最终伤害均在每次命中记录，便于验证和结算说明。

这是旧 `DamageSystem.cs` 的实际公式，而非猜测。R3只复原公式；M09“穿甲参数如何削减而非完全无视护甲”的高级变体仍待后续设计。

### C. R3验收策略（推荐）

优先让所有单位拥有可运行的“兼容基线”，而不是等最终平衡后才验证：

- 有完整旧数值且使用已验证机制族的单位，采用A/B并进入R3-B。
- 旧参数冲突、缺参或复杂AI的单位先运行基础攻击/已确认技能；其标志性技能进入R3-C后才可标记身份通过。
- 绝不使用0或任意默认数值填补缺参。

## 3. R3-B：已验证机制族批量运行

按以下顺序批量接入，所有单位同时满足“真实生成、移动/攻击、命中或效果结算、死亡清理、双实例隔离”才通过：

1. 单体/范围近战、地面移动、目标重选。
2. 弹丸、范围爆炸、穿透、持续光束和固定落点。
3. 飞行、俯冲窗口、对空、冲锋、目标承诺和硬控取消。
4. 中毒、燃烧、凋零、减速、冻结、恐慌、治疗和自爆。
5. 召唤、来源效果、转化、共享生命、部位减伤和吞噬。

每组先做一个对抗场景，再把同族单位参数化加入。每项测试必须走真实世界路径，不能只检查目录字段。

## 4. R3-C：六类复杂机制

R2已经识别出以下六类，它们要么需要真实组合验证，要么需要明确能力裁定：

| 机制 | 涉及单位 | R3验收 |
|---|---|---|
| SK10 跃击 | 遗弃者、暝煌龙、珊瑚傀儡、珊瑚巨兽 | 真实追击轨迹、落点、控制/死亡取消和落地范围 |
| SK20 条件处决 | 独眼巨人 | 最大生命门、吞噬恢复、删除和飞行资格 |
| SK22 蛇身接触 | 地面娜迦 | 多节共享CD、缩节、蛇形路径和头部受伤 |
| SK24 骑乘 | 国王蜘蛛、骷髅德鲁伊 | 双生命、独立决策、上下马和层级清理 |
| M06 来源效果 | 先驱者、悚怖尸巫 | 直接/间接来源、击杀恢复、转换归属和来源死亡后标记 |
| M09 穿甲 | 铜羽泽鹗 | 采用护甲公式后的穿甲语义、伤害证据和敌我资格 |

任何一项无法用当前公共能力表达时，程序必须给出A/B最小方案和影响单位名单；该机制族暂停，其他五组继续。

## 5. R3-D：84单位身份场景

每个单位建立一个可重复的身份场景。基础单位可以复用同一模板场景，但断言必须点名其单位ID、装配参数和至少一次有效行为。复杂单位的场景必须覆盖其标志性技能。

全量商店试玩前置：

- 78个可购买单位全部可查看详情、购买、部署和进入战斗。
- 6个隐藏单位只能由规定的召唤或转换链创建。
- 任一单位没有合法可运行装配时，商店不得把它作为可购买成品展示。
- 详情信息从统一内容目录读取，必须显示采用状态或对玩家隐藏未完成单位。

## 6. R3完成判据

- A/B/C三项全局裁定已落账。
- 所有已上线单位具有真实行为证据；84单位逐行身份状态可查。
- 六类复杂机制均已通过或有独立裁定和明确阻塞状态。
- 没有 `pending-design` 字段进入实际战斗。
- 84单位全量矩阵、组合回归、类型检查、构建和系统审计通过；独立复查确认没有用数据绕开规则。

R3完成后，才可宣称“84种单位均已接入实际战斗”。R4才处理阵容平衡、全量经济和性能；S6才处理正式动作素材。
