日期：2026-09-15。策划下发。目标是程序连续完成所有不依赖新美术成品的剩余工作，最后统一回归和交审；不要求每完成一个小项就暂停汇报。本文不改变已确认规则，不推翻 B、V02 和已独立通过的修复。

## 0. 当前基线

- B 对照表范围已独立验收通过；V02 逻辑和默认画面已通过；C1 已完成程序自证，独立复核另行进行。
- 动画硬控切出、目标承诺、死亡清理、拍初位置、碰撞时序等已有公共修复继续复用，不重复造系统。
- C3、C4、C5 已有首轮实现，见 [本批程序交付](s2-action-v06-v08-delivery.md)。下面只补差额，不因实验数值不同重写已成立的语义测试。
- 当前测试数量只是回归信息，不是阶段完成判据。

## 1. 执行方式

程序按 P1→P5 连续推进。开发过程中应运行最小定向测试以定位问题；全部完成后再统一执行一次完整回归、类型检查、组合审计和可视化留证。中途仅在以下情况暂停交回：

1. 实查 registry、生产线手册和现有组合后确认公共能力确实无法表达，需要 owner 选择 A/B；
2. 缺少真实动作图片使 C2 美术验收无法继续。该情况不阻塞 P2—P5，先完成其他工作后统一报告；
3. 发现会推翻已确认玩法规则的冲突。

普通测试失败、实现困难或需要补回归不构成中途交回理由。

## 2. P1：C1收口与动作播放器

### C1

不再新增功能。保留 [C1交付证据](s2-c1-closeout-evidence.md)，等待独立复查；若复查退回，只修明确问题并纳入最终回归。

### C2程序部分

在现有 AnimState、ActionObservation 和绑定数据上完成正式播放器所需的通用数据接线：片段、帧序、帧时长、循环方式、默认朝右、左右镜像、根/身体/握持/效果挂点、等比缩放、命中反馈、硬控切出、死亡清理。动画只读战斗阶段和结果，不能写 HP、窗口、目标、技能阶段或 CD。

必须验证：

- 卫道士正常右向和左向各一轮；前摇锁定朝向后，目标越过或远离不翻转本次动作；
- 移动宿主挂点跟随，镜像误差按素材像素坐标计算；
- Tick3区域生成不显示命中，Tick4真实扣血后的首渲染帧显示命中反馈；
- 硬控当拍切到中断片段、死亡立即清掉单位与攻击表现、重开不残留；
- 僵尸复用同一近战技能模板但使用独立表现绑定；恼鬼复用真实俯冲 Flow 的阶段映射。

真实素材仍按 [动作素材要求](s2-action-binding-gaps.md) 的两套挥砍与一个俯冲、共14片段执行。程序不得把原版单姿态复制、拉伸或补间后称为完整动作。素材未交付时，用明确标注的占位序列完成播放器自动测试和缺失提示，最终将“播放器通过、真实素材验收待素材”分开记录。

## 3. P2：C3 / V06接敌与避让收口

复用现有7项，不重做已经成立的接近、重叠、宽墙、墙角绕行与断路阻挡。补齐并记录：

- 3—6个近战单位围攻单目标，连续100拍：不能穿墙、瞬移、出现非有限坐标或每拍重启技能；给出末拍最小单位间距、与目标距离及每拍最大位移；
- 至少两个墙角入射方向和一次可绕行障碍，真实 NavGraph 路径能到达目标附近；
- 断路不可达持续100拍，不穿墙且状态确定。S2接受“沿现有回退方向被实体墙挡停”作为已观测的实验行为，不要求本阶段新增不可达识别、主动放弃或重选。报告必须明确这不是最终AI策略。

“最优包围站位”、动态障碍重规划和所有地图覆盖不属于S2退出条件。

## 4. P3：C4 / V07多段与效果收口

复用已完成的3段、间隔2tick、来源与清理证据。基础伤害3或4均可，只要由配置读取并在断言中明确；不为把3改成4而重写样例。

补齐一个统一数据场景：两敌一友，其中一个敌人由生产移动在段间进入或离开区域；每段按当拍位置与资格判断。记录 castId/来源/段序，防止同一段对同一目标重复结算。另验证：

- 友伤倍率0和0.5；无护甲，隔离倍率计算。0.5是本次能力实验及自爆规则所需证据，不自动成为所有技能默认值；
- 硬控或死亡在第一段后打断时，第二、三段不再生成；无中断对照完成3段；
- 每段临时实体均清理，新一轮施法不会继承旧目标或命中记录。

若现有 Hitbox 只支持友伤开关、无法表达倍率，按缺口协议实查后提交 A/B；其他项目继续。

## 5. P4：C5 / V08确定性与规模

确定性场景至少运行3次：相同seed、相同初态和相同外部输入，在每tick比较权威战斗快照或现有确定性hash；画面、墙钟和调试日志不进入比较。至少覆盖目标选择、移动、技能选择、多段伤害、死亡和临时实体清理。

规模测量统一为20、50、100单位，各1000tick，预热一次后记录3轮：机器/运行时版本、总耗时、每tick中位数、P95、最大值、结束实体数及未清理临时实体数。不得用测试框架总耗时替代。当前无正式性能阈值，所以结论只能是“完成测量、是否出现明显非线性或泄漏”，不能写“性能达标”。旧16/64/128×60数据保留为历史参考。

## 6. P5：C6代表机制覆盖与最小样例

先提交一张“单位需求→技能模板→已注册能力→当前证据→缺口”的覆盖表。随后只对没有等价证据的机制建立最小生产组合，不能用定点区域冒充弹丸，也不能用一次范围命中冒充持续效果。

本批必须具备运行证据的六类：

1. 弹丸：从发射挂点生成，经速度/移动/接触命中，命中或寿命结束清理；
2. 光束：长度、宽度、朝向与伤害范围同源，允许穿透多个合法目标，打断后清理；
3. 固定落点轰击：标记期追踪，标记结束固定落点，目标移动可躲避；
4. 持续区域：固定持续时间和结算间隔，每目标每段最多一次，来源可追溯；
5. 召唤：归属、生成位置、来源死亡后的处理按实验合同明确，重开无残留；
6. 特殊关系骨架：共享生命部位、骑乘、蛇身和死亡转化分别证明数据关系与清理可表达。只需最小实体，不制作正式怪物。

已确认规则必须带入：光束穿透；标记结束固定落点；轻语灵头/本体分别索敌、共享生命且只有头部减伤；尸巫转化只一次并归最后伤害它的尸巫，形态按原单位最大生命与节肢标签判断。尸巫本体先死亡后标记是否仍生效等尚未裁定部分，用明确标注的实验分支验证技术可行性，不写入正式GDD。

若某类已有完全等价的生产测试，可以引用并补 MC Fight 数据装配，不重复开发。发现真实能力缺口仍按 A/B 裁决；不得写每单位专属系统绕过。

## 7. 统一可视化证据

同一S2入口增加P1—P5代表场景选择，复用自动测试工厂。只为动态、易误判的边界保存关键帧：动作镜像/打断、围攻/不可达、多段移动进出、弹丸飞行、光束穿透、固定落点躲避、特殊关系清理。暂停、单步、重开控件只需统一复验一次，不为每项重复留相同控件截图。

画面必须读取真实 Transform、Relation、Shape、阶段、资源和来源；调试范围与逻辑Shape同源。几何画面证明机制，真实动作素材另作明确结论。

## 8. 最终一次性门禁与交付

所有可施工内容完成后，按顺序执行：

1. 新增场景定向测试，保留非静默输出并检查告警；
2. `games/game-mcfight`及所有本批改动的共享能力回归；
3. TypeScript类型检查；
4. 安装本批全部生产能力的组合调度审计，核对无重复系统、悬空边和环；
5. 构建与项目既有范围门禁；
6. 实际浏览器逐场景复验并保存索引化截图/轨迹；
7. 更新V01—V08、C1—C6对照表，每项只允许：通过、部分通过、阻塞、留后续，并给证据路径；
8. 提交一张总复查交接单，由独立复查者一次复跑、针对新增公共修复撤修验红并给出S2技术结论。

最终交付必须分开写：程序自证结论、独立复查状态、真实素材状态、未裁定玩法、性能测量。不得因为真实素材未到就隐去其他完成结果，也不得因测试全绿把素材或未裁定规则写成已完成。

## 9. 明确不在本批范围

- 84个单位的批量配置、正式数值平衡、全部美术、八方向动画；
- 正式商店、部署、结算闭环；
- 所有地图的导航质量、动态障碍最优重规划；
- 跨平台浮点一致性、正式目标硬件性能承诺；
- 未获裁定的特殊规则定稿。

程序完成本单后停止扩展S2范围，提交总证据。策划根据独立复查、真实素材状态和未裁定项给出S2签核建议。
