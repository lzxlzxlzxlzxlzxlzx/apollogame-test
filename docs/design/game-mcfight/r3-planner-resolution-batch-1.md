# MC Fight R3 策划裁定第一批：兼容基线与机制边界

日期：2026-09-15。状态：owner已确认本文件第1节三项全局方案。本文件将R2的待定项压缩为可施工规则；未在本文裁定的复杂几何不得由程序自行补写。

## 1. 已确认的全局兼容基线

- 单位属性：采用旧 `effectiveAttributes` 作为兼容基线；SO/JSON差异保留在溯源层，不另选值。
- 单位换算：1个新版世界单位 = 24旧像素。旧速度、攻击距离、碰撞半径、范围、弹速和落点距离均除以24；时间仍以秒计，不按20Hz再次缩放。
- 经济：全量商店初始金币1000，旧价格直接保留；S4的30金币六单位演示保持独立范围。
- 隐藏单位：悚怖尸兽、悚怖食尸鬼、悚怖劫蛛、悚怖尸奴、跨座蝌蚪、恼鬼均不进入全量商店；它们只通过各自召唤/转化来源出现。
- 护甲：采用旧Minecraft护甲/韧性公式。真伤跳过护甲；穿甲将目标护甲与韧性视为0后结算。
- 玩家统计：造成伤害只计实际扣除HP；治疗量只计实际恢复HP；两者独立显示。

## 2. 通用决策算法

31份复杂决策不再为每单位写独立状态机，统一采用下列可配置策略：

1. 先过滤阶段、硬控、CD、目标资格、距离、目标类别和专属条件。
2. 对剩余候选按 `priority` 排序；相同priority按配置顺序稳定决胜。
3. `alternate`/`cycle` 只在技能成功启动时推进；启动失败、目标失效或被硬控取消不推进；已启动CD不退款。
4. `distance-switch` 使用配置阈值；切换后的技能必须重新通过合法性检查，不能因为先前目标类别而越权命中。
5. `periodic` 用独立计时器，不占用正在执行的主动技能，除非装配明确写 `blocksAction=true`。
6. 来源为旧版随机选择的候选，使用引擎种子PRNG，在合法候选中均匀选择；空候选不消耗循环或CD。
7. 变身、召唤、骑乘等改变实体组成的机制，必须通过专门机制合同，不能由通用候选表偷改基础组件。

## 4. 已裁定的复杂机制边界

### M06 来源效果

- 悚怖尸巫只有自身直接造成的实际伤害会写转化标记。
- 随从、间接区域和持续状态默认不继承尸巫标记能力。
- 标记保存最后实际伤害的尸巫来源身份和阵营快照；来源死亡后标记仍有效；死亡只转化一次。
- 先驱者的击杀恢复只计算先驱者自身来源的击杀，不从召唤物或盟友继承。

### M09 穿甲

- 铜羽泽鹗的穿甲使用本文件第1节的“护甲和韧性均按0”定义。
- 穿甲不改真伤类别，也不影响非护甲类减伤。

### SK20 吞噬

- 吞噬可选择飞行目标，按CR15执行。
- 仅当目标最大生命小于等于单位配置阈值、目标位于吞噬距离且技能成功启动时删除目标；删除后结算配置治疗/恢复并进入CD。
- 不满足阈值时独眼巨人使用地面范围重击；吞噬阈值、治疗量和CD采用旧参数换算并进入身份测试。

## 5. 仍需专门机制方案的三类

| 机制 | 原因 | R3程序不得自行假设的部分 |
|---|---|---|
| SK10 跃击 | 需要真实连续轨迹和落点；旧代码轨迹不能直接替代新版时序 | 空中是否可被选择/控制、途中目标死亡、落点被阻挡的最终规则 |
| SK22 蛇身接触 | 多体节、共享CD、缩节、蛇形路径在当前公共组合中尚未验真 | 体节数量、缩节阈值/顺序、头与身体的受击/碰撞关系 |
| SK24 骑乘 | 双生命、独立骑手决策、下马和层级清理需统一合同 | 骑手/坐骑死亡先后、购买方式、下马位置与骑乘期间目标资格 |

这三类先由程序提交最小真实组合探针和A/B实现边界，策划据探针补最终合同；不得直接从Unity类迁移专属状态机。
