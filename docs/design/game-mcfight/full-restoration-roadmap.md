# MC Fight 全量内容复原路线 v1.0

日期：2026-09-15。状态：owner目标已确认，作为S4通过后、S5开始前的强制内容里程碑。

## 1. 最终目标

完工版本必须完整覆盖旧版MC Fight已经盘点的84种单位、各单位的核心技能、攻击方式、目标规则、特殊状态、行为逻辑和可识别视觉身份。新版不复制旧Unity工程的单位专属代码和已知缺陷，而是在ApolloGame统一的单位、技能、决策、状态、伤害与表现架构中重新装配。

“完整复原”定义为内容与玩家可观察行为完整，不要求逐行复制旧代码，也不要求保留旧实现中的错误、调度偶然性或相互矛盾的数据。

## 2. 在生产流程中的位置

```text
S3 统一骨架
→ S4 六单位完整可玩纵切
→ R 全量内容复原（84单位，S5前置硬门）
→ S5 全量UI与信息呈现
→ S6 全量素材、动作、特效与声音
→ S7 平衡、性能、手感和视觉品质
→ S8 终检与完整交付
```

R不是绕过看板新增的签核阶段，而是MC Fight项目内部的内容里程碑。R未通过时，不得把S5描述为“全量正式UI”，也不得宣称游戏已经完整复原。

## 3. R里程碑的四个批次

### R1 原版事实冻结

- 为84个单位逐一登记旧版名称、阵营/标签、价格、生命、速度、攻击数值、CD、范围、控制时长和行为条件。
- 每个数值标记来源：旧数据、旧代码推断、画面观察或缺失。
- 将“旧版事实”和“新版采用值”分列，禁止覆盖原始记录。
- 旧资料冲突、缺失或明显属于bug时，写入裁定表，由策划给出新版值及理由。

完成标准：84/84单位均有内容卡；每个可观察技能均有来源或明确缺失记录；没有“程序自行猜测”的未标记字段。

**R1当前状态（2026-09-15）：事实库、素材库和84行机读矩阵已完成；交接见 [R1全量复原数据交接](r1-restoration-data-handoff.md)。新版采用值、R2装配、R3验证和S6绑定仍为pending。**

### R2 全量数据装配

- 将84个单位装配进S3冻结的 UnitDefinition、SkillLoadout、DecisionProfile 和 PresentationProfile。
- 复用 `skill-design-v0.1.md` 的公共技能模板；参数差异写在装配层。
- 每个单位至少包含价格、基础属性、目标标签、完整技能装配、技能选择逻辑、详情文案和表现槽。
- 同一模板跨单位不复制运行状态；不得出现按单位ID分支的技能系统。

完成标准：84/84可创建；所有引用有效；每个配置字段有解释器；目录无死数据；统一数据检查通过。

### R3 行为与组合验证

按机制族分组，不为84个单位各写一套重复测试：

- 基础近战、远程弹丸、范围、穿透和持续攻击。
- 冲锋、俯冲、游走、环绕、传送及特殊移动。
- 治疗、召唤、转换、自爆、吞噬、部位与共享生命。
- 中毒、燃烧、凋零、冰冻、恐慌及控制打断。
- 多技能选择、独立CD、目标承诺、死亡清理和跨实例隔离。

每个单位另有一项“身份验收”：在固定场景中至少成功执行一次使其与普通单位不同的代表行为。纯基础单位验证其模板装配和数值身份。

完成标准：84/84身份验收通过；全部机制族组合回归通过；没有只能在测试替身中工作的技能。

### R4 全量内容试玩门

- 商店可以浏览、筛选、查看和购买84种单位。
- 详情页展示的数值、技能、对空/地资格和状态说明与真实配置一致。
- 建立覆盖低价、前排、远程、飞行、控制、召唤和特殊单位的固定试玩阵容。
- 验证大量目录不会使商店不可用，并复测20/50/100单位性能风险。
- 给出首轮平衡报告，记录明显无效、必选、无法接敌、永久卡死或无限循环的单位。

完成标准：用户可在正式入口选择任意单位完成一局；不存在无法购买、无法部署、永不施放或结算残留的单位。

## 4. 数值复原原则

数值分三类处理：

1. 旧版明确且与新版单位/时间尺度兼容：优先保留。
2. 旧版明确但依赖旧bug、旧帧率或专属代码：保存旧值，同时给出等效新版换算值。
3. 旧版缺失、冲突或无法观察：由策划给出新版初值，标记为“重建值”，进入S7平衡。

任何调整都保留“旧值→新版值→调整理由”三列。最终版本可以比旧版更平衡，但不得悄悄改变单位的核心定位和标志性行为。

## 5. 素材复原原则

- 先完整盘点旧项目中的单位图像、图标、特效和声音，按单位及动作语义登记。
- 能满足尺寸、朝向、挂点和动作阶段要求的旧素材优先直接使用。
- 只有静态姿态的素材可以作为身份参考或临时占位，不能冒充完整动作。
- 缺失动作优先基于旧单位造型制作；需要AI生成时，以旧素材为角色参考，保持轮廓、配色和装备特征。
- 每项素材记录来源、用途、动作关键点、逻辑挂点、镜像规则和允许偏差。
- 命中范围永远取自逻辑攻击几何；素材必须对齐判定，不得反向改变伤害或范围。

S6完成标准是84个单位均有可识别主体表现，所有实际使用的技能动作/特效都有正式绑定；页面中没有未声明占位、缺图或将单姿态误作动画的情况。

## 6. UI与信息规模要求

S5必须按84单位规模设计，而不是把6张原型卡简单扩成84张：

- 商店支持分类、筛选、排序和滚动/分页。
- 单位详情由真实目录生成，禁止维护第二份展示数值。
- 清楚展示价格、生命、移动、攻击类型、目标资格、技能、CD、范围和关键状态。
- 飞行、对空、召唤、控制、共享生命等特殊规则有统一图标和文字规范。
- 素材缺失和数据错误在制作工具中可见，但不向玩家展示技术字段。

## 7. 性能硬目标

S2已经记录100单位明显非线性。R4必须重新测量并在进入S7前形成优化任务：

- 目标场景：20、50、100个真实装配单位，各运行1000 Tick。
- 同一seed重复三次，结果哈希一致。
- 50单位必须保持可正常游玩；100单位不得出现数量级恶化、冻结或结算错误。
- 最终毫秒预算由S7结合目标设备确定；未达预算时不得隐去风险或用减少84单位目录冒充解决。

## 8. 全量完成矩阵

维护一份机读矩阵，每个单位一行，至少包含：

- `sourceFactsComplete`
- `definitionComplete`
- `loadoutsComplete`
- `decisionComplete`
- `presentationSlotsComplete`
- `identityTestPass`
- `browserObserved`
- `artBound`
- `finalReview`

只有84行全部完成，才可以使用“全量内容已复原”的表述。总测试数、公共模板通过或少数样例截图都不能替代逐单位矩阵。

## 9. 分工与复查

- 策划：旧版事实裁定、单位身份、重建数值和身份验收预期。
- 程序：统一目录装配、公共能力接线、测试、性能与真实运行证据。
- 美术：旧素材整理、缺失素材制作、动作与挂点绑定。
- 独立复查：抽查旧版来源，逐机制撤修验红，核对84行矩阵与浏览器证据。
- owner：批准有争议的内容改动和里程碑人审。

## 10. 最终交付判词

项目只有同时满足以下条件，才算“完整复原且更健壮”：

- 84种单位全部在正式游戏中可购买、部署、战斗和结算。
- 每种单位的标志性技能与行为得到保留或有明确批准的重建设计。
- 全部单位使用统一数据结构和公共能力，不恢复旧版单位专属系统堆叠。
- 旧版可用素材已接入，缺失部分已补制并完成动作/范围验收。
- 完整循环、全量身份验证、性能、UI、美术、品质和终检均通过各自门槛。
