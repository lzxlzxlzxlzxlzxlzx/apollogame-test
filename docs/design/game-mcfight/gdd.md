## 2. 技能系统方向

已形成[技能详细设计 v0.1](C:/Users/24652/Desktop/projects/apollpgame/apollogame-test-game-105-standalone/docs/design/game-mcfight/skill-design-v0.1.md)及[单位装配建议](C:/Users/24652/Desktop/projects/apollpgame/apollogame-test-game-105-standalone/docs/design/game-mcfight/unit-skill-loadouts-v0.1.md)。复用技能的伤害、范围、CD等通过单位装配参数提供。初稿提出的CD、锁定、打断等默认行为均属待确认提案，本GDD的“已确认规则”不因此扩充。

单位、技能参数装配、表现配置与素材之间的关系，以及攻击几何和视觉对齐原则，见[单位—技能—表现设计](unit-skill-presentation-design.md)。该文为S1设计补充，具体Schema及实现待S2验证。

统一普攻与主动技能，采用共享技能定义和单位独立运行状态。技能定义至少讨论CD、施放距离、效果范围、目标规则、前摇/持续/后摇、效果、锁定、打断。CD已确认从成功启动开始，打断不退款；属性单位、零CD及并发细则仍按提案讨论。

单位决策采用公共算法与配置，禁止为每只怪物另建解释器。优先级规则或评分算法仍待选择。进入执行后何时允许重新决策或打断，应由统一契约决定。

技能效果不限于伤害；治疗、召唤、控制均应有对应表达。不要强制所有效果都有非零伤害，也不把所有移动和被动硬塞为主动技能。

## 3. 待明确规则

详见decisions.md。1000金币、1280×720、78种购买目录、原版伤害和眩晕时长、120秒判定都只是旧版参考，尚未作为新版最终规则批准。不得为了跑通原型擅自固化。

单位详情建议包含名称、价格、属性、普攻、主动技能、对空能力与关键状态说明；最终字段待UI与规则共同确认。仅有文案没有运行效果不算完成。

## 4. AI职责

分为敌方购买/布阵AI与每个单位的战斗决策。前者预算、难度、是否知晓玩家阵容待定；后者须共享真实技能合法性与冷却判断，不能独立复制一套伤害或目标规则。

## 5. 验证原则

既有能力通过单测不能替代机制组合验证。测试必须调用真实引擎路径，临时参数单列fixture且不进入正式内容。俯冲窗口起止、被打断、目标死亡等未定部分可比较多个实验方案，但不得声明用户已批准。
