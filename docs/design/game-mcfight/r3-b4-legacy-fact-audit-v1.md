# R3-B4 旧版事实与缺参审计 v1.0

日期：2026-09-17。范围仅覆盖 B4 开工前仍未消歧的旧 Unity 行为。本文件把**可由旧源码或配置复核的事实**、**旧版实现缺陷**和**必须由 owner 决定的新规则**分开；程序不得把 UI 文案、缺失键的 `0` 返回值或本文件的候选默认值当作已冻结数值。

旧工程根目录：`mcfight-unity-main`。距离数值均为旧工程像素；导入新游戏时按既有 `÷24` 规则转换为世界单位。

## 1. 裁定汇总

| 项目 | 旧版可复核结论 | B4 处理 | 是否需要 owner |
|---|---|---|---|

## 2. 核能苦力怕：辐照区并非旧版已实现行为

### 已证实

- `Assets/Scripts/Simulation/Abilities/Batch3Abilities.cs:275-299` 的 `NucleeperAbility` 只在引信结束后遍历所有存活单位，按 `lerp(500, 100, distance / 200)` 结算爆炸，然后令自身死亡；该代码没有创建区域实体，也没有附加状态。
- `Assets/Resources/monster_config.json:191-200` 仅包含 `explodeRadius=200`、`fuseDuration=10`、`centerDamage=500`、`edgeDamage=100`（重复一组相同键）；没有辐照半径、持续时间、伤害、状态或目标过滤字段。
- 全工程唯一 `CreatePollutionZone` 调用位于 `Assets/Scripts/Simulation/Abilities/Batch2Abilities.cs:224`，属于 `BrainiacAbility`，不是核能苦力怕。
- 因为旧代码不排除同队，核爆本身会伤及任意存活单位，含友军；这只适用于爆炸，不能自动推断给不存在的辐照区。

### 新版处理

**冻结结论：**B4 的“旧版复原”范围是 10 秒引信、半径 `200/24`、中心 500 到边缘 100 的线性爆炸和自毁；不产生辐照区。

若 owner 要在新版新增辐照区，须先裁定 `radius`、`duration`、每段伤害/状态、目标阵营和是否在来源死亡后保留。最小可测试的新增默认方案是：爆炸成功后在爆心生成独立区域，使用爆炸同一来源快照，只影响合法敌人；其数值字段全部设为 `OWNER_REQUIRED`，在 owner 填值前编译器必须拒绝装配。不得用任意猜测数值替代裁定。

## 3. 炽燃遗魂：声波与骨弹参数缺失，旧 UI 文案不能覆盖运行事实

### 已证实的运行结构

- `Batch3Abilities.cs:171-204`：地面目标从旋转、声波、骨弹三项中 seeded 随机选择；飞行目标只从声波、骨弹选择。每次施法时长 2 秒。选择骨弹时解除防御；结束时恢复防御并给 1 秒攻击冷却。
- 同文件 `177` 读取 `sonicTicks`、`sonicDamage`、`sonicRadius`、`sonicTickInterval`、`projDamage`、`projRange`；`197-198` 还错误地让骨弹共用 `sonicTicks` 和 `sonicTickInterval`。
- `monster_config.json:743-752` 只有旋转和近战数据，没有上述 6 个键，也没有代码读取的 `spinTickInterval`。`MonsterConfigLoader.cs:81-104` 对任何缺键记录错误并返回 `0`。
- 因此旧运行时的声波次数、伤害、半径、间隔、骨弹伤害与射程全部为不可用的 0 基线；不能据此复原。
- `CodexUI.cs:265` 有“声波 4 次、64px、4伤害；骨弹 6伤害”的说明，但它与同一 UI 行的旋转描述、以及配置中的旋转 `2×11/64` 相互冲突。该行只能作为历史设计候选，不能当运行事实。

### 已冻结且可迁移的部分

- 旋转：`spinTicks=2`、`spinDamage=11`、`spinRadius=64/24`、间隔采用此前已裁定的 `spinInterval=1.5 秒`，规范内容字段为 `pulseIntervalSeconds`。
- 防御：初始开启；近战伤害乘 0.1，远程/光束伤害为 0，其他类别按普通伤害管线。依据 `DamageSystem.cs:31-39`。
- 旧声波实际是以自身为中心、可对空的圆形范围攻击，并附 Burn；它不是穿透直线声波。依据 `Batch3Abilities.cs:197`。新版若改成声波射线，属于新设计，必须与数值裁定一起批准。

### owner 裁定单：REQ-B4-REVENANT-01

声波至少需：`pulseCount`、`damagePerPulse`、`shape/radius-or-length`、`pulseIntervalSeconds`、是否附 Burn、目标资格。骨弹至少需：`projectileDamage`、`range`、`count`、`intervalSeconds`、速度、目标快照/失效策略。

最小可测试候选（**不是冻结值**）：采用旧 UI 的声波 `4 × 4`、`64/24`，骨弹单发 6 伤害；其间隔、射程、速度和形状仍必须由 owner 填写。没有完整字段时，B4 不得把遗魂标为行为通过。

## 4. 霜冻巨兽冰冻：2 秒为旧版确定值

- `Batch3Abilities.cs:423`：冰球以 12 伤害、220 射程创建投射物，并在真实命中后附 `StatusEffectType.Freeze`。
- `StatusEffectSystem.cs:75-87`：`Freeze` 固定持续 `2f`；`164-170`：冻结时移动速度为 0、攻击间隔为极大值。
- `monster_config.json:1141-1148` 没有冰冻时长键，说明 2 秒来自旧版公共状态表而不是该单位专属配置。

**B4 裁定：**冰球命中施加 2 秒硬控冰冻。它必须使用 S2 的硬控取消与刷新规则，不能复用旧版“攻击间隔设为极大值”的实现细节。

## 5. 雪怪首领：冰区只影响敌方地面单位

- `Batch3Abilities.cs:458-461`：冰弹爆炸半径为 `60/24`、伤害 8；旧实现还会在施法时的目标坐标立即创建冰区，半径 `50/24`、持续 5 秒、每秒伤害 2。
- `AreaEffectSystem.cs:42-58`：冰区附加 Slow；`91-102`：每秒结算；`137-160`：先排除死亡和同队，再对 `FrostZone` 排除飞行单位。没有 Boss、护甲或其他标签过滤。
- `monster_config.json:1260-1267` 证实冰区半径和持续时间、冰弹伤害与半径；2 DPS 来自 `Batch3Abilities.cs:460` 与 `CodexUI.cs:270`，并不在 JSON 中。

**B4 裁定：**冰区是落点独立区域，以实际冰弹接触/爆炸位置创建；每秒 2 点范围伤害并附 Slow；只影响合法敌方地面目标。处于 S2 俯冲下降窗口的飞行单位按“当前视作地面”资格可被命中，回升关窗后从下一段起不再命中。

## 6. 女巫：三种攻击包，加一项条件自疗

- `Batch2Abilities.cs:17-26`：只有当受伤且 200 范围内无敌时自疗 10；否则若有敌人，用 `state.RNG.Next(3)` 等权选择三种攻击包。
- 该三种攻击包为：纯 6 点范围伤害；6 点范围伤害 + Poison；6 点范围伤害 + Slow。区域半径 `48/24`，攻击冷却 2 秒。
- `monster_config.json:1579-1582` 仅存储治疗量、范围伤害和半径；等权和状态包由源码固定。
- `CodexUI.cs:290` 称“四种药水随机”，与运行代码不符：治疗不参加随机，而是在无近敌且受伤时优先。

**B4 裁定：**自疗和投药是两个数据技能：自疗条件为受伤且 200/24 内没有合法敌人，治疗 10、CD 2 秒；攻击以对局种子等权选取三包，范围 `48/24`、伤害 6、CD 2 秒。中毒和减速完全采用 S2 状态合同。

## 7. 食人妖：按伤害类别过滤，不看来源单位

- `DamageSystem.cs:42-45`：目标带 `troll_immune_ranged` 时，`DamageCategory.Ranged` 或 `DamageCategory.Beam` 直接返回 0。
- 同段未拦截 `Melee`、`Explosion` 或 `True`；护甲管线在该过滤之后才执行。
- `MonsterDataGenerator.cs:142` 给食人妖标签 `knockback_immune` 与 `troll_immune_ranged`；`monster_config.json:1091-1094` 证实重击 27、普通攻击 10、重击 CD 15。

**B4 裁定：**实现为通用 `DamageCategoryFilter`：拒绝 ranged 和 beam，允许其他类别继续所有常规资格、伤害与状态处理。验收必须包含被远程/光束零伤害、被近战/爆炸/真实伤害正常结算，以及击退免疫独立于伤害过滤。
