# MC Fight R3-B1 程序施工单：标准投射物与首批远程身份

日期：2026-09-16。前置：R3-A已完成首批24个身份验证；全库5210项通过、1项历史跳过，类型检查、构建和组合审计通过。本单只安排一个完整、可复核的机制族，避免把跃击、蛇身和骑乘等未定机制混入施工。

策划依据：[R3全量行为计划](r3-validation-and-calibration-plan.md)、[第一批裁定](r3-planner-resolution-batch-1.md)、旧工程 `GenericAbilities.cs` 和 `ProjectileSystem.cs`。本单完成后仍不得宣称R3整体完成。

## 1. 本批目标与单位范围

实现一个由数据驱动的**标准直线投射物**，并完成以下四个单位的真实身份场景：

| 单位ID | 单位 | 旧版身份 | 本批必须验证的差异 |
|---|---|---|---|
| `pillager` | 掠夺者 | 地面标准远程 | 2秒攻击间隔的弩箭 |
| `skeleton` | 骷髅 | 地面标准远程 | 标准箭矢 |
| `twilightforest_death_tome` | 死灵书 | 飞行标准远程 | 飞行施法者的法术投射物 |
| `twilightforest_slime_beetle` | 粘液甲虫 | 地面标准远程 | 粘液投射物的真实命中与清理 |

本批不纳入身份通过的单位：`stray`、`iceandfire_if_cockatrice`、`cataclysm_the_watcher`、`alexscaves_teleto`。它们分别带减速、凋零、燃烧或来源参数冲突；待状态族和对应旧参数单独裁定后再进入下一批。不得为了凑数量删掉其标志性状态并标记通过。

## 2. 标准投射物的正式合同

实现通用的 `ProjectileSkill` / 投射物实体装配能力；接口由技能配置提供，禁止根据单位ID分支。

### 2.1 参数来源与兼容换算

对本批四个单位，伤害、攻击间隔、攻击距离、体型和移动方式均来自 `inventory/units.json` 的 `effectiveAttributes`，按既定兼容规则换算：

- `damage = effectiveAttributes.attack`；
- `cooldown = effectiveAttributes.attackInterval`；
- `castRange = effectiveAttributes.attackRange / 24`；
- 飞行速度采用旧公共常量 `PROJECTILE_SPEED = 280 px/s`，运行值为 `280 / 24` 世界单位/秒；
- 投射物最大飞行距离采用旧规则：本次启动时的有效射程（含目标半径资格）乘以 `1.15`；
- 目标选择保留远程可对空资格。投射物碰撞半径、目标半径和边界均必须使用真实 `Shape` 数据，不能以显示半径或视觉坐标代替。

若实际旧配置与以上公共规则冲突，停止该单位装配，登记来源位置、冲突值及建议；不得填0或自行选择新数值。

### 2.2 生命周期与命中

1. Flow成功启动时捕获目标和发射方向，进入CD；硬控或死亡在发射前取消施放，已启动CD不返还。
2. 释放时生成独立投射物实体，实体以固定初始方向真实移动；普通投射物不追踪、不能穿透、首次命中一个合法敌人后销毁。
3. 投射物按来源阵营过滤友军；命中时通过统一伤害路由结算护甲、实际扣血、来源和统计。
4. 目标在飞行途中死亡或失去资格时，投射物不回头、不重定向；它继续沿原方向飞行，可命中路径上第一个仍合法的敌人，或在达到最大距离/越界后清理。
5. 发射者死亡后，已生成投射物仍按已保存的来源快照完成一次合法命中；不得引用已销毁实体、不得产生幽灵攻击，也不得把伤害归属错误地改给其他单位。
6. 同单位多实例、不同单位和不同投射物各自保存目标、移动距离、CD、命中记录与来源，绝不互相覆盖。

本批不实现追踪、爆炸、穿透、光束、弹道抛物线或命中状态。这些均是后续机制族，不得塞入“标准投射物”。

## 3. 实现与身份测试

### 3.1 先完成公共能力测试

新增或扩展定向测试，至少覆盖：

- 真实发射 → 可观察移动 → 与真实 Shape 重叠 → 一次实际扣血 → 实体销毁；
- 目标半径影响合法射程，最大距离与越界清理；
- 友军过滤、地空资格、先接触者命中；
- 前摇硬控/死亡取消与CD规则；
- 发射者死亡后投射物来源快照；
- 两名错时射手连续三轮，证明实体、目标、CD和伤害记录隔离；
- 同seed下重复轨迹一致；
- 所有新系统与已安装的 Flow、aggro、motion、overlap、trigger、hitbox、resource、death、cleanup 共装审计无环。

### 3.2 再完成四个身份场景

每个单位一个名称中包含单位ID的场景，必须断言：

- 从该单位自己的 R3 内容装配生成，未使用测试直注伤害或手写单位参数；
- 至少三轮有效发射与命中；
- 其旧攻击力、攻击间隔、射程、移动方式和投射物公共速度均进入实际轨迹；
- 双实例隔离和死亡后清理；
- 死灵书额外验证飞行来源对地面与飞行目标均可发射，且不误开“俯冲地面资格窗口”。

只有完整通过的单位可将 `full-restoration-matrix.json` 对应行的 `r3IdentityTest` 更新为 `passed-program`，并写入单独的轨迹证据。未完成者保持 `pending`，不得开放为完整商店成品。
