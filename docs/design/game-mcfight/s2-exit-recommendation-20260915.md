# MC Fight S2 结项建议

日期：2026-09-15。策划结论：**建议结束S2技术验证，进入下一阶段。** 本文是阶段签核建议，不代替owner人审落账。

## 结论依据

- 当前相关回归225项通过，类型检查和构建通过；昂贵规模测量已单独完成，没有用跳过项冒充运行。
- 独立复查通过，六组带锚点撤修全部验红并恢复，无新增退回项。
- REQ-MCFIGHT-001～003已经分别按原始合同关闭。
- V01～V08的代表性技术链已经形成证据：实例隔离、多技能选择、目标承诺、俯冲窗口、取消清理、接敌避让、多段效果、确定性和规模测量。
- 代表机制已经覆盖弹丸、穿透与持续光束、固定落点、持续区域、召唤、关系骨架、共享生命、部位减伤、伤害来源与一次性死亡转化。
- 死亡掉落继续遵守“死亡当拍后段展开、下一拍参与碰撞”的合同；此前唯一回归红灯已按合同修复，原断言未改。
- 性能非线性已登记为PERF-MCFIGHT-001，不以当前结果宣称百单位性能达标，也不在S2无限扩张优化范围。

## 真实动作素材的处理

卫道士4段、僵尸4段、恼鬼6段，共14段真实动作素材尚未制作和验收。当前只证明播放器、阶段绑定、镜像、挂点换算、命中反馈、中断与清理接口；原版单姿态和占位画面不算合格动画。

该缺项从“S2技术验证阻塞”调整为**下一阶段首个内容生产门槛**：

1. 在批量接入单位前，先完成卫道士一套端到端真实动作并验收像素挂点、握持、镜像、伤害时点和5%斩击边界；
2. 接口成立后完成僵尸与恼鬼，证明同技能模板不同表现和俯冲阶段表现；
3. 三套样例未验收前，不批量生产84单位动作，也不宣称美术管线完成。

这个调整不把素材写成已完成，只是不再用美术成品等待阻塞已经完成的引擎能力验证。如果owner要求S2必须同时包含真实素材，则S2只能保持“技术通过、素材未通过”；否则可按本建议结束S2。

## 已确认的尸巫补充规则

留下有效转化标记的尸巫先死亡，标记仍然有效。标记者之后死亡时照常转化一次，使用标记保存的尸巫来源身份和施加伤害时的阵营快照，不改归最后击杀者。该规则已写入combat-rulings-v0.2.md。

## 下一阶段入口

下一阶段先完成“小规模可玩纵切”：少量单位的购买、拖拽部署、自动战斗、结算和重新购买闭环。同期完成上述三套真实动作样例，并根据PERF-MCFIGHT-001暂时控制战场规模；正式单位上限在独立性能基准后确定。

不在S2继续追加：84单位批量配置、全量美术、正式数值平衡、所有地图导航优化、百单位性能优化和完整商业UI。新问题按下一阶段所属功能单独登记，不重新打开已经通过的整个S2。
