# 内容迁移建议与策划裁定入口

这是建议分组，不是已经批准的首发名单，不代表已证实Apollo存在同名能力。每个原版单位档案已登记新版处理待裁定。

先用每族最小代表做机制覆盖，再批量配置外观和数值。原版“48个单位专属绑定”不意味着新版需要48套程序。

## 新内容合同需要补齐什么

1. 共享规则先冻结：索敌与施法锁定分开；技能选择规则与技能执行分开；地面/飞行/俯冲状态与命中掩码；护甲、状态和伤害归属；CD推进和打断后的处理。
2. 每个技能模板写：启动条件、目标模式、前摇/生效/后摇、效果链、命中几何、CD起点与时钟、打断/死亡处理、表现事件。普通攻击也使用此合同；被动/持续触发保留明确触发模式，不强迫每种效果都竞争同一主动槽。
3. 每个单位绑定写：可用技能、合法参数覆盖、决策优先级/权重、没有技能可用时的行动；选择具体单位动作/特效/音效绑定。
4. 每条表现绑定写：单位动作、技能阶段事件、锚点、镜像、缩放换算、预警与命中反馈。半径/扇角/长度等战斗参数由唯一数据源提供，图片不参与权威伤害判定。
5. 逐单位裁定旧设计意图与当前实现冲突，补上新数值、保留/调整/延后/删除与验收剧本。未裁定字段不能由程序根据旧错误实现自行补全。

## 与当前S2的衔接

当前已有74项通过是程序上一轮自证，本盘点没有改变其证据等级。继续执行s2-round2-task.md要求的完整技能阶段、错时多实例至少三轮、真实俯冲和中断清理。新增代表用例优先覆盖INV-004召唤注册、INV-005重复接触CD、INV-006区域生命周期、INV-008表现接线；以批准的实验参数运行，不把实验数值当成正式平衡数值。

程序无需先照搬84个单位再发现基础调度缺陷。S2证明通用合同能执行后，策划提交首批冻结配置；其余单位沿机制族扩充。真正表达不了的能力再按现有流程实查、列A/B与代价、由用户裁定，不在本次盘点直接申请全套新系统。
