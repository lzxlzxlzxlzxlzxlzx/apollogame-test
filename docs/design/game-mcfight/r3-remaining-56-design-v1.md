# MC Fight R3：剩余56个单位行为设计与施工分组 v1.0

日期：2026-09-16。前置：24个首批身份与R3-B1四个标准投射物身份已完成程序自证，R3-B1仍待独立复查。本文件定义其余56个单位的玩法身份、共用机制、施工顺序和身份验收，不以旧Unity单位专属代码作为实现方案。

## 1. 共同规则

- 数值仍以 `inventory/units.json` 的 `effectiveAttributes` 为兼容基线；距离、半径、速度除以24，时间保持秒。
- 每项主动技能都必须有独立的启动条件、目标资格、前摇、命中几何、CD和恢复；成功启动即进入CD，硬控或死亡只取消尚未发生的效果，不返还CD。
- 中毒、燃烧、凋零可并存；同类刷新时间、取较强效果且不叠加伤害。冰冻、恐慌为硬控，按既定战斗裁定打断施放。
- 同一机制只实现一个数据驱动公共能力。每个单位只提供参数、技能组合和决策配置，禁止按单位ID写战斗分支。
- 每个单位须完成代表性行为、双实例隔离、来源死亡/硬控清理和三轮确定性轨迹，才可把矩阵中的 `r3IdentityTest` 标为 `passed-program`。

## 4. 三项必须先探针再装配的结构合同

| 机制 | 涉及单位 | 程序先提交的探针 | 策划验收合同 |
|---|---|---|---|
| SK10 跃击 | 遗弃者、暝煌龙、珊瑚傀儡、珊瑚巨兽 | 连续起跳、空中轨迹、固定落点、落地形状、硬控/死亡取消。 | 不能用瞬移替代；目标死亡后仍落在启动时记录的落点；落地伤害只在落点真实几何内结算。 |

| SK24 骑乘 | 国王蜘蛛、骷髅德鲁伊 | 两实体、相对挂点、独立决策、死亡与下马。 | 骑手和坐骑各有HP；骑手死亡则坐骑继续战斗，坐骑死亡则骑手下马并恢复地面移动。 |

## 5. 交付规则

每批交付都必须附带：单位清单、公共能力合同、逐单位三轮轨迹、未解决参数表、受影响回归、类型检查、构建、组合审计、可视化场景和冻结副本。只有一批独立复查通过，才进入下一批的“已验证身份”计数。
