# S1补充：单位、技能、表现与素材关系

日期：2026-09-11。性质：近期讨论的策划整理稿，作为S1设计输入；不是已实现的引擎Schema，也不代表S2验证或人门签核通过。统一技能为用户提出的设计方向；以下数据分层、动画适配和工具方案为策划建议，尚待细化与验证。

## 1. 目标

同一套技能机制允许多个单位复用，各单位可使用不同伤害、范围、冷却及表现素材。单位差异以配置表达，避免每只怪物单独实现攻击、技能状态机与动画控制逻辑。

更换图片、动画或皮肤不自动改变攻击范围、伤害和冷却。玩法变化必须通过明确参数修改，并让表现与之对齐。

## 2. 概念数据关系

以下是设计职责划分，名称不是已注册组件，不能直接照抄为引擎manifest字段。

| 数据 | 内容 | 引用关系 |
|---|---|---|
| 单位定义 | 身份、基础属性、技能装配列表、决策策略引用 | 指向技能装配及单位表现配置 |
| 技能模板 | 目标与阶段规则、命中方式、效果列表、可配置参数、动作标识 | 声明动作/特效需求，不绑定某怪物专属图片 |
| 单位技能装配 | 技能模板引用及允许的参数配置，例如伤害、施放距离、作用范围、CD | 同一模板可在不同单位上产生不同数值版本 |
| 单位表现配置 | 动作标识到动画/特效/音效的绑定、挂点、朝向、尺寸适配 | 引用素材资源；必要时对特定技能装配显式覆盖 |
| 素材资源 | 图像、图集、帧动画、音效、特效及对齐元数据 | 通过资源ID登记和引用，不承担游戏规则 |
| 实例运行状态 | 每只单位的生命、每项技能剩余CD、执行阶段、目标、施放序号 | 独立于共享模板与素材，不写回定义数据 |

原则：模板参数默认值→单位技能装配的显式配置→战斗中的合法修正，具体属性公式和覆盖白名单在S2确定。不能让技能伤害既从单位攻击力计算、又被装配值暗中覆盖；必须声明采用哪种来源及修正顺序。

## 3. 挥砍示例

共享模板“近战挥砍”：前摇→扇形攻击生效→后摇，声明动作标识melee_slash。骷髅可绑定挥剑动画，巨兽可绑定挥爪动画，各自有独立的伤害、距离、角度与冷却配置。

技能决定何时产生判定与效果；单位表现配置决定播放哪段动作；素材库保存实际文件。同一单位的普攻、重劈、横扫可分别声明melee_slash、heavy_cleave、sweep_attack，不强制复用一个动作。

变化若超出模板已声明的能力，例如单次扇形变为持续追踪光束，应选用或扩展合适的公共机制，而非用怪物ID条件绕过模板规则。

## 4. 行动与表现的职责

公共决策器根据单位策略选择技能及目标；技能执行器推进阶段并处理打断；效果系统执行命中和结算；表现系统读取状态/事件播放动画、特效与声音。

逻辑时间决定实际生效时刻。动画接触标记用于视觉对齐，不由渲染帧回调决定扣血。掉帧、快进、更换素材不得改变命中次数或伤害。

动画建议按准备、挥击、恢复分段匹配技能时序；运行中的攻速变化是否重新计时仍属于D06，不由美术播放速度暗中决定。

## 5. 判定与视觉使用同源攻击几何

每次攻击依据技能、单位参数、方向及锁定策略解析得到一份逻辑几何描述。命中系统与表现系统消费同一来源，表现可插值，但不反向改判定。

几何至少明确：形状、逻辑起点、偏移、朝向、尺寸（圆半径、扇形角度或矩形长宽）、生效时间；施放距离与效果覆盖范围分开。

攻击起点必须在逻辑世界中可计算。画面中的手、剑、爪挂点应映射到逻辑锚点；不能从仅在渲染端存在的动画骨骼位置反推命中。是否需要由确定性逻辑轨迹驱动的扫掠判定，后续单独定义。

## 6. 素材对齐元数据（建议）

- 锚点：素材哪一点对准逻辑攻击起点。
- 默认方向：素材原始朝向，旋转和镜像如何处理。
- 有效区域：素材中表示攻击覆盖的区域，区别于透明边缘及装饰光晕。
- 适用几何：支持的形状、角度与尺寸范围；扇形角度不能仅靠等比缩放改变。
- 适配策略：允许缩放、分段、遮罩、替换变体或拒绝；不能靠任意拉伸处理所有素材。
- 动画关键点：准备、接触、恢复时间及可接受的播放速度范围。

这些元数据的格式、单位换算、资源索引接入与验证器尚未实现承诺，须对照现有资产和渲染能力确认。

视觉一致不是要求每个发光像素都造成伤害。主要攻击轮廓要准确，装饰层须明显区别；遮挡、透明度和粒子散逸不能掩盖真实覆盖边界。

短剑动作与极长射程即使在数学上缩放一致，也不一定视觉可信。超出适配范围应换动作/特效或设计为剑气等另一攻击，不自动放大单位身体、武器或碰撞半径。

## 7. 攻击对齐预览（工具提案）

选择单位和技能后，显示单位动作、攻击特效、实际判定轮廓、素材有效区域、锚点、朝向及阶段时间轴；支持暂停、逐步推进和边界内外测试目标。

该工具用于制作与QA，默认不出现在玩家正式界面。先查现有展示台、碰撞调试和渲染能力能否组合，不在S1承诺另做完整编辑器。

## 8. S2验证要求

| 编号 | 验证内容 | 判据 |
|---|---|---|
| P01 | 两种单位共用一个挥砍模板 | 参数与动画不同，模板与各实例状态不相互污染 |
| P02 | 修改攻击范围 | 判定与有效视觉区域同源更新，无第二份手填范围 |
| P03 | 更换外观素材 | 命中、伤害、CD与锁定不变 |
| P04 | 生效时间对齐 | 逻辑照常推进，接触关键点与生效点吻合；掉帧不丢伤害 |
| P05 | 朝向与边界 | 不同方向/镜像下锚点正确；边界内外目标按统一规则命中 |
| P06 | 不适配素材 | 缺动作、错误形状、超出缩放范围可明确检出，不静默换成错误表现 |

几何误差容差、边界接触是否算命中、素材不足时的回退等级需定稿。测试应报告世界单位误差与视觉证据，不能只依赖截图主观判断。

先完成当前s2-round2-task.md的生命周期和俯冲验证，再安排本表的最小挥砍适配样例；可以并行核查字段，不因此改变程序当前第一任务。

## 9. S1/S2/S5/S6分工

S1描述关系、玩家可观察行为与一致性原则；S2确定可执行Schema、引擎能力映射与验证结果；S5/S6制作界面、动画和资源并进行视觉验收。先有这份设计输入，不代表S1需要先写完程序数据结构或做齐所有素材。
