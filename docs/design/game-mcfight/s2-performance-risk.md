# PERF-MCFIGHT-001：战斗规模非线性风险

状态：已记录风险，等待正式最大战场单位数后单列优化任务。不阻塞S2继续核验代表机制，不宣称性能达标。

## 已有测量

来源：evidence/c5-final-20260915.log，Node24.15.0、Windows10.0.26200、i7-14700HX。20/50/100战斗单位（每组一个目标，其余共用双技能模板）各预热1000Tick，随后三轮1000Tick。世界总实体135/345/695，含技能/事件挂件。停止目标资格后推进10拍，三组Hitbox残留0。

- 20单位：每Tick中位数2.28–2.42ms。
- 50单位：每Tick中位数28.65–29.90ms，已经偏重。
- 100单位：最低中位数264.34ms，另两轮311.70/520.16ms，当前不适合百单位实时战斗。

测量时有其他编辑/类型检查与后段诊断竞争，不能当最终独占硬件基准。最低一轮仍足以表明非线性风险；区残留为0不等于已经证明无全部内存泄漏。此样例未启用后续新增伤害路由，不声称覆盖转换负载。

## 可复现条件

项目根使用s2-c5.fixture.ts的scaleBattle(seed=301)，记录每次w.tick()的performance.now差值而非测试框架总时间。显式开启昂贵测量，日常回归默认跳过此项、继续跑三次确定性：

```powershell
$env:MCFIGHT_SCALE = '1'
node node_modules/vitest/vitest.mjs run games/game-mcfight/s2-c5.test.ts --maxWorkers 1 --minWorkers 1
Remove-Item Env:MCFIGHT_SCALE
```

正式优化前先由策划/主程确认最大单位数、Tick频率、目标硬件和预算；随后单列性能分析与优化任务，固定独占环境比较前后。S2本轮不扩展性能优化，不调整游戏数值或降低单位上限来掩盖测量。
