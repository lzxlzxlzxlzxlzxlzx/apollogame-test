# MC Fight R3 程序施工单 v1.0

日期：2026-09-15。前置：R2独立复查PASS，owner已确认兼容换算、护甲和验收策略。策划依据：[R3计划](r3-validation-and-calibration-plan.md)、[第一批策划裁定](r3-planner-resolution-batch-1.md)。

## 1. 本批目标

将84单位内容目录中的已裁定字段接入真实战斗路径，按机制族和单位身份场景验证。不得把内容校验PASS误报为84单位实战通过。

## 2. 施工顺序

1. 实现全局兼容投影：24px→1世界单位、旧时间不缩放、1000金币全量商店、隐藏六单位来源限制。
2. 实现并验证Minecraft护甲/韧性公式、真伤绕过和穿甲归零语义；记录原始/护甲后/实际扣血。
3. 将第一批策划裁定中的七组缺参写入 adoption 和正式运行装配，保留来源与理由。
4. 以真实世界路径批量验证已具备字段的机制族：近战/范围、弹丸/爆炸/穿透/光束/固定落点、飞行/俯冲/冲锋、状态/治疗/自爆、召唤/转化/共享生命/吞噬。
5. 对SK10、SK22、SK24先建立最小真实组合探针，提交能力边界和A/B方案；在策划补合同前不得用瞬移、单实体替代蛇身或单位专属骑乘逻辑冒充完成。
6. 为每个已接入单位增加身份场景；场景必须点名单位ID、至少一项有效行为、一次实例隔离和清理结果。
7. 每批更新 `full-restoration-matrix.json`。只有真实场景通过的单位可将 `r3IdentityTest` 改为通过。

## 3. 必须验证

- 同seed重复运行得到相同轨迹摘要。
- 同模板单位与同单位多技能的CD/目标/状态互不污染。
- 目标死亡、硬控、来源死亡和结算后清理遵守CR01—CR15。
- 所有范围、弹丸、光束和固定落点以真实Shape/命中几何结算，不以视觉坐标代替。
- 造成伤害只记实际HP扣除，治疗只记实际恢复，过量部分不计入玩家统计。
- 78个可购买单位只能在具备完整可运行装配后进入全量商店；6个隐藏单位只能从规定来源创建。

## 4. 交付与禁止项

输出 `r3-program-evidence.md`、机制族测试清单、84行身份矩阵、未完成/阻塞机制清单及浏览器观察证据。每个新公共能力先登记缺口，不得写单位ID分支、第二套战斗循环、测试注入命中或用0填缺参。程序不得修改策划验收剧本或自行签独立复查。

完成当前可施工族后统一运行相关回归、类型检查、构建、组合审计和全量身份场景，再交独立复查。
