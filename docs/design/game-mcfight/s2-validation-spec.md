# 程序首任务：S2战斗能力验证

2026-09-15策划收尾补充：[S2收尾清单](s2-closeout-plan.md)将本表剩余项分为C1—C6，提供实验参数、交付边界及执行顺序。原V01—V08不删除，已通过范围复用证据；范围缩减提案在用户确认前不改变现行验收要求。

本任务是验证计划，不代表S2通过，也不授权绕过能力裁决新增游戏专属战斗系统。

## 工作顺序

1. 读取本目录GDD与待定表、引擎接入手册、相关生产线手册，再看../mc-fight/engine-targeting-skill-assessment.md。
2. 对registry与当前实现重新核查，不只采信此前68个既有测试通过。
3. 先用现有能力制作最小验证；临时数值写在测试fixture并明确不是正式平衡数据。
4. 现有能力无法表达时，记录查阅路径、反例与失败原因，提交A公共能力扩展/B受控例外两路，等待相应裁决；继续不受影响的验证。
5. 将结果交给策划整理正式capability-plan，再进行独立复查。不签人门，不提前做完整游戏。

## 验收场景草案

| ID | 场景 | 必须证明 |
|---|---|---|
| V01 | 同种两个单位错时施法 | 独立目标、阶段、冷却；同名信号不群体误触发 |
| V02 | 普攻与主动技能竞争 | 选择和执行分离；已经执行的技能不被每拍决策重置 |
| V03 | 技能目标与追击目标 | 锁定规则可表达，不被全局索敌悄悄覆盖 |
| V04 | 两飞行怪错时俯冲 | 下降开始至回升完成视作地面；未启动攻击便升空须重选；窗口内已开始前摇的单体近战在升空后仍命中；地面范围伤害按生效时资格判断；两实例不串状态 |
| V05 | 前摇目标死亡、施法被打断、自身死亡 | 按实验契约结束并清理动作锁与窗口，不残留状态 |
| V06 | 近战围攻、重叠、边角、不可达 | 记录接敌与避让结果；不能用瞬移或取消碰撞伪装通过 |
| V07 | 多段范围与效果 | 次数、间隔、来源一致，能验证友伤配置 |
| V08 | 相同seed/输入重复运行 | 可重复；多单位规模记录耗时，阈值等待D10 |

当前顺序：V03目标捕获与失效取消 → V01/V02/V05完整生命周期、多技能动作占用及打断清理 → V04真实俯冲 → 少量真实动作素材适配。已有三轮时序证据保留，不回到首轮重做。其余规则未定的部分只作可行性实验，报告所用假设及结果，不宣称最终玩法合格。

## 交付

- s2-program-evidence.md：规则/场景、真实调用链、命令、退出码、通过与失败、局限。
- 每项现有能力的注册名与字段对照；必要的测试文件和fixture路径。
- 动态问题附实际运行截图/录像和日志，尤其是窗口、移动、施法中断。
- 新增能力候选单：证据、可选路径、通用性、成本和需要owner决定的内容。

首轮不做批量素材导入、84只怪物、正式UI、全库流程改造或Unity整套C#翻译。正式功能测试接入S2机器门是单独的流程变更，目前脚本只做gap-check。
