# MC Fight S4 CONCERNS 处理决定

日期：2026-09-15。角色：策划。输入：`review/s4-independent-review-20260915.md`。

## 结论

S4的购买、真实拖放、六单位战斗、结算和返回商店闭环按当前证据功能通过，但阶段暂不签核。独立复查仍为CONCERNS，流程板显示S3机器与复查证据过期、S4人门未完成。全量复原可以先做R1只读事实冻结，不得开始R2的84单位批量程序装配。

## 三项处理

### 1. 战斗统计口径

玩家界面的“造成伤害”采用**实际扣除的HP**：单次有效伤害为 `min(结算前HP, 本次结算伤害)`，不计过量伤害；治疗不得抵扣伤害。另行记录“治疗量”，同样只计算实际恢复HP，不计过量治疗。

原始请求伤害可以保留为调试数据，但不得以“造成伤害”名称展示给玩家。结算摘要和验收读取统一使用有效伤害。该改动完成后须补充过量伤害、普通伤害和治疗三种断言。

### 2. 共享回归与进程异常

程序需为16项旧共享失败建立逐项清单：测试名、所属能力/游戏、首次可复现基线、当前失败、是否被MC Fight消费、处理人和结论。MC Fight实际消费的能力失败必须修复并全绿；与MC Fight无调用关系的旧游戏失败可以由对应负责人处理，但必须由独立复查确认隔离，不能由施工者口头豁免。

测试worker异常须在受控并发下重跑至少三次。再次发生则保留完整错误和最小复现；三次不再发生也只能记录为未复现，不能删除历史证据。

### 3. 过期阶段证据

当前最终源码重新执行S3 gate，并由非施工复查者更新S3复查记录。随后重跑S4受影响测试、验收、类型检查、构建、系统审计和S4 gate，由独立复查者将S4更新为PASS或给出具体退回项。PASS后再由owner完成人门。

## 可并行工作

策划/内容盘点可立即执行R1：冻结84单位旧版名称、数值、技能、行为和素材来源。R1不得修改正式游戏运行代码，不得把推断值写成新版正式值。R2—R4等S4三门全绿后开始。

## 转入R2的门槛

- 当前源码S3机器门与独立复查恢复有效。
- S4机器门有效，独立复查为PASS，owner人门完成。
- 伤害/治疗统计口径按本决定完成并复核。
- 16项失败得到修复或独立范围隔离，worker异常有稳定复跑结论。
