# `game-clue-investigation`《现场搜证》立项简报

> S1-P-01 HTML 原型已由 Owner 于 2026-10-12 真机定稿；本文仍不代表项目控制台 S1 人门已经通过，控制台终审只由 Owner 本人操作。

## 一句话玩法

DokiWorld 向小游戏提供一张调查现场与一组可交互物件；玩家在场景中观察并点击物件，普通物件给出简短调查反馈，关键物件播放线索特写并加入本局线索清单，找齐必需线索后完成调查。

## 产品定位

- 类型：独立、短局、无时限的场景调查与线索收集小游戏。
- 参考：借鉴《弹丸论破2》调查环节的“场景物件可调查、关键证物特写收录”交互骨架，不复制其角色、素材、界面、字体、命名或视听资产。
- 宿主：DokiWorld。
- 核心价值：把宿主原本的一次点击判定，扩展成一段可观察、可探索、有线索获得仪式感的独立交互。
- 首版逻辑画布：1440×900。
- 首版操作：鼠标 / 触控为主，键盘焦点与确认键可完成等价操作。

## 核心循环

1. 进入现场，展示场景名称、调查目标与尚未完成的线索进度。
2. 玩家移动指针；可调查物件在悬停或键盘聚焦时出现克制但清晰的轮廓、标签或焦点反馈。
3. 点击普通物件：镜头或焦点轻推，出现 1 段简短调查描述，然后返回现场；该物件可标记为“已查看”。
4. 点击关键物件：焦点确认与线索闪光并行，弹出线索图片、名称与简述，确认后加入本局线索清单。
5. 已取得的关键物件保留“已收录”状态，重复点击只回看线索，不重复结算。
6. 找齐全部必需线索后，播放短完成演出并返回唯一成功结果。
7. 玩家主动退出属于 `cancelled`，不是调查失败。

## 首版交互对象

每个物件都是宿主传入的闭集数据项，分为两类：

| 类型 | 玩家反馈 | 是否推进完成 |
|---|---|---|
| `flavor` 普通物件 | 标签、简短描述、已查看状态 | 否 |
| `clue` 线索物件 | 标签、描述、线索图片特写、已收录状态 | 仅 `required:true` 的线索推进 |

首版不使用“完全不可见且无提示的像素猎杀”。物件可以不常亮，但在悬停、触控探索模式或键盘聚焦时必须可发现。调查难点来自观察和信息理解，而不是猜测不可见命中区。

## 场景与热点边界

- 场景背景由宿主提供 render-only 图片 URL；加载失败显示包内降级背景，并阻止产生错误成功结果。
- 交互区域使用相对 0–1 坐标，随 1440×900 逻辑画布等比缩放。
- S1 目标只冻结 `rect` 与 `circle` 两种区域；不在首版加入任意多边形、像素遮罩或自动图像识别。
- 区域只负责命中；物件名称、描述、线索图与是否必需均由独立字段表达。
- 同一屏建议 4–12 个物件，其中必需线索 1–5 个；最终上下限由 S2 合同与容量验证冻结。

## 初步 DokiWorld 权威边界

### 宿主预计传入

- 本次调查的稳定 `investigationId`；
- 场景标题、调查目标和场景图片 URL；
- 有序物件数组：稳定 `objectId`、类型、命中区域、显示文案；
- 线索物件的 render-only 线索图片 URL；
- `required` 标记，或等价的必需线索 ID 闭集。

### App 预计返回

- `investigationId`；
- `outcome: "completed"`；
- 已收集的稳定 `objectId` 列表，按首次取得顺序或合同规定的稳定顺序输出。

### 明确不归 App

- 不写 DokiWorld 的知识、传闻、任务、背包、奖励、剧情、数据库或存档；
- 不接收完整世界对象、角色对象或数据库主键映射；
- 不决定线索带来的剧情效果；宿主把 opaque `objectId` 映射为自身知识 / Effect；
- 不把关闭、返回、资源失败或非法输入伪装为业务失败；这些情况退出或取消，不返回成功结果。

字段名、长度上限、URL 策略、合同名与版本将在 S2 对 capability registry 和最新版 SDK 实查后冻结；本节不是最终调用说明。

## 完成与失败语义

- `completed`：全部必需线索均已取得；小游戏成功结束。
- `cancelled`：玩家主动退出、宿主关闭、配置非法或无法继续；不是失败，宿主不应施加失败代价。
- 首版没有 `completed + failure`：不设倒计时、点击次数、误点惩罚、生命或评分失败。
- 普通物件无需全部查看；完成只由必需线索集合决定。

## S1-P HTML 原型范围

原型必须是单文件 `docs/design/game-clue-investigation/prototype.dc.html`，固定 1440×900，并至少提供一套原创占位现场：

- 6–8 个可交互物件；
- 其中 3 个线索物件、至少 2 个必需线索；
- 主场景默认态；
- 物件悬停、按下、键盘聚焦、已查看、已收录、不可用状态；
- 普通物件描述弹层；
- 线索图片特写与“线索已收录”演出；
- 线索清单 / 进度查看；
- 找齐必需线索后的完成态；
- 主动退出确认态；
- 一键重播“进入现场 → 查看普通物件 → 收集两条必需线索 → 完成”的整条关键演出。

原型必须标注所有占位素材，并把动画时长、并行关系、层级、遮挡、安全区与 reduced-motion 降级写入同目录说明。owner 真机目击并明确说“定稿”前，不得进入 S2。

## 初步视觉方向

- 原创“档案调查 / 现场取证”风格：深色现场、亮色焦点描边、纸质档案与高对比证物特写。
- 主场景始终是视觉主体；HUD 只保留目标、线索进度、退出与线索清单，不用大面板遮住现场。
- 线索取得是首版最强反馈：物件焦点确认、闪光 / 扫描线、证物图片抬升、档案盖章与收录音效形成约 1.2–1.8 秒的完整链。
- 普通物件反馈更短，约 0.5–0.9 秒，避免每次点击都打断探索节奏。
- 不使用“言弹”“学级裁判”等参考作品专有名词；统一称“线索”“证物”“现场记录”。

## 首版包含

- 单场景、静态背景、声明式热点；
- 普通物件与关键线索物件；
- 线索特写、收录、已调查状态与完成判断；
- 鼠标、触控、键盘可达；
- 主动退出；
- DokiWorld 严格输入、唯一成功输出、调用说明、资产闭包与 dist 交付。

## 首版不包含

- 3D 自由移动、第一人称镜头或场景漫游；
- 多房间地图、物件组合、道具使用、证词推理或谜题链；
- 调查技能值、随机检定、难度等级、倒计时、误点惩罚或失败评分；
- 自动识图、AI 动态生成热点或宿主数据库直连；
- 在小游戏内修改 DokiWorld 的知识、任务、背包或奖励；
- 复制参考作品的美术、音效、字体、角色或 UI。

## 阶段边界

1. 当前只完成 S1 立项与 S1-P 原型任务冻结。
2. owner 定稿 HTML 原型后，S2 才能实查并提交 `capability-plan.md`。
3. 若 S2 发现现有能力不能声明式表达热点命中、线索会话或宿主图片消费，必须按缺口协议给出 A / B 两路，由 owner 裁决；不得先写游戏专属 DOM、Canvas 命中或规则系统。
4. 正式 UI 走 LayoutNode，现场物件与特效走 render 组件 / 通用特效能力；HTML 原型代码禁止复制进生产运行时。
