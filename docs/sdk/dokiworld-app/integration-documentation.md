# DokiWorld App 调用说明文档规范

## 1. 文档的用途

每个 App 至少有 `docs/integration.zh-CN.md`，并由 `manifest.documentation.zh-cn` 登记。读者是 DokiWorld 调用方程序员，不是玩家。读完后必须能在不查看 App 源码的情况下构造调用、校验字段、区分终局语义、处理输出并完成宿主权威结算。

新文档必须复制 [标准中文模板](../../playbooks/templates/dokiworld-integration.zh-CN.template.md)。manifest 是文档清单的唯一真相；未登记的 Markdown 不算交付文档。

## 2. 十二个必写章节

1. **身份与版本**：App ID、protocol/version、输入与输出合同、scopes/modules。
2. **宿主调用示例**：完整 `apps.launch()`，覆盖 completed、cancelled、异常。
3. **APPS 面板说明**：数据框粘贴 data 还是完整 envelope，preview 有何限制。
4. **输入完整示例**：可直接复制的 JSON。
5. **输入字段表**：路径、类型、必填、范围/长度、默认值、规则语义、非法行为。
6. **规则与算法**：计算顺序、优先级、随机消费顺序和覆盖关系。
7. **非法输入处理**：缺字段、额外键、错类型、错合同/版本如何响应。
8. **输出完整示例**：每种业务终局至少一个。
9. **输出字段表**：存在条件、精确定义、宿主应如何使用。
10. **完成/失败/取消/异常**：何时 complete，何时 cancelled，何时没有结果。
11. **权威与幂等**：谁发奖励、谁写存档、能否重算、使用什么 ID 去重。
12. **接入核对清单**：调用方上线前逐项确认。

## 3. 字段怎么写

每个字段单独一行，不把多个字段合并成“配置项”。至少写：

| 项目 | 写法要求 |
|---|---|
| 路径 | 从 `data` 开始的完整路径，如 `data.difficulty` |
| 类型 | 写 JSON 类型与更窄结构，如 `integer`、`string enum` |
| 必填 | 明确“是/否”；可选必须写省略语义 |
| 值域 | 数值含不含端点；枚举逐项列全；文本最大长度 |
| 默认值 | 只能写代码真实采用的默认值；无默认写“无，缺失即拒绝” |
| 规则作用 | 是否影响胜负、随机、奖励，或仅 render-only |
| 非法行为 | 拒绝整次调用、字段降级还是使用默认；不得含糊 |

数组还要写最小/最大长度、顺序是否有语义、是否允许重复；对象写允许键的闭集；文本写空白处理、字符长度与是否允许空串；URL 写协议、用途、加载失败降级和是否仅展示。默认 extra keys 拒绝。

## 4. 示例怎么写

- 同时给出完整 envelope 和 APPS 面板只粘贴的 `data`，不可混淆。
- 示例字段值必须满足真实 parser，并由测试 fixture 覆盖。
- 输出示例必须来自可达到的真实终局，不得杜撰字段。
- 所有枚举、失败结果和条件字段都必须有示例；禁止“等等”“同理”。
- TypeScript 示例要处理 completed、cancelled、SDK error，并对 output 再校验。

## 5. 规则与权威怎么写

规则部分面向接入，不抄内部函数。应明确：输入如何映射为局内配置；结果何时锁定；seed 从哪里来；同一输入能否重演；表现物理是否参与裁决；App 返回的是建议、证明还是最终事实。奖励、背包、剧情、成就和数据库写入默认归宿主，App 只回传结果。

## 6. 终局语义怎么写

必须分别定义：

- `completed + success`：玩法成功，宿主可进入成功结算。
- `completed + failure`：只有合同定义的玩法失败才使用。
- `cancelled`：关闭、返回或 requestExit；不是失败，不应扣除失败代价。
- 技术错误：输入拒绝、超时、SDK rejected、资源失败；默认不产生业务结果。

若 App 没有失败结果，也要明确写“输出只有成功；主动退出为 cancelled”。

## 7. 更新纪律

以下变化必须同一次更新 manifest、代码、测试、源码调用说明并重新构建 dist：合同名/版本、字段、枚举、范围、默认值、算法、随机、终局语义、权威边界、App ID。纯美术、布局和不改变合同的动画通常不改正文，但仍须重建以保证 dist 文档新鲜。

禁止只修改 DokiWorld `public/apps` 内的文档；那是部署副本，下次构建会被覆盖。禁止写未经实现的未来能力、宿主内部 API、数据库操作或秘密值。
